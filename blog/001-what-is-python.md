파이썬이란 무엇인가를 검색하면 인터프리터, 객체 지향, 동적 타입 같은 말이 한꺼번에 나옵니다. 모두
필요한 개념이지만 정의만 외우면 Python이 왜 중요한지는 보이지 않습니다. 더 쉬운 출발점은 사람이
적은 몇 줄이 실제 결과로 바뀌는 장면입니다.

Python은 컴퓨터에게 할 일을 글로 적는 프로그래밍 언어입니다. 이 글에서는 붕어빵 세 개의 가격을
계산하는 아주 작은 코드에서 시작합니다.

코드가 실행되는 과정, 1989년에 시작된 역사, 읽기 쉬운 문법과
라이브러리가 서로를 키운 방식, AI 시대에도 많이 쓰이는 이유, 다른 언어를 골라야 하는 경우까지 한 흐름으로
연결합니다. 끝까지 읽으면 Python을 단순히 쉬운 언어라고 부르는 대신 어떤 문제에서 왜 유리한지 설명할 수
있습니다.

## 파이썬이란 무엇인가: 컴퓨터에게 일을 적는 언어입니다

### 사람이 적은 명령을 Python이 읽고 계산 결과를 화면에 보여 줍니다

![짧은 Python 명령이 붕어빵 주문 영수증 결과로 바뀌는 실행 흐름](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/7d/7dd30cfe6faea2d684950be94309e088999242e29ca6514ba2fddf98ad824c15.png "코드에 수량과 가격을 적으면 Python이 계산한 영수증을 돌려줍니다")

프로그래밍 언어는 사람이 컴퓨터에 일을 설명할 때 쓰는 규칙입니다. 컴퓨터는 한국어나 영어 문장을
그대로 이해하지 못합니다. 어떤 값을 저장할지, 어떤 순서로 계산할지, 결과를 어디에 보여 줄지를 정해진
문법으로 적어야 합니다. Python은 그 규칙을 사람이 읽기 쉬운 모양으로 만든 언어입니다.

아래 예제의 입력은 팥 붕어빵 수량 `2`, 슈크림 붕어빵 수량 `1`, 한 개 가격 `1000`입니다. 핵심 처리는
두 수량을 더한 뒤 가격을 곱하는 일이고, 기대 결과는 `붕어빵 3개, 3,000원`이라는 한 줄입니다. 입력,
처리, 결과를 먼저 구분하면 코드의 각 줄이 왜 필요한지 놓치지 않습니다.

#### 예시 코드: 수량과 가격을 계산해 한 문장으로 출력하기

```python
red_bean = 2
custard = 1
price = 1000

count = red_bean + custard
total = count * price

print(f"붕어빵 {count}개, {total:,}원")
```

`red_bean = 2`에서 등호는 수학의 같다는 표시가 아니라 오른쪽 값에 왼쪽 이름을 붙이라는 뜻입니다.
이름이 붙은 값을 변수라고 합니다. `count = red_bean + custard`는 두 수량을 더해 새 변수에 저장하고,
`total = count * price`는 전체 수량과 가격을 곱합니다. 마지막 `print`는 메모리 안에만 있던 결과를
사람이 볼 수 있게 화면으로 내보냅니다.

중괄호 안의 변수 값을 문장에 넣는 `f"..."` 형식은 뒤에서
다시 배워도 됩니다. 지금은 입력 세 개가 계산 두 번을 거쳐 출력 한 줄로 바뀐다는 관계가 핵심입니다.

**언어와 인터프리터와 CPython은 서로 다릅니다.**

Python이라는 말은 서로 가까운 세 가지를 가리킬 때가 많습니다. 첫째는 `if`, `for`, 들여쓰기처럼
코드를 쓰는 규칙인 언어입니다. 둘째는 그 규칙으로 적은 소스 코드이며 보통 `.py` 파일에 저장합니다.
셋째는 그 파일을 읽어 실제로 실행하는 프로그램입니다. 이 실행 프로그램을 Python 인터프리터라고
부릅니다.

가장 널리 쓰이는 Python 구현은 CPython입니다. Python이 언어의 설계도라면 CPython은 그 설계도를
C 언어로 구현한 대표 실행기입니다.

CPython은 소스 코드를 내부 명령 형태로 바꾼 뒤 Python 가상
머신에서 실행합니다. 초보 단계에서 이 내부 과정을 외울 필요는 없지만, 코드와 실행기가 같은 것은
아니라는 구분은 중요합니다. 문법이 틀리면 실행 전에 오류가 나고, 문법은 맞아도 파일이 없거나 값이
잘못되면 실행 도중 오류가 날 수 있기 때문입니다.

공식 설명에서 Python은 범용 고수준 프로그래밍 언어로 소개됩니다. 범용은 표 계산, 웹 서버, 자동화,
AI처럼 한 종류의 문제에만 묶이지 않는다는 뜻입니다.

고수준은 CPU와 메모리의 세부 명령을 매번 직접
적기보다 목록, 문자열, 파일 같은 사람이 익숙한 개념으로 일을 표현한다는 뜻입니다. 고수준은 더 우수하다는
서열이 아니라 하드웨어 세부 사항에서 얼마나 떨어져 있는지를 나타내는 말입니다.

## 1989년 크리스마스에 시작됐습니다

### 취미 프로젝트로 시작한 언어가 1991년 공개되고 Python 3으로 이어졌습니다

![1989년 겨울 달력에서 시작한 코드가 1991년 공개와 2008년 Python 3 문서로 이어지는 연표](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/8d/8da6da4beb36a994488e2e79553ace349f184febbd16894cd9921188120495d8.png "작은 개인 프로젝트가 공개 배포와 큰 언어 개편을 거쳐 오늘의 Python이 됐습니다")

Python은 거대한 회사의 비밀 회의에서 시작되지 않았습니다. 네덜란드 CWI 연구소에서 일하던 Guido
van Rossum은 1989년 12월 크리스마스 휴가에 취미 프로젝트로 새 언어의 인터프리터를 만들기
시작했습니다. 당시 그는 분산 운영체제 Amoeba 팀에서 일했고, 시스템 관리 작업을 C보다 빠르고 셸
스크립트보다 구조적으로 적을 언어가 필요했습니다.

Guido는 이전에 교육용 언어 ABC 구현에 참여했습니다. ABC의 읽기 쉬운 문법과 높은 수준의 자료형은
좋아했지만 외부 기능을 붙이기 어려운 폐쇄성은 답답했습니다.

Python은 이 두 경험을 결합했습니다.
들여쓰기로 코드 묶음을 보이게 하고, 목록과 사전 같은 자료를 기본으로 제공하면서도, 성능이 필요한 기능은
C로 만들어 연결할 수 있게 했습니다. 오늘날 Python이 쉬운 문법과 강력한 외부 라이브러리를 함께 가진
이유가 시작 단계부터 들어 있었습니다.

Python이라는 이름은 뱀에서 가져온 것이 아닙니다. Guido가 좋아한 영국 코미디 프로그램
`Monty Python's Flying Circus`에서 가져왔습니다. 공식 문서 예제에 유머가 자주 등장하고 Python
관련 책과 프로젝트에 뱀 그림이 많이 쓰이면서 나중에 뱀 이미지가 강하게 연결됐습니다.

#### 설명 목록: 개인 프로젝트가 공동체의 언어가 된 연표

- **1980년대:** Guido가 ABC 언어 구현에 참여하며 들여쓰기와 높은 수준의 자료형에 관한 경험을
  쌓았습니다.
- **1989년 12월:** 크리스마스 휴가에 새 인터프리터 구현을 시작했습니다.
- **1991년 2월:** 1년여 개발한 코드를 USENET에 공개해 누구나 내려받고 의견을 보낼 수 있게
  했습니다.
- **2001년:** Python의 지식재산과 공동체 활동을 지원하는 Python Software Foundation이
  설립됐습니다.
- **2008년 12월:** 오래된 설계를 정리한 Python 3.0이 공개됐습니다.
- **2020년 1월:** Python 2 공식 지원이 끝나 새 프로젝트의 기준이 Python 3으로 모였습니다.

1991년 공개는 단순한 무료 배포 이상의 의미가 있었습니다. 사용자가 오류를 알리고 패치를 보내며
문서와 라이브러리를 함께 만들 수 있는 공개 개발 구조가 시작됐습니다. Guido 한 사람이 만든 언어가
오래 살아남은 까닭은 최초 설계뿐 아니라 공동체가 개선을 이어 갈 통로가 있었기 때문입니다.

Python 3은 Python 2와 완전히 호환되지 않는 큰 개편이었습니다. `print`를 함수로 바꾸고 문자열 처리
원칙을 정리하는 등 오래된 선택을 바로잡았습니다. 당장은 두 문법이 함께 쓰여 혼란이 컸지만, 장기적으로
언어가 낡은 제약을 계속 떠안지 않게 했습니다. 지금 새로 배우는 코드는 Python 3 문법만 보면 됩니다.

2018년 Guido가 최종 결정자 자리에서 물러난 뒤에는 핵심 개발자가 선출하는 운영위원회가 언어의 큰
결정을 맡습니다. 새 기능은 보통 PEP라는 공개 제안서로 문제, 설계, 대안, 호환성을 논의합니다. 이것은
Python이 창시자의 개인 프로젝트에서 공개 절차를 가진 공동체 프로젝트로 성장했다는 또 하나의 역사입니다.

## 읽기 쉬운 문법이 사람을 모았습니다

### 중괄호 대신 들여쓰기를 써서 코드의 시작과 끝을 눈으로 찾기 쉽습니다

![같은 가격 합계를 계산하는 짧고 정돈된 코드와 기호가 많은 코드가 나란히 놓인 비교](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/f0/f05d6e40a7b4e6e7a81d9760c7f4f728da507b616abc9a1abc0c1e21dac80f7a.png "Python은 들여쓰기와 익숙한 단어로 계산 순서를 짧게 보여 줍니다")

Python은 코드가 어떻게 보이는지도 언어 규칙으로 정합니다. `if`나 `for` 아래 줄을 같은 간격으로
들여쓰면 한 묶음이라는 뜻입니다. 들여쓰기는 보기 좋게 꾸미는 선택이 아니라 실행 범위를 정하는 문법입니다.
사람마다 중괄호 위치를 다르게 놓는 일을 줄이므로 처음 보는 코드에서도 어디까지가 같은 작업인지 눈으로
찾기 쉽습니다.

읽기 쉽다는 말은 코드가 항상 짧다는 뜻과 다릅니다. 지나치게 많은 일을 한 줄에 넣으면 Python 코드도
읽기 어려워집니다. 중요한 점은 변수 이름, 들여쓰기, 익숙한 영어 단어를 이용해 문제의 순서를 코드
모양에 드러내기 쉽다는 것입니다.

붕어빵 가격 목록에서 1,000원 이상인 값만 골라 더하는 같은 작업을 두 언어로 비교해 보겠습니다. 입력은
`1000`, `1500`, `800` 세 가격이고, 기준은 `1000` 이상이며, 기대 결과는 `2500`입니다.

#### 예시 코드: Python으로 기준 가격 이상만 골라 합산하기

```python
prices = [1000, 1500, 800]
total = sum(price for price in prices if price >= 1000)
```

`prices`는 세 가격을 순서대로 담은 목록입니다. `for price in prices`는 목록에서 가격을 하나씩 꺼내고,
`if price >= 1000`은 기준을 통과한 값만 남깁니다. `sum`은 남은 값을 더합니다. 오른쪽에서 왼쪽으로
억지로 해석하기보다 가격을 꺼낸다, 기준으로 고른다, 합산한다는 세 동작으로 읽으면 됩니다.

#### 예시 코드: JavaScript로 같은 계산 표현하기

```javascript
const prices = [1000, 1500, 800];
const total = prices.filter(price => price >= 1000).reduce((sum, price) => sum + price, 0);
```

JavaScript에서는 `filter`로 값을 고른 뒤 `reduce`로 합산합니다. 이 코드는 잘못된 코드가 아닙니다.
웹브라우저에서는 JavaScript와 TypeScript가 훨씬 자연스러운 선택입니다.

비교의 목적은 어느 언어가
무조건 우월한지 정하는 데 있지 않습니다. Python은 같은 데이터 처리 순서를 적은 기호와 익숙한 단어로
표현해 처음 아이디어를 시험하기 쉽다는 차이를 보여 줍니다.

**동적 타입은 빠른 시작과 늦은 오류를 함께 만듭니다.**

Python에서는 변수를 만들 때 숫자형이나 문자열형을 앞에 선언하지 않아도 됩니다. `price = 1000`을
실행하면 현재 값이 정수라는 사실을 실행기가 알아냅니다. 이를 동적 타입이라고 합니다. 자료 모양이 자주
바뀌는 탐색 작업에서는 빠르게 코드를 고칠 수 있지만, 숫자가 와야 할 자리에 문자열이 들어온 문제를 실행
전까지 발견하지 못할 수도 있습니다.

규모가 커지면 함수의 입력과 출력에 타입 힌트를 적고, 자동 검사와 테스트를 함께 사용합니다. Python의
쉬움은 규칙이 없다는 뜻이 아닙니다. 처음에는 생략할 수 있는 규칙이 많고, 프로젝트가 커질수록 필요한
안전장치를 단계적으로 더할 수 있다는 뜻에 가깝습니다.

Python 설계 철학을 정리한 PEP 20에는 읽기 쉬움이 중요하다는 원칙이 들어 있습니다. 코드는 컴퓨터가
실행하지만 유지보수 비용은 사람이 치릅니다. 한 번 실행되는 짧은 코드보다 몇 달 뒤 다시 읽고 고칠 수
있는 코드가 실무에서 더 가치 있는 이유입니다.

## 라이브러리가 작은 코드를 크게 만듭니다

### 같은 Python 문법으로 표, 웹 서버, 자동화, AI 모델을 연결할 수 있습니다

![하나의 Python 파일이 표 계산, 웹 요청, 자동화 시계, AI 모델 결과에 각각 연결된 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/3a/3a32ae457b3851760457c6ce147e7297127ad3e7d403f3d45c3967fc1b8e9a44.png "Python 파일 하나가 목적에 맞는 라이브러리를 불러 여러 종류의 작업을 실행합니다")

라이브러리는 다른 사람이 미리 만들어 둔 코드 묶음입니다. Python을 설치하면 파일 경로, CSV, JSON,
날짜, 압축, 인터넷 통신처럼 자주 필요한 기능을 담은 표준 라이브러리가 함께 옵니다.

여기에 Python
Package Index인 PyPI에서 목적별 외부 패키지를 설치할 수 있습니다. 표를 다루는 `pandas`, 수치 계산을
맡는 `NumPy`, 웹 서버를 만드는 `Django`와 `FastAPI`, 머신러닝에 쓰는 `scikit-learn`과
`PyTorch`가 대표적인 예입니다.

언어와 라이브러리는 역할이 다릅니다. `for`, `if`, 함수처럼 문제를 표현하는 기본 규칙은 Python
언어가 제공합니다.

Excel 파일을 읽거나 신경망을 계산하는 전문 기능은 라이브러리가 제공합니다. 이
구분을 알면 Python을 배운다는 말이 모든 패키지를 외운다는 뜻이 아님을 알 수 있습니다. 기본 문법과
자료 구조를 익힌 뒤 필요한 문제에 맞는 도구를 찾아 쓰는 것이 실제 학습 방식입니다.

이 생태계가 Python을 중요한 연결 언어로 만들었습니다. 화면은 TypeScript로 만들고 빠른 계산은 C,
C++, Rust로 구현하더라도, 데이터를 읽고 모델을 실행하고 API로 결과를 보내는 순서를 Python으로
묶을 수 있습니다.

NumPy 같은 라이브러리의 무거운 계산은 더 빠른 저수준 코드가 맡고 Python은 작업
순서를 표현합니다. Python 자체의 반복문이 언제나 빠르기 때문이 아니라 빠른 전문 도구를 같은 문법에서
연결하기 때문에 강한 것입니다.

아래 예제의 입력은 `sales.csv` 파일입니다. 이 파일에는 최소한 `menu`와 `amount` 열이 있어야 합니다.
처리는 파일 읽기, 메뉴별 묶기, 금액 합산의 세 단계이고, 출력은 메뉴 이름과 합계가 있는 표입니다.

#### 예시 코드: CSV 판매표를 메뉴별로 합산하기

```python
import pandas as pd

sales = pd.read_csv("sales.csv")
summary = sales.groupby("menu")["amount"].sum()
print(summary)
```

첫 줄은 `pandas`에 짧은 이름 `pd`를 붙여 불러옵니다. `read_csv`는 파일을 표로 바꾸고,
`groupby("menu")`는 같은 메뉴의 행을 한 묶음으로 봅니다. `["amount"].sum()`은 각 묶음의 금액만
더합니다. 직접 CSV 문법을 해석하고 그룹 합산 알고리즘을 처음부터 만들지 않아도 되므로 문제 자체에
집중할 수 있습니다.

다만 라이브러리는 마법이 아닙니다. 파일이 없으면 파일 오류가 나고, `amount` 열에 `무료` 같은 문자가
섞여 있으면 합계가 기대와 달라질 수 있습니다.

패키지 버전이 달라 동작이 바뀌는 문제도 있습니다. 그래서
프로젝트마다 가상환경을 만들고 사용한 패키지 버전을 기록하며, 입력 열과 결과 합계를 검사합니다.
라이브러리가 개발 시간을 줄여 주지만 입력 계약과 검증 책임까지 없애 주지는 않습니다.

Python Software Foundation과 JetBrains의 2024 개발자 조사에서는 데이터 분석, 웹 개발, 머신러닝,
데이터 엔지니어링, 자동화가 모두 주요 사용 분야로 나타났습니다.

한 언어가 여러 직무 사이에서 만나는
지점이 많다는 뜻입니다. 분석가가 만든 코드를 엔지니어가 서비스로 옮기고, 운영자가 자동화에 재사용할 수
있을 때 생태계의 가치는 패키지 개수보다 더 커집니다.

## 다른 언어가 더 좋은 일도 있습니다

### Python의 중요함은 모든 언어를 대신해서가 아니라 여러 작업을 연결하는 데 있습니다

![브라우저, 모바일 앱, 고성능 엔진, 네트워크 서버, 데이터와 AI 작업이 알맞은 언어 경로로 나뉜 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/9b/9b029651ee8ef83cbcd60e5a6bd3f5fdbf359d0200368fa3b4b4edb268651f94.png "제품의 실행 장소와 속도 조건에 따라 Python과 다른 언어의 선택이 달라집니다")

Python은 사람이 코드를 빨리 작성하고 고치기 좋지만, 실행 속도와 메모리 제어가 가장 중요한 문제에는 다른 언어가 더 잘 맞을 수 있습니다.

한 줄씩 해석하기 쉬운 동적 구조는 개발 속도를 높이지만, 같은 작업을 기계어에 가깝게 최적화한 코드보다
실행 비용이 클 수 있습니다. 작은 자동화에서는 사람이 아끼는 시간이 더 중요하지만, 초당 수백만 번
반복하는 엔진에서는 실행 비용 차이가 중요해집니다.

Python 파일은 브라우저가 기본으로 실행하는 언어가 아니고, 모바일 운영체제의 주 개발 언어도 아닙니다.
사용자에게 하나의 실행 파일로 전달할 때는 인터프리터와 패키지를 함께 묶는 배포 문제도 생깁니다. 동적
타입은 빠른 실험에 편하지만 큰 프로젝트에서는 타입 검사와 테스트가 부족하면 오류가 늦게 발견됩니다.
따라서 쉬운 문법이 운영 난이도까지 자동으로 낮춰 주는 것은 아닙니다.

#### 설명 목록: 문제에 따라 먼저 살펴볼 언어

- **데이터 분석, AI 실험, 반복 업무 자동화:** 짧은 문법과 관련 라이브러리가 많은 Python이 강한
  출발점입니다.
- **웹브라우저 화면과 큰 웹 앱:** 브라우저가 직접 실행하고 정적 타입 도구가 성숙한 TypeScript가
  자연스럽습니다.
- **안드로이드 앱:** 운영체제 공식 도구와 긴밀하게 연결되는 Kotlin을 먼저 살펴볼 수 있습니다.
- **고성능 엔진과 메모리 제어:** 실행 비용과 메모리 배치를 세밀하게 다루는 C++이나 Rust가 알맞습니다.
- **큰 조직의 장기 운영 서버:** 팀의 배포 체계에 따라 Java, Kotlin, Go, TypeScript도 강한
  후보입니다.

#### 확인 목록: 언어를 고르기 전에 답할 다섯 질문

- 코드는 브라우저, 휴대전화, 개인 컴퓨터, 서버 중 어디에서 실행되는가
- 느린 응답이 불편한 수준인가, 안전이나 비용에 직접 영향을 주는 수준인가
- 팀이 이미 운영할 수 있는 언어와 배포 도구는 무엇인가
- 필요한 라이브러리가 실제 입력 형식과 플랫폼을 지원하는가
- 1년 뒤 고칠 사람도 지금의 선택을 이해하고 테스트할 수 있는가

Python의 진짜 강점은 모든 층을 혼자 차지하는 데 있지 않습니다. 아이디어를 빠르게 실행하고, 필요하면
다른 언어로 만든 빠른 기능을 불러오고, 결과를 표와 API로 전달하는 가운데 자리에 강합니다. AI 모델의
핵심 계산은 C++과 GPU 코드가 맡을 수 있습니다.

연구자와 개발자는 Python에서 데이터를 준비하고 학습을 지시하며
결과를 확인할 수 있습니다. 다른 언어가 발전해도 Python이 함께 쓰이는 까닭입니다.

언어 선택은 인기 투표가 아니라 제약 조건을 맞추는 일입니다. 같은 회사에서도 웹 화면은 TypeScript,
데이터 처리는 Python, 성능이 중요한 모듈은 Rust를 쓸 수 있습니다. 여러 언어를 함께 쓰는 것이 실패가
아니라 각 층에 맞는 도구를 배치한 설계일 수 있습니다.

## 브라우저에서 첫 코드를 실행합니다

### 팥 수량을 바꾸고 실행을 눌러 합계가 달라지는지 바로 확인합니다

![브라우저 코드 입력칸의 붕어빵 수량이 실행 버튼을 거쳐 새 영수증 결과로 바뀌는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/57/57a319f7b8b14b5a6271e0ab6f27f2607921bd5e5b669861ba4266a32dd5fc7e.png "팥 수량 한 곳을 바꾸고 다시 실행하면 개수와 가격이 함께 달라집니다")

설치 없이 Python을 직접 실행해 보면 지금까지의 설명이 눈에 잡힙니다. 아래 실행 링크에는 팥 두 개와
슈크림 한 개가 들어 있습니다. 처음 실행의 입력은 `2`, `1`, `1000`이고 기대 결과는 `붕어빵 3개,

#### 실패 예시: 숫자를 바꾼 뒤 실행되지 않을 때 확인할 곳
