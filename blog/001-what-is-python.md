파이썬이란 무엇인가를 검색하면 인터프리터, 객체 지향, 동적 타입 같은 말이 먼저 나옵니다. 그 말을 다 읽어도 파이썬으로 뭘 할 수 있는지는 여전히 모릅니다.

그래서 설명을 미루고 실제로 돌아가는 화면 다섯 개를 먼저 보겠습니다.

## 그림판에 선이 혼자 그려집니다

### 사람이 마우스를 잡지 않은 채 사각 나선이 그려지는 화면입니다

![왼쪽 코드가 실행되는 동안 오른쪽 그림판에 사각 나선이 그려지는 화면](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/26/26a61e5a395d39d010b201143df44ff76e3725c913d1c9a4399c314e8dbb288d.mp4 "왼쪽 코드를 실행하자 오른쪽 그림판에서 선이 이어집니다")

왼쪽에서 코드가 실행되는 동안 오른쪽 그림판에 사각 나선이 생깁니다. 마우스 포인터가 움직이지만 그 마우스를 잡은 사람은 없습니다.

`pyautogui.drag`라는 한 줄이 마우스를 200픽셀 끌고, 다음 줄이 방향을 바꾸고, 그다음 줄이 거리를 조금 줄입니다. 사람이 손으로 하던 드래그를 글로 적어 두면 컴퓨터가 그 글을 읽고 그대로 손을 움직입니다.

여기까지는 마우스를 흉내 내는 것처럼 보입니다. 그런데 같은 코드가 브라우저 안에서도 똑같이 손을 씁니다.

## 브라우저 입력칸도 혼자 채워집니다

### 키보드를 치지 않았는데 할 일 목록에 글자가 들어갑니다

![공식 할 일 목록에 Buy milk가 입력되고 완료로 표시되는 화면](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/6d/6d7cfb1ebc80d49de79f20640d4ca71260aad30ae7ebb9c0236622244c5978e9.mp4 "입력칸에 글자가 들어가고 첫 줄에 완료 표시가 켜집니다")

브라우저가 열리고 입력칸에 `Buy milk`가 찍히고 목록에 줄이 하나씩 쌓입니다. 마지막에 첫 줄이 완료로 바뀝니다. 키보드를 친 사람은 없습니다.

브라우저를 코드로 다루는 도구 `Playwright`가 공개 데모 주소 `demo.playwright.dev/todomvc`를 열고, 입력칸을 찾아 글자를 넣고, 체크박스를 눌렀습니다. 사람이 하던 클릭과 타이핑을 순서대로 적어 둔 것뿐입니다.

두 화면 모두 사람의 손을 대신했습니다. 그럼 그 손을 움직이는 코드는 얼마나 어려운 글일까요.

## 그 코드는 여덟 줄입니다

### 값을 적고 계산하고 화면에 내보내는 세 동작이 전부입니다

![짧은 Python 명령이 붕어빵 주문 영수증 결과로 바뀌는 실행 흐름](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/7d/7dd30cfe6faea2d684950be94309e088999242e29ca6514ba2fddf98ad824c15.png "왼쪽에 적은 수량과 가격이 오른쪽 영수증 한 줄로 바뀝니다")

파이썬 코드는 사람이 읽는 문장에 가깝습니다. 붕어빵 가게에서 팥 두 개와 슈크림 한 개를 한 개 `1000`원에 팔았다고 하겠습니다. 이 계산을 그대로 적으면 아래가 전부입니다.

#### 예시 코드: 수량과 가격을 계산해 한 문장으로 출력하기

```python
red_bean = 2
custard = 1
price = 1000

count = red_bean + custard
total = count * price

print(f"붕어빵 {count}개, {total:,}원")
```

`red_bean = 2`의 등호는 수학의 같다가 아니라 오른쪽 값에 왼쪽 이름을 붙이라는 뜻입니다. `count = red_bean + custard`는 두 수량을 더해 새 이름에 넣고, `total = count * price`는 그 수량에 가격을 곱합니다. 마지막 `print`가 컴퓨터 안에만 있던 답을 화면으로 꺼냅니다. 실행하면 `붕어빵 3개, 3,000원`이라는 한 줄이 나옵니다.

여덟 줄로 곱셈은 됩니다. 그런데 앞의 그림판과 브라우저는 이 여덟 줄로 설명되지 않습니다.

## 남이 만든 코드를 불러 씁니다

### 마우스를 움직이는 코드도 표를 읽는 코드도 이미 누군가 만들어 뒀습니다

![하나의 Python 파일이 표 계산, 웹 요청, 자동화 시계, AI 모델 결과에 각각 연결된 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/3a/3a32ae457b3851760457c6ce147e7297127ad3e7d403f3d45c3967fc1b8e9a44.png "파일 하나가 목적에 맞는 도구를 하나씩 불러 씁니다")

앞에서 마우스를 끈 `pyautogui`와 브라우저를 연 `Playwright`는 파이썬 문법이 아닙니다. 다른 사람이 미리 만들어 공개한 코드 묶음이고, 이것을 라이브러리라고 부릅니다.

내려받을 수 있는 라이브러리는 `pypi.org`에 모여 있습니다. 표를 다루는 `pandas`, 계산을 맡는 `NumPy`, 웹 서버를 만드는 `FastAPI`, 모델을 학습시키는 `PyTorch`가 그런 묶음입니다. 파이썬을 배운다는 말은 이 이름들을 외운다는 뜻이 아니라, 필요할 때 맞는 것을 찾아 불러 쓴다는 뜻에 가깝습니다.

#### 예시 코드: CSV 판매표를 메뉴별로 합산하기

```python
import pandas as pd

sales = pd.read_csv("sales.csv")
summary = sales.groupby("menu")["amount"].sum()
print(summary)
```

첫 줄이 `pandas`를 `pd`라는 짧은 이름으로 불러옵니다. `read_csv`가 파일을 표로 바꾸고, `groupby("menu")`가 같은 메뉴끼리 묶고, `sum()`이 금액을 더합니다. 네 줄로 끝나는 이유는 CSV를 해석하고 그룹을 묶는 코드를 이미 다른 사람이 만들어 뒀기 때문입니다.

이제 남의 코드를 불러 쓴다는 말이 실제 업무에서 어떻게 보이는지 봅니다.

## 사업자번호를 넣으면 상태가 채워집니다

### 홈페이지에 한 건씩 붙여 넣던 조회를 표가 대신합니다

![사업자등록번호를 넣자 표에 계속사업자라는 상태가 채워지는 화면](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/5e/5e4de925132c227ae7380d32d551c427793a4ff40006d02f321f4f06259c8b1d.mp4 "번호를 넣은 칸 옆에 조회 결과가 하나씩 들어옵니다")

왼쪽 칸에 사업자등록번호를 넣으면 오른쪽 칸에 `계속사업자`가 채워집니다. 국세청 홈페이지를 열고 번호를 붙여 넣고 결과를 옮겨 적던 일을 코드가 대신했습니다.

번호 모양이 `2211561480`처럼 하이픈 없이 들어와도 먼저 형태를 맞춘 뒤 조회합니다. 100건이든 1,000건이든 사람이 하던 손동작은 똑같고, 그 손동작을 한 번만 적어 두면 됩니다.

밖에서 자료를 받아 오는 일은 이렇게 됩니다. 이미 내 컴퓨터에 있는 파일은 어떨까요.

## 엑셀을 올리면 그래프가 나옵니다

### 차트 종류를 고르지 않아도 계정별 카드가 만들어집니다

![엑셀 파일을 올리자 계정별 막대 그래프 대시보드가 생기는 화면](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/45/45a2d0545791403e5c48fd1115880a14c8da715d3e3b31cc440c4a486d8b7d1e.mp4 "파일을 올린 직후 계정별 카드가 화면에 깔립니다")

엑셀 파일을 올리자 이자수익, 보험료 같은 계정 이름별로 막대 그래프 카드가 깔립니다. 파일 안에 계정 이름과 월별 숫자만 있으면 됩니다.

사람이 하던 일은 시트를 열고, 계정별로 범위를 잡고, 차트를 삽입하고, 축을 맞추는 것이었습니다. 그 순서를 한 번 적어 두면 다음 달 파일에도 그대로 다시 적용됩니다.

여기까지는 이미 있는 숫자를 정리한 것입니다. 아직 없는 숫자는 어떻게 될까요.

## 없는 숫자를 추정하기도 합니다

### 1,482행을 읽고 앞으로 30일 선을 그립니다

![나스닥 숫자 표와 앞으로 30일 예측 선이 한 화면에 나타나는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/af/af0807f0918766f5780d23f06fb42e1055b8803d22a44fec22ed19120a7718c6.mp4 "표 오른쪽 끝에서 선이 앞으로 더 이어져 나갑니다")

나스닥과 예측 모델을 고르면 지난 시세 1,482행을 읽고 앞으로 30일 선을 그립니다. 표 오른쪽 끝에서 선이 더 이어지는 부분이 아직 오지 않은 날짜입니다.

이 선은 참고용 숫자이지 약속이 아닙니다. 지난 값에서 뽑아낸 추정이라 시장이 갑자기 바뀌면 그대로 빗나갑니다. 화면이 그럴듯하게 나온다고 답이 맞는 것은 아니라는 점이 이 다섯 화면 중 가장 중요합니다.

다섯 화면을 다 봤습니다. 그럼 파이썬으로 뭐든 하면 되는가 하면 그렇지 않습니다.

## 파이썬이 나쁜 선택인 자리도 있습니다

### 화면, 앱, 속도가 걸린 곳에서는 다른 언어가 먼저입니다

![브라우저, 모바일 앱, 고성능 엔진, 네트워크 서버, 데이터와 AI 작업이 알맞은 언어 경로로 나뉜 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/9b/9b029651ee8ef83cbcd60e5a6bd3f5fdbf359d0200368fa3b4b4edb268651f94.png "할 일마다 먼저 열어 볼 언어가 다릅니다")

브라우저 화면을 만드는 일은 `JavaScript`와 `TypeScript`가 먼저입니다. 아이폰 앱은 `Swift`, 안드로이드 앱은 `Kotlin`으로 만듭니다. 게임 엔진이나 매 밀리초를 다투는 계산은 `C++`이나 `Rust`가 맡습니다.

파이썬은 실행 속도가 빠른 언어가 아닙니다. `NumPy`가 빠른 이유도 무거운 계산을 더 낮은 언어로 만든 코드에 넘기기 때문입니다. 파이썬이 잘하는 일은 그 빠른 도구들을 같은 문법 안에서 이어 붙여 순서를 적는 것입니다.

#### 확인 목록: 언어를 고르기 전에 답할 세 가지

- 이 코드가 어디서 실행됩니까. 브라우저 안이면 `JavaScript`가 먼저입니다.
- 얼마나 빨라야 합니까. 밀리초를 다투면 `C++`이나 `Rust`를 봅니다.
- 표, 파일, 모델을 이어 붙이는 일입니까. 그렇다면 파이썬이 맞습니다.

읽는 것만으로는 손에 남지 않습니다. 지금 직접 한 줄 바꿔 실행해 보면 확실해집니다.

## 파이썬이란 무엇인가를 직접 눌러 봅니다

### 팥 수량을 바꾸고 실행을 누르면 합계가 같이 달라집니다

![브라우저 코드 입력칸의 붕어빵 수량이 실행 버튼을 거쳐 새 영수증 결과로 바뀌는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/57/57a319f7b8b14b5a6271e0ab6f27f2607921bd5e5b669861ba4266a32dd5fc7e.png "수량을 고치고 실행을 누르면 아래 결과가 새로 찍힙니다")

설치는 하지 않아도 됩니다. 아래 칸에 앞에서 본 붕어빵 코드가 그대로 들어 있고, 실행 버튼을 누르면 브라우저 안에서 바로 돌아갑니다.

https://eddmpython.com/codaro/run/?example=python-bungeoppang-order

`red_bean = 2`를 `red_bean = 5`로 고치고 실행을 눌러 봅니다. 결과가 `붕어빵 6개, 6,000원`으로 바뀌면 값을 적고 계산하고 화면에 내보내는 세 동작을 직접 돌린 것입니다.

#### 실패 예시: 숫자를 바꾼 뒤 실행되지 않을 때 확인할 곳

- `red_bean = 다섯`처럼 글자를 넣으면 더할 수 없어 오류가 납니다.
- `red_bean = 5`의 등호 앞뒤 이름을 지우면 무엇에 붙일지 알 수 없어 멈춥니다.
- 줄 앞에 빈칸을 넣으면 들여쓰기로 읽혀 오류가 납니다.

파이썬이란 무엇인가에 대한 답은 이 한 줄을 고쳐 본 순간 손에 남습니다. 사람이 하던 일을 글로 적어 두면 컴퓨터가 그 글을 읽고 몇 번이든 다시 합니다.
