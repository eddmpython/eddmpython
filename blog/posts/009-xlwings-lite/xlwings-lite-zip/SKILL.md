# xlwings Lite 코드 교체

사용자가 지정한 통합문서에서 Python 코드를 추출하거나 교체한다. 필요한 입력은 원본 `.xlsx`, 교체할 Python 파일, 새 출력 경로다. 교체 코드가 없으면 추출까지만 수행한다. 파일을 만들었다는 사실과 Excel에서 실행했다는 사실을 구분해 보고한다.

## 먼저 구조 확인

일반적인 암호화되지 않은 `.xlsx`는 ZIP 패키지다. Excel을 닫고 저장된 파일을 대상으로 작업한다. 웹 Excel이라면 먼저 사본을 내려받는다. 원본과 다른 출력 경로를 사용하며 기존 출력 파일이 있으면 새 이름을 고른다.

Python 표준 라이브러리 `zipfile.ZipFile`로 목록을 읽고 `testzip()`으로 손상 여부를 검사한다. 중복된 ZIP 항목 이름이 있으면 교체를 중단하고 보고한다. ZIP이 아니거나 암호화된 파일이면 확장자를 바꿔 해결하려 하지 않는다.

`xl/webextensions/` 아래 XML을 XML 파서로 읽어 `property` 요소 중 `name="main.py"`를 찾는다. 파일명이 `webextension1.xml`이라고 가정하지 않는다. 실제 확인한 저장 형식은 `value` 속성에 Python 소스를 JSON 문자열로 넣는 방식이다. XML 파서로 속성을 읽은 뒤 `json.loads()`를 적용하면 소스가 나온다.

후보가 하나이며 JSON 해석 결과가 문자열인지 확인한다. 후보가 없거나 여럿이거나 다른 저장 형식이면 임의로 XML을 추가하지 않는다. 발견한 구조를 보고하고 대상 확인 또는 해당 버전의 저장 형식 조사를 진행한다. 기존 코드와 관계 파일을 통해 xlwings Lite 대상인지 확인한다.

## 대상 값만 교체

1. 새 Python 파일을 UTF-8로 읽고 `ast.parse()`로 문법을 검사한다. 추출한 기존 소스도 별도 파일로 보존한다. 코드를 검사하려고 실행하지 않는다.
2. 새 소스를 `json.dumps(source, ensure_ascii=False)`로 직렬화한 뒤 XML 속성값으로 이스케이프한다. JSON 인코딩과 XML 인코딩은 서로 다른 단계다. XML 속성의 따옴표, `&`, `<`, 줄바꿈이 올바르게 복원되는지 확인한다.
3. 확인한 `main.py` 속성값 구간만 바꾼다. XML 전체를 파서로 재직렬화하면 접두사나 호환성 선언이 달라질 수 있으므로 원문 나머지를 보존한다. 속성 순서나 따옴표 종류를 고정한 정규식으로 모든 파일을 처리하지 않는다. 대상 구간이 하나임을 검증한 경우에만 교체한다.
4. `ZipFile.infolist()`를 순회하며 원래 `ZipInfo`와 압축 해제한 바이트를 새 ZIP에 쓴다. 대상 XML 외에는 바이트를 변경하지 않고 ZIP 주석도 보존한다. append 모드로 같은 항목을 추가하지 않는다.
5. 임시 출력 검사를 끝낸 뒤 새 `.xlsx` 경로로 옮긴다. 압축 해제 폴더를 통째로 감싸 ZIP 내부에 상위 폴더를 하나 더 만들지 않는다.

이 작업에서는 `openpyxl`로 통합문서 전체를 다시 저장하지 않는다. 지원하지 않는 추가 기능 부품이 소실될 수 있으므로 기존 ZIP 부품을 보존하는 방식이 목적에 맞다. 시트 XML, 수식, 관계 파일을 바꾸는 작업은 `main.py` 교체에 포함하지 않는다.

## 완료 검사

- 원본과 출력의 ZIP 항목 이름과 순서가 같고 `testzip()`이 모두 통과하는지 확인한다.
- 대상 XML을 제외한 모든 항목의 압축 해제 바이트 해시가 같은지 확인한다. ZIP 파일 전체 해시는 재압축 때문에 달라질 수 있다.
- 출력 XML을 다시 파싱하고 JSON을 해석해 `main.py`가 입력 소스와 정확히 같은지 확인한다. 다른 속성과 XML 원문 구간이 보존됐는지도 검사한다.
- 공개 검증에는 새로 만든 연습용 통합문서와 가짜 데이터만 쓴다. 한글, 따옴표, 줄바꿈, `&`, `<`를 포함한 소스로 왕복 복원을 검사한다.
- 출력 파일을 Excel에서 열어 복구 경고가 없는지, xlwings Lite에 새 코드가 표시되는지 확인한다. 코드 실행은 사용자가 요청한 동작 범위에서 수행한다. 실행 환경이 없으면 ZIP과 소스 검증까지만 확인했다고 보고한다.

보고에는 출력 경로, 교체한 ZIP 항목, 보존 검사 결과, 실제 Excel 실행 여부를 남긴다. 통합문서의 업무 데이터나 전체 소스를 로그에 출력하지 않는다.
