AI에게 코딩을 맡겨 보고 싶은데 무엇부터 열어야 할까요? 화면에 저장소, README, 터미널 같은 말이 나오면 코드를 쓰기도 전에 막힙니다. 도구를 열고 나면 새 대화를 열 때마다 이 프로젝트가 무엇이고 어떤 명령으로 실행하는지 다시 설명하게 됩니다.

이 글을 따라가면 프로젝트에서 확인한 작업 방법이 적힌 `AGENTS.md`나 `CLAUDE.md`가 폴더에 남습니다. 다음 대화의 AI는 그 파일에서 프로젝트 목적과 실행 방법을 다시 찾습니다. 이미 프로젝트 폴더를 연 상태라면 [AI에게 요청문 보내기](#ai에게-요청문-보내기)에서 시작합니다.

직접 할 일은 폴더를 열고 요청문을 보낸 뒤, 새 대화에서 설명 파일을 확인하는 것입니다. `AI 작업`이 붙은 섹션은 주소를 받은 AI가 수행합니다. 거기 나오는 명령을 모두 외울 필요는 없습니다.

## AI 코딩 도구 준비

### 프로젝트 파일을 읽고 고칠 수 있는 도구로 시작합니다

![공식 시작 안내에서 내려받을 앱과 로그인 단계를 확인하는 화면](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/ea/ea7f6d66d2825cd3175c2f19c2bbf930f34c50817fc53a322c85a1f44b4927d8.png "공식 시작 안내에서 운영체제에 맞는 설치 경로를 확인합니다")

아직 도구가 없다면 [OpenAI 시작 안내](https://learn.chatgpt.com/docs/quickstart)를 열어 현재 컴퓨터용 앱을 내려받고, 앱을 연 뒤 계정으로 로그인합니다. 현재 안내는 ChatGPT 데스크톱 앱에서 시작하며, 코딩 작업은 새 대화의 제품 선택 메뉴에서 `Codex`를 고릅니다. 이미 Claude Code를 쓰고 있다면 바꾸지 않습니다. [Claude Code 시작 안내](https://code.claude.com/docs/en/quickstart)에서 설치와 로그인 경로를 확인할 수 있습니다. 사용 가능한 계정이나 요금제는 각 안내의 조건을 먼저 확인합니다.

| 도구 | 프로젝트 지침 파일 |
|---|---|
| Codex | AGENTS.md |
| Claude Code | CLAUDE.md |

AI 코딩 도구는 대화만 하는 AI와 다릅니다. 허용한 프로젝트 파일을 읽고 고칩니다. 프로그램을 실행하는 명령도 입력합니다. Codex와 Claude Code가 이런 도구입니다. 일반 AI 채팅은 이 글 주소를 받아도 내 컴퓨터의 프로젝트 폴더를 보지 못합니다.

로그인 뒤 대화를 입력할 수 있는 화면이 보이면 준비된 것입니다. 일반 채팅 화면만 열었다면 프로젝트 폴더에 접근하는 기능도 있는지 확인합니다.

## 프로젝트 폴더 열기

### 작업할 폴더를 열면 AI가 읽을 파일의 범위가 정해집니다

![my-first-project 폴더 이름과 그 안의 README.md 파일을 확인하는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/9c/9c90584509ae278a46a842703b7c45a8630215afb7b8cb13d13598a240d5d671.png "컴퓨터 전체가 아니라 작업할 프로젝트 폴더 하나를 엽니다 · 설명 이미지")

프로젝트 폴더는 프로그램을 만드는 파일을 모아 둔 곳입니다. 변경 기록까지 함께 관리하면 저장소 또는 repo라고 부릅니다.

도구를 열면 작업 파일이 들어 있는 프로젝트 폴더를 선택하고, 도구가 그 폴더의 파일을 읽고 고칠 수 있도록 허용합니다. 이미 받은 프로젝트가 있다면 그 파일들이 들어 있는 폴더를 고릅니다. 새 프로젝트를 시작한다면 `my-first-project`처럼 이름을 붙인 빈 폴더를 하나 만들어 엽니다. 빈 폴더로 시작하면 AI가 무엇을 만들지 먼저 물어봅니다.

폴더를 열었다면 대화에 `현재 열린 폴더 이름과 최상위 파일 이름을 알려 줘. 파일은 바꾸지 마`라고 보냅니다. AI가 고른 폴더의 이름을 말하는지 대조합니다. 다른 폴더가 나오면 도구에서 작업 폴더를 다시 선택합니다. 새 빈 폴더라면 다음처럼 만들려는 것을 함께 알려 줍니다.

```text
my-first-project는 새 빈 폴더다.
개인 메모를 정리하는 웹페이지를 만들려고 한다.
프로그래밍 언어와 실행 방법은 아직 정하지 않았다.
지금은 이 목적만 설명 파일에 남겨 줘
```

## AI에게 요청문 보내기

### 열린 폴더의 대화에 요청문을 보내면 AI가 설명 파일을 만듭니다

![ai-environment 주소와 AGENTS.md 작성 요청이 함께 적힌 대화 입력 내용](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/1d/1da93c54a27f4a2aaf0fef89904080af92188e6b8d01c3b66307a810afda1fbb.png "아래 요청문을 복사하고 현재 프로젝트의 대화에 보냅니다 · 설명 이미지")

프로젝트 폴더를 연 대화에 아래 요청문을 보냅니다.

```text
나는 AI 코딩 도구를 처음 쓴다.
이 프로젝트 폴더를 살펴보고 아래 글의 순서대로 AI용 설명 파일을 만들어 줘
https://eddmpython.com/blog/ai-environment

Codex를 쓰고 있다면 AGENTS.md를, Claude Code를 쓰고 있다면 CLAUDE.md를 먼저 확인해 줘
두 도구를 함께 쓰는 프로젝트라면 규칙은 한 파일에만 적고 다른 파일은 그 파일을 읽게 해 줘
파일을 바꾸기 전에 무엇을 만들지 쉬운 말로 알려 줘
작업이 끝나면 바꾼 파일, 실행한 검사, 내가 확인할 것을 알려 줘
```

요청문을 보내면 준비는 끝납니다. 아래 지침 파일 선택과 `AI 작업`이 붙은 절은 전부 이 글 주소를 받은 AI가 맡습니다. 거기 나오는 `git status` 같은 명령어를 다 몰라도 됩니다. AI는 파일을 바꾸기 전에 무엇을 만들지 먼저 알려 줍니다. 설명이 요청과 다르면 사용자가 AI에게 바로 알려 줍니다. 일이 끝나면 `바꾼 파일`과 `확인하지 못한 것`을 읽고, 마지막 `사용자 작업` 절에서 새 대화를 열어 직접 확인합니다.

## AI 작업 범위 확인

### 수정 요청과 폴더 접근이 확인됐을 때만 파일을 바꿉니다

![내용만 검토해 달라는 요청과 파일을 만들어 달라는 요청에서 다른 동사를 짚은 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/2e/2ef9a95011e4a3e042000de03046a18b6ebee2172322622ed5475ffe06e40f46.png "검토와 수정은 서로 다른 요청입니다 · 설명 이미지")

AI는 [복사할 요청문](#ai에게-요청문-보내기)에 적힌 작업과 현재 열린 폴더를 먼저 확인합니다. 글 주소를 읽었다는 사실만으로 파일을 바꿀 권한이 생기지는 않습니다.

| 확인한 상태 | AI가 할 일 |
|---|---|
| 내용만 검토해 달라는 요청 | 읽고 결과만 보고 |
| 설명 파일을 만들어 달라는 요청 | 폴더를 읽고 필요한 파일 수정 |
| 글 주소만 있고 요청이 없음 | 하려는 작업 확인 |
| 프로젝트 파일을 열 수 없음 | 폴더 접근 또는 필요한 파일 요청 |

AI가 이 페이지를 읽고 있다면 사용자가 요청한 범위 안에서 현재 프로젝트를 조사합니다. 어느 설명 파일에 적을지는 [지침 파일 고르기](#지침-파일-고르기)에서 정합니다. 사용자가 검토만 요청했다면 파일을 바꾸지 않고 확인한 내용만 알려 줍니다.

사용자가 글 주소만 보내고 할 일을 말하지 않았다면 파일을 바꾸지 않습니다. `새 설명 파일 만들기`, `기존 파일 고치기`, `내용만 검토하기` 가운데 무엇을 원하는지 묻습니다.

프로젝트 폴더를 읽을 수 없다면 폴더 접근을 요청합니다. 폴더를 열 수 없는 채팅에서는 `README.md`, 기존 `AGENTS.md`와 `CLAUDE.md`, 설치와 테스트 방법이 적힌 설정 파일을 요청한 뒤 기다립니다. 폴더는 읽을 수 있지만 그 안이 비어 있거나 목적과 실행 방법을 확인할 파일이 없다면 내용을 추측하지 않습니다. 사용자에게 무엇을 만들려는지, Python이나 JavaScript처럼 이미 정한 프로그래밍 언어가 있는지 묻고 답을 받을 때까지 기다립니다.

폴더를 읽을 수 있고 수정 요청이 분명하면, 바꿀 설명 파일의 이름을 사용자에게 먼저 알립니다.

## AI 작업. 기존 변경 확인

### 변경된 파일을 먼저 확인해 사용자의 작업을 보존합니다

![git status 출력의 수정 표시 M과 README.md 파일 이름을 확인하는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/1f/1febc6358495bfaed0de2db0338fec8f13426b7f9dd516889b35fa2ef6b33de5.png "M은 이미 수정된 파일을 가리킵니다. 삭제하라는 표시가 아닙니다 · 설명 이미지")

명령을 실행할 자리는 [앞에서 연 프로젝트 폴더](#프로젝트-폴더-열기)입니다. Git으로 기록하는 폴더라면 AI가 그 위치의 터미널에서 다음 명령을 실행합니다.

```text
git status --short --branch
```

터미널은 컴퓨터에 글자로 명령을 입력하는 창입니다. `git status --short --branch`는 파일을 바꾸지 않고 변경된 파일과 Git 브랜치 이름을 보여 줍니다. 브랜치는 작업 갈래입니다. 예를 들어 ` M README.md`가 보이면 README가 이미 수정된 상태이므로 그 변경을 보존합니다. 실제 파일 이름은 프로젝트마다 다릅니다.

Git 저장소가 아니라면 기존 파일을 읽고 필요한 설명만 보탭니다. 빈 폴더에 아직 설치·테스트 명령이 없으면 사용자가 말한 목적만 적고 명령을 추측하지 않습니다.

이미 바뀐 파일이 있다면 되돌리거나 덮어쓰지 않습니다. 기존 `AGENTS.md`나 `CLAUDE.md`가 있으면 새 파일로 교체하지 않고, 빠진 설명만 찾아 보탭니다. 완성한 프로그램을 실제 서비스에 올리는 배포 명령을 찾더라도 사용자가 요청하지 않았다면 실행하지 않습니다.

| 확인할 것 | 쉬운 설명 | 하지 않을 일 |
|---|---|---|
| 사용자의 요청 | 확인만 할지, 파일을 고칠지, 배포까지 할지 | 맡기지 않은 일까지 넓히기 |
| 기존 설명 파일 | 이미 적힌 작업 방법이 있는지 | 새 예시로 통째로 덮기 |
| `git status --short --branch` | 이미 바뀐 파일이 있는지 | 기존 변경 지우기 |

`AGENTS.md`나 `CLAUDE.md`가 여러 개라면 모두 확인합니다. 이 글에 적힌 순서는 사용자의 요청이나 프로젝트에 이미 적힌 규칙보다 우선하지 않습니다.

확인한 변경 목록은 작업을 마칠 때 다시 대조합니다. 설명 파일을 고치는 동안 다른 파일의 변경이 사라지지 않아야 합니다.

## AI 작업. 실행 명령의 근거 찾기

### README와 설정 파일에서 명령과 실행 폴더를 함께 찾습니다

![README.md와 package.json에서 test라는 같은 명령 이름을 대조하는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/ae/aeea826154f2faa7b1dc8f885e0ba62c732a234eec9600eb76d9f41fc0f6b597.png "문서에 적힌 명령을 실제 설정과 대조합니다 · 설명 이미지")

`README.md`는 사람에게 프로젝트를 소개하는 글 파일입니다. 보통 설치 방법과 실행 방법이 적혀 있습니다. 설명이 오래됐거나 빠졌을 수도 있으므로 설정 파일과 자동 검사 파일도 함께 읽습니다. `package.json`과 `pyproject.toml`은 프로젝트가 사용하는 프로그램과 실행 방법을 적는 설정 파일입니다. `.github/workflows` 폴더가 있으면 그 안의 파일에서 GitHub가 자동으로 실행하는 검사 순서를 확인합니다.

AI는 프로젝트 최상위 폴더에서 아래 명령을 실행합니다. `rg`는 파일과 글자를 검색하는 프로그램이며 [공식 배포 페이지](https://github.com/BurntSushi/ripgrep#installation)에서 받을 수 있습니다. 이미 도구의 파일 검색 기능을 쓸 수 있다면 설치하지 않고 같은 파일을 찾습니다.

```text
rg --files -g "README*" -g "AGENTS.md" -g "CLAUDE.md"
rg --files -g "pyproject.toml" -g "uv.lock" -g "package.json" -g "package-lock.json"
rg --files -g ".github/workflows/*" -g "tests/**" -g "test/**"
```

테스트는 프로그램이 예상대로 움직이는지 확인하는 작업이고, 빌드는 원본 파일을 실행하거나 서비스에 올릴 형태로 바꾸는 작업입니다. 찾은 파일에서 설치, 프로그램 실행, 가장 작은 테스트, 전체 테스트, 빌드 명령을 확인합니다. 명령을 어느 폴더에서 실행해야 하는지도 함께 적습니다. README와 자동 검사 파일에 적힌 명령이 다르면 어느 쪽을 실제로 확인했는지 설명합니다. 비밀번호나 서비스 접속 정보를 담을 수 있는 `.env` 파일에서는 항목 이름만 확인하고 값은 출력하지 않습니다.

명령을 찾았다면 설명 파일에 추측이 아닌 실제 명령을 적을 수 있습니다. 찾지 못한 명령은 `아직 없음`으로 구분합니다.

## 지침 파일 고르기

### Codex는 AGENTS.md에, Claude Code는 CLAUDE.md에 적습니다

![AGENTS.md와 CLAUDE.md 두 파일 이름을 각각 구분해 보여 주는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/b9/b9c45d033aa4b0c4b27e0ef35f1c951a230a30800ed916fdb85a6b20bb34b973.png "사용하는 도구가 읽는 파일을 프로젝트 최상위 폴더에 둡니다 · 설명 이미지")

지침 파일은 [열어 둔 프로젝트 폴더](#프로젝트-폴더-열기)의 맨 위에 둡니다. AI가 만드는 파일 이름을 확인하고, 이미 같은 파일이 있으면 내용을 유지한 채 필요한 설명만 보탭니다.

| 사용하는 도구 | 규칙을 적을 곳 |
|---|---|
| Codex만 사용 | AGENTS.md |
| Claude Code만 사용 | CLAUDE.md |
| 두 도구 함께 사용 | 기존 정본을 유지하고 다른 파일에서 연결 |

사용자가 Codex만 쓴다면 `AGENTS.md`에 확인한 명령과 수정하면 안 되는 파일을 적습니다. Claude Code만 쓴다면 `CLAUDE.md`에 적습니다. 쓰지 않는 도구의 파일까지 만들 필요는 없습니다.

파일 이름 뒤의 `.md`는 메모장으로도 열 수 있는 글 파일 형식입니다. Codex는 `AGENTS.md`에서, Claude Code는 `CLAUDE.md`에서 지침을 읽습니다. 읽기 방식은 [OpenAI의 안내](https://developers.openai.com/codex/guides/agents-md)와 [Claude Code의 안내](https://code.claude.com/docs/en/memory)에서 확인할 수 있습니다.

## AI 작업. 두 지침 파일 연결

### 다른 지침 파일을 읽도록 연결하면 규칙을 두 번 적지 않습니다

![CLAUDE.md 안에 @AGENTS.md 한 줄을 적은 설명 이미지](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/c5/c507aead3493247abf0f84ff74f69aaaea81c47f23c1c982f79b04e3e25684ab.png "CLAUDE.md에는 파일을 읽는 한 줄만 남긴 예시입니다 · 설명 이미지")

두 도구를 함께 쓴다면 기존 프로젝트의 방식을 먼저 따릅니다. 두 파일이 모두 없다면 `AGENTS.md`에 공통 규칙을 적습니다. `CLAUDE.md` 파일에 아래 한 줄만 넣으면 Claude Code가 `AGENTS.md`를 함께 읽습니다. 같은 내용을 두 번 적지 않아도 됩니다.

```markdown
@AGENTS.md
```

기존 프로젝트가 `CLAUDE.md`에 규칙을 모아 두었다면 그 규칙을 `AGENTS.md`로 옮기지 않습니다. `AGENTS.md`에는 아래처럼 `CLAUDE.md`를 먼저 읽으라고 적을 수 있습니다.

```markdown
# 프로젝트 설명

작업을 시작하기 전에 `CLAUDE.md`를 끝까지 읽는다.
공통 작업 방법은 `CLAUDE.md`에만 적는다.
```

두 파일은 같은 폴더에 둡니다. 첫 예의 `@AGENTS.md`는 실제 CLAUDE.md 안에서 코드 상자나 백틱으로 감싸지 않습니다. [Claude Code의 가져오기 안내](https://code.claude.com/docs/en/memory#import-additional-files)는 이 표기로 파일을 함께 읽는다고 설명합니다. 연결을 양방향으로 만들지 말고, 규칙이 있는 파일과 그 파일을 가리키는 파일을 구분합니다.

## AI 작업. 확인한 작업 방법 적기

### 확인한 명령만 실행할 폴더와 함께 기록합니다

![AGENTS.md에 개인 메모 웹페이지라는 목적과 아직 정하지 않은 실행 방법을 적은 설명 이미지](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/e0/e08f61bd27879696c82f9fdd135c36f8c1cdb7ef127fb45f4695f0a5e28b23d4.png "명령을 찾지 못한 새 폴더에는 없는 명령을 적지 않습니다 · 설명 이미지")

AI는 [실행 명령의 근거 찾기](#ai-작업-실행-명령의-근거-찾기)에서 읽은 파일과 실행 결과로 설명 파일을 채웁니다. 아래 항목마다 근거가 있는지 확인합니다.

| 적을 항목 | 확인할 근거 |
|---|---|
| 프로젝트 목적 | README와 사용자 요청 |
| 설치와 실행 명령 | 설정 파일과 실행 결과 |
| 테스트와 빌드 명령 | 자동 검사 파일과 실행 결과 |
| 수정하면 안 되는 파일 | 사용자 요청과 기존 규칙 |
| 비밀정보와 완료 확인 | 기존 규칙과 실제 작업 범위 |

설명 파일에는 프로젝트의 목적, 확인한 설치·실행·테스트·빌드 명령, 수정하면 안 되는 파일, 비밀정보를 다루는 방법, 작업을 마친 뒤 확인할 내용을 적습니다. "알아서 잘 테스트한다"처럼 확인할 수 없는 말은 쓰지 않습니다. `npm test`처럼 실제로 찾은 명령과 실행할 폴더를 적고, 명령이 없으면 그 사실을 적습니다.

빈 폴더에서 시작했다면 목적만 있어도 됩니다. 예를 들어 사용자가 개인 메모 웹페이지를 만들겠다고 답했다면 아래처럼 적고, AI가 설치 명령을 지어내지 않았는지 확인합니다.

```markdown
# 프로젝트 목적

개인 메모를 정리하는 웹페이지를 만든다.

## 실행 방법

프로그래밍 언어와 설치·실행·테스트 명령은 아직 정하지 않았다.
```

## AI 작업. 적어 둔 명령 실행

### 기록한 폴더에서 명령을 실행해 성공과 실패를 구분합니다

![my-first-project 폴더에서 npm test를 입력하는 위치를 보여 주는 설명 이미지](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/da/dafdeda8a95bff5b2a99dea1be37ba7723846c701c3a22bc793cb9c73b78ccec.png "명령 이름뿐 아니라 실행 위치와 결과도 기록합니다 · 설명 이미지")

설명 파일에 명령을 적었다면 같은 폴더에서 직접 실행합니다. 표의 `프로그램 실행` 칸에 나오는 개발 서버는 완성 중인 화면을 사용자의 컴퓨터에서 미리 여는 프로그램입니다.

| 설명 파일에 적은 것 | AI가 실행할 것 | 사용자에게 알려 줄 결과 |
|---|---|---|
| 설치 명령 | 문서에 적은 폴더에서 설치 | 어떤 설치 도구를 썼고 성공했는지 |
| 프로그램 실행 | 개발 서버나 프로그램 열기 | 열린 주소나 프로그램 이름 |
| 작은 테스트 | 가장 작은 테스트 실행 | 통과 여부와 실패한 항목 |
| 전체 테스트 | 프로젝트의 자동 검사 파일에 적힌 명령 실행 | 통과 여부와 실패한 항목 |
| 빌드 | 배포 전에 쓰는 명령 실행 | 성공 여부와 만들어진 폴더 |

웹사이트라면 개발 서버 주소를 브라우저로 열어 첫 화면이 보이는지도 확인합니다. 명령이 실패하면 성공했다고 적지 않습니다. 실행한 명령, 실행한 폴더, 나온 오류를 함께 남깁니다.

빈 폴더라 아직 명령이 없다면 실행을 건너뛰고 그 이유를 기록합니다. 필요한 프로그램이나 접속 권한이 없어서 실행하지 못한 것과, 원래 명령이 없는 것을 구분합니다.

## AI 작업. 확인 결과 보고

### 바꾼 파일과 확인하지 못한 것을 보고에서 바로 찾을 수 있게 씁니다

![바꾼 파일과 통과한 검사와 확인하지 못한 것을 나눠 적은 작업 보고](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/77/77cabfe774f0053eadbb77e4816e5cdaff7a7289ab6ccb0416af40c8ba533af8.png "통과하지 못한 검사를 성공한 검사에 섞지 않습니다 · 설명 이미지")

테스트를 실행하지 못했다면 왜 실행하지 못했는지 적고, README에서 찾은 설치 방법을 함께 알려 줍니다. 비밀번호나 인증 정보가 필요한 작업은 값을 추측하지 않고 사용자에게 필요한 항목의 이름만 요청합니다.

보고에는 실행한 폴더까지 함께 적습니다. 사용자가 새 대화를 열어 같은 자리에서 같은 명령이 나오는지 견주기 때문입니다. 보고는 이런 모양입니다.

```text
바꾼 파일
- AGENTS.md

확인한 파일
- README.md
- package.json
- GitHub 자동 검사 파일

통과한 검사
- npm test (프로젝트 최상위 폴더에서 실행)

확인하지 못한 것
- 실행하지 못한 명령과 그 이유

사용자가 확인할 것
- AGENTS.md에 적힌 실행 폴더와 명령이 맞는지 확인
```

여기까지가 AI의 몫입니다.

## 사용자 작업. 새 대화에서 확인

### 같은 프로젝트의 새 대화에서 설명 파일만으로 작업 방법을 되찾습니다

![AGENTS.md의 프로젝트 목적과 새 대화의 답을 대조하는 설명 이미지](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/e1/e1b002d71a7d859e14e2702ce3939ed15b6e582f17a33d8d21eafa863450d665.png "이전 대화의 기억이 아니라 파일에 남긴 내용으로 확인합니다 · 설명 이미지")

먼저 보고의 `바꾼 파일`에 적힌 `AGENTS.md`나 `CLAUDE.md`를 열어 보고에 적힌 명령과 실행 폴더가 그대로 들어 있는지 견줍니다. 그다음 새 대화를 엽니다. 설명 파일을 만든 대화에는 AI가 방금 읽은 파일과 명령이 남아 있습니다. 설명 파일에 필요한 명령이 빠져 있어도 그 대화에서는 AI가 방금 읽은 내용을 기억해 맞는 답을 할 수 있습니다. 그래서 새 대화에서 한 번 더 확인해야 합니다.

같은 프로젝트 폴더를 선택한 채 새 대화를 열고 아래 요청문을 보냅니다. 새 대화에 폴더가 연결되지 않았다면 [프로젝트 폴더 열기](#프로젝트-폴더-열기)에서 위치부터 다시 확인합니다.

```text
설명 파일에 테스트 명령이 있다면 가장 작은 테스트를 실행해 줘
아직 명령이 없는 새 폴더라면 프로젝트 목적과 정하지 않은 실행 방법을 구분해서 알려 줘
읽은 설명 파일과 README를 알려 주고, 명령을 실행했다면 폴더와 명령도 알려 줘
```

테스트가 있는 프로젝트에서는 AI가 `AGENTS.md`나 `CLAUDE.md`를 읽고, 앞의 보고와 같은 폴더에서 같은 테스트를 골랐는지 봅니다. 명령이 없는 빈 폴더에서는 사용자가 정한 목적을 되찾고 없는 실행 방법을 지어내지 않는지 봅니다. 각 경로에서 확인한 내용이 같다면 설명 파일이 제 몫을 한 것입니다.

보고와 다른 목적이나 명령을 말했다면 어떤 파일을 근거로 삼았는지 묻고 설명 파일을 고쳐 달라고 요청합니다. 폴더에 남은 설명 파일과 새 대화의 답이 같은 내용을 가리키는지 확인하고 마칩니다.

## 더 해 볼 것

- 프로젝트의 여러 폴더에 `AGENTS.md`가 흩어져 있다면 Codex는 작업할 파일과 가장 가까운 것을 먼저 따릅니다. 규칙은 [OpenAI의 AGENTS.md 안내](https://developers.openai.com/codex/guides/agents-md)에 있습니다.
- 현재 프로젝트에 맞게 바꿔 쓸 예시는 [eddmpython Agent Template](https://github.com/eddmpython/eddmpython/tree/main/blog/posts/001-ai-needs-an-environment/agent-template)에 있습니다. 그대로 복사하지 말고 현재 프로젝트에서 확인한 값만 남깁니다.
- 설명 파일이 길어지면 AI가 매번 다 읽습니다. 자주 쓰지 않는 규칙은 별도 문서로 빼고 설명 파일에서는 그 문서를 가리킵니다.
