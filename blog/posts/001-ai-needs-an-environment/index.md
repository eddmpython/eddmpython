AI에게 코딩을 맡겨 보고 싶은데 무엇부터 열어야 할까요? 화면에 저장소, README, 터미널 같은 말이 나오면 코드를 쓰기도 전에 막힙니다. 막히는 자리는 하나 더 있습니다. 도구를 열고 나면 새 대화를 열 때마다 이 프로젝트가 무엇이고 어떤 명령으로 실행하는지 다시 설명하게 됩니다.

AI 코딩 도구를 처음 쓰는 사람을 위한 글입니다. 코드를 모르거나 README를 처음 봐도 괜찮습니다. 이 글을 따라가면 프로젝트의 설치와 실행, 테스트 명령이 적힌 `AGENTS.md`나 `CLAUDE.md`가 폴더에 하나 남습니다. 다음 대화의 AI는 그 파일을 읽고 같은 명령을 찾습니다.

직접 할 일은 이렇습니다. AI 코딩 도구를 설치하고 로그인한 뒤, 작업할 프로젝트 폴더를 열고, 아래 요청문을 보내고, AI가 만든 설명 파일을 확인하고, 새 대화에서 그 파일이 제 몫을 하는지 봅니다. 프로그램을 설치하거나 제대로 움직이는지 검사하는 명령은 AI가 프로젝트 안에서 찾아 실행합니다.

## 프로젝트 폴더 열기와 요청문 보내기

AI 코딩 도구는 대화만 하는 AI와 다릅니다. 허용한 프로젝트 파일을 읽고 고칩니다. 프로그램을 실행하는 명령도 입력합니다. Codex와 Claude Code가 이런 도구입니다. 일반 AI 채팅은 이 글 주소를 받아도 내 컴퓨터의 프로젝트 폴더를 보지 못합니다.

아직 도구를 준비하지 않았다면 Codex나 Claude Code 가운데 하나를 골라 설치하고 로그인합니다. [Codex 시작 안내](https://developers.openai.com/codex/quickstart)와 [Claude Code 시작 안내](https://code.claude.com/docs/en/quickstart)에서 지금 쓰는 컴퓨터에 맞는 설치 방법을 볼 수 있습니다.

도구를 열면 작업 파일이 들어 있는 프로젝트 폴더를 선택하고, 도구가 그 폴더의 파일을 읽고 고칠 수 있도록 허용합니다. 이미 받은 프로젝트가 있다면 그 파일들이 들어 있는 폴더를 고릅니다. 새 프로젝트를 시작한다면 `my-first-project`처럼 이름을 붙인 빈 폴더를 하나 만들어 엽니다. 빈 폴더로 시작하면 AI가 무엇을 만들지 먼저 물어봅니다.

프로젝트 폴더를 열었다면 아래 요청문을 그대로 보냅니다.

```text
나는 AI 코딩 도구를 처음 쓴다.
이 프로젝트 폴더를 살펴보고 아래 글의 순서대로 AI용 설명 파일을 만들어 줘
https://eddmpython.com/blog/ai-environment

Codex를 쓰고 있다면 AGENTS.md를, Claude Code를 쓰고 있다면 CLAUDE.md를 먼저 확인해 줘
두 도구를 함께 쓰는 프로젝트라면 규칙은 한 파일에만 적고 다른 파일은 그 파일을 읽게 해 줘
파일을 바꾸기 전에 무엇을 만들지 쉬운 말로 알려 줘
작업이 끝나면 바꾼 파일, 실행한 검사, 내가 확인할 것을 알려 줘
```

요청문을 보내면 준비는 끝납니다. 아래 `AI 작업` 이 붙은 절은 전부 이 글 주소를 받은 AI가 맡습니다. 거기 나오는 `git status` 같은 명령어를 다 몰라도 됩니다. AI는 파일을 바꾸기 전에 무엇을 만들지 먼저 알려 줍니다. 그 설명을 읽고 맞으면 이어서 진행하라고 답합니다. 일이 끝나면 `바꾼 파일`과 `확인하지 못한 것`을 읽고, 마지막 `사용자 작업` 절에서 새 대화를 열어 직접 확인합니다.

## AI 코딩에서 자주 나오는 말

| 화면에 나오는 말 | 쉬운 뜻 |
|---|---|
| 프로젝트 폴더 | 프로그램을 만드는 파일을 한곳에 모아 둔 폴더 |
| 저장소 또는 repo | 프로젝트 폴더와 파일의 변경 기록을 함께 부르는 말 |
| `README.md` | 이 프로젝트가 무엇이고 어떻게 실행하는지 사람에게 알려 주는 파일 |
| 터미널 | 컴퓨터에 글자로 명령을 입력하는 창 |
| 명령어 | 설치, 실행, 검사 같은 일을 컴퓨터에 시키는 짧은 문장 |
| 테스트 | 프로그램의 일부가 예상대로 움직이는지 자동으로 확인하는 작업 |
| 빌드 | 프로그램의 원본 파일을 실제로 실행할 수 있는 파일이나 서비스에 올릴 수 있는 파일로 바꾸는 작업 |
| `AGENTS.md`, `CLAUDE.md` | 이 프로젝트에서 AI가 지켜야 할 작업 방법을 적는 글 파일 |

파일 이름 뒤의 `.md`는 메모장으로 열어 글을 적을 수 있는 파일 형식입니다. `README.md`가 없다고 프로젝트가 고장 난 것은 아닙니다. `AGENTS.md`와 `CLAUDE.md`도 처음부터 있는 파일은 아니라 이 글에서 만들 것입니다.

Codex는 `AGENTS.md`에서 프로젝트 지침을 읽고 Claude Code는 `CLAUDE.md`를 읽습니다. 자세한 읽기 방식은 [OpenAI의 AGENTS.md 안내](https://developers.openai.com/codex/guides/agents-md)와 [Claude Code의 CLAUDE.md 안내](https://code.claude.com/docs/en/memory)에 있습니다. 두 도구를 함께 쓸 때 파일을 어떻게 연결하는지는 `AI 작업 3` 에서 다룹니다.

## AI 작업. 멈추고 물어보는 때

AI가 이 페이지를 읽고 있다면 사용자가 요청한 범위 안에서 현재 프로젝트를 조사합니다. 어느 설명 파일에 적을지는 아래 `AI 작업 3` 에서 정합니다. 사용자가 검토만 요청했다면 파일을 바꾸지 않고 확인한 내용만 알려 줍니다.

사용자가 글 주소만 보내고 할 일을 말하지 않았다면 파일을 바꾸지 않습니다. `새 설명 파일 만들기`, `기존 파일 고치기`, `내용만 검토하기` 가운데 무엇을 원하는지 묻습니다.

프로젝트 폴더를 읽을 수 없다면 폴더 접근을 요청합니다. 폴더를 열 수 없는 채팅에서는 `README.md`, 기존 `AGENTS.md`와 `CLAUDE.md`, 설치와 테스트 방법이 적힌 설정 파일을 요청한 뒤 기다립니다. 폴더는 읽을 수 있지만 그 안이 비어 있거나 목적과 실행 방법을 확인할 파일이 없다면 내용을 추측하지 않습니다. 사용자에게 무엇을 만들려는지, Python이나 JavaScript처럼 이미 정한 프로그래밍 언어가 있는지 묻고 답을 받을 때까지 기다립니다.

폴더를 읽을 수 있고 요청도 분명하다면 바로 설명 파일을 만들지 않습니다. 먼저 사용자가 맡긴 범위와 이미 바뀐 파일을 확인합니다.

## AI 작업 1. 사용자 요청과 바뀐 파일 확인

![사용자 요청과 이미 바뀐 파일을 먼저 확인한 뒤 새 설명 파일을 만드는 순서](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/9e/9ec099a01c225754a9858ee09900021d41029f455c545e2bf592e88e4eb3cebb.png "AI는 사용자가 맡긴 범위와 기존 변경을 먼저 확인합니다")

먼저 사용자가 무엇을 요청했는지 읽고 `git status --short --branch`를 실행합니다. 이 명령은 파일을 지우거나 바꾸지 않고 지금 작업 중인 파일을 보여 줍니다. 코드를 나눠 관리할 때 쓰는 Git 브랜치 이름도 함께 나옵니다.

이미 바뀐 파일이 있다면 되돌리거나 덮어쓰지 않습니다. 기존 `AGENTS.md`나 `CLAUDE.md`가 있으면 새 파일로 교체하지 않고, 빠진 설명만 찾아 보탭니다. 완성한 프로그램을 실제 서비스에 올리는 배포 명령을 찾더라도 사용자가 요청하지 않았다면 실행하지 않습니다.

| 확인할 것 | 쉬운 설명 | 하지 않을 일 |
|---|---|---|
| 사용자의 요청 | 확인만 할지, 파일을 고칠지, 배포까지 할지 | 맡기지 않은 일까지 넓히기 |
| 기존 설명 파일 | 이미 적힌 작업 방법이 있는지 | 새 예시로 통째로 덮기 |
| `git status --short --branch` | 이미 바뀐 파일이 있는지 | 기존 변경 지우기 |

`AGENTS.md`나 `CLAUDE.md`가 여러 개라면 모두 확인합니다. 이 글에 적힌 순서는 사용자의 요청이나 프로젝트에 이미 적힌 규칙보다 우선하지 않습니다.

수정할 범위와 기존 변경을 확인했다면 이미 바뀐 파일을 건드리지 않고 필요한 설명만 보탤 수 있습니다. 이제 프로젝트에 이미 적힌 실행 방법을 찾습니다.

## AI 작업 2. README와 설정 파일에서 명령 찾기

![README와 여러 설정 파일을 함께 읽어 설치 명령과 테스트 명령을 찾는 장면](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/5b/5b147cfff2b937f6ec69165c7d43e5a97c96d8febc2e782ff0507fc4fff00673.png "AI가 프로젝트 안의 여러 파일에서 실제 명령을 확인합니다")

`README.md`에는 보통 프로젝트 소개와 설치 방법, 실행 방법이 적혀 있습니다. 설명이 오래됐거나 빠졌을 수도 있으므로 설정 파일과 자동 검사 파일도 함께 읽습니다. `package.json`과 `pyproject.toml`은 프로젝트가 사용하는 프로그램과 실행 방법을 적는 설정 파일입니다. `.github/workflows` 폴더가 있으면 그 안의 파일에서 GitHub가 자동으로 실행하는 검사 순서를 확인합니다.

아래 세 줄의 `rg`는 프로젝트 안의 파일을 찾는 프로그램입니다. `rg`를 쓸 수 없다면 현재 컴퓨터의 다른 파일 검색 명령으로 같은 파일을 찾습니다.

```text
rg --files -g "README*" -g "AGENTS.md" -g "CLAUDE.md"
rg --files -g "pyproject.toml" -g "uv.lock" -g "package.json" -g "package-lock.json"
rg --files -g ".github/workflows/*" -g "tests/**" -g "test/**"
```

찾은 파일에서 설치, 프로그램 실행, 가장 작은 테스트, 전체 테스트, 빌드 명령을 확인합니다. 명령을 어느 폴더에서 실행해야 하는지도 함께 적습니다. README와 자동 검사 파일에 적힌 명령이 다르면 어느 쪽을 실제로 확인했는지 설명합니다. 비밀번호나 서비스 접속 정보를 담을 수 있는 `.env` 파일에서는 항목 이름만 확인하고 값은 출력하지 않습니다.

설치와 실행, 테스트, 빌드 명령을 찾았으니 이제 설명 파일에 추측이 아닌 실제 명령을 적을 수 있습니다.

## AI 작업 3. AGENTS.md와 CLAUDE.md 가운데 한 파일에 모으기

![AGENTS.md와 CLAUDE.md 가운데 한 파일에 규칙을 적고 다른 파일이 그 규칙을 읽는 구조](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/f3/f3e10a5d91b6ab8315e0cf92c2221462ebc8c81bf2e4b04e5018da6eca3f7bb1.png "같은 작업 방법을 두 파일에 복사하지 않습니다")

사용자가 Codex만 쓴다면 `AGENTS.md`에 확인한 명령과 수정하면 안 되는 파일을 적습니다. Claude Code만 쓴다면 `CLAUDE.md`에 적습니다. 쓰지 않는 도구의 파일까지 만들 필요는 없습니다.

두 도구를 함께 쓴다면 기존 프로젝트의 방식을 먼저 따릅니다. 두 파일이 모두 없다면 `AGENTS.md`에 공통 규칙을 적습니다. `CLAUDE.md` 파일에 아래 한 줄만 넣으면 Claude Code가 `AGENTS.md`를 함께 읽습니다. 같은 내용을 두 번 적지 않아도 됩니다.

```markdown
@AGENTS.md
```

기존 프로젝트가 `CLAUDE.md`에 규칙을 모아 두었다면 그 규칙을 `AGENTS.md`로 옮기지 않습니다. `AGENTS.md`에는 아래처럼 `CLAUDE.md`를 먼저 읽으라고 적을 수 있습니다.

```markdown
# 프로젝트 설명

작업을 시작하기 전에 `CLAUDE.md`를 끝까지 읽는다.
공통 작업 방법은 `CLAUDE.md`에만 적는다.
```

설명 파일에는 프로젝트의 목적, 설치와 실행 명령, 테스트와 빌드 명령, 수정하면 안 되는 파일, 비밀정보를 다루는 방법, 작업을 마친 뒤 확인할 내용을 적습니다. "알아서 잘 테스트한다"처럼 확인할 수 없는 말은 쓰지 않습니다. `npm test`처럼 실제로 찾은 명령과 실행할 폴더를 적습니다.

설명 파일을 만들었다고 끝난 것은 아닙니다. 적어 둔 명령이 실제로 움직이는지 같은 프로젝트 폴더에서 실행해 봐야 합니다.

## AI 작업 4. 적어 둔 명령을 실제로 실행

![설치와 실행 및 테스트 명령을 하나씩 실행하고 결과를 확인하는 장면](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/39/399fba52cdd484055106cfa88c8685f42755cdf44fc6783b96b3364b49f55427.png "설명 파일에 적은 명령이 실제로 동작하는지 하나씩 확인합니다")

설명 파일에 명령을 적었다면 같은 폴더에서 직접 실행합니다. 표의 `프로그램 실행` 칸에 나오는 개발 서버는 완성 중인 화면을 사용자의 컴퓨터에서 미리 여는 프로그램입니다.

| 설명 파일에 적은 것 | AI가 실행할 것 | 사용자에게 알려 줄 결과 |
|---|---|---|
| 설치 명령 | 문서에 적은 폴더에서 설치 | 어떤 설치 도구를 썼고 성공했는지 |
| 프로그램 실행 | 개발 서버나 프로그램 열기 | 열린 주소나 프로그램 이름 |
| 작은 테스트 | 가장 작은 테스트 실행 | 통과 여부와 실패한 항목 |
| 전체 테스트 | 프로젝트의 자동 검사 파일에 적힌 명령 실행 | 통과 여부와 실패한 항목 |
| 빌드 | 배포 전에 쓰는 명령 실행 | 성공 여부와 만들어진 폴더 |

웹사이트라면 개발 서버 주소를 브라우저로 열어 첫 화면이 보이는지도 확인합니다. 명령이 실패하면 성공했다고 적지 않습니다. 실행한 명령, 실행한 폴더, 나온 오류를 함께 남깁니다.

프로젝트에 필요한 프로그램이나 접속 권한이 없으면 모든 명령을 실행할 수는 없습니다. 실행한 명령과 나온 결과를 모았으니 이제 사용자에게 무엇을 알릴 차례입니다.

## AI 작업 5. 실행 결과와 확인하지 못한 것 알리기

![기존 변경, 없는 도구, 비밀정보, 배포 권한 때문에 멈춘 작업을 따로 알려 주는 그림](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/22/224f77ce7c9528b75c42653dfc4bcaf96ff50057765096fdb5db81ce568767a0.png "실행하지 못한 일은 이유와 함께 따로 보고합니다")

테스트를 실행하지 못했다면 왜 실행하지 못했는지 적고, README에서 찾은 설치 방법을 함께 알려 줍니다. 비밀번호나 인증 정보가 필요한 작업은 값을 추측하지 않고 사용자에게 필요한 항목의 이름만 요청합니다.

보고에는 실행한 폴더까지 함께 적습니다. 사용자가 새 대화를 열어 같은 자리에서 같은 명령이 나오는지 견주기 때문입니다. 보고는 이런 모양입니다.

```text
바꾼 파일
- AGENTS.md

확인한 파일
- README.md
- package.json
- GitHub 자동 검사 파일

통과한 검사
- npm test (프로젝트 최상위 폴더에서 실행)

확인하지 못한 것
- 배포 권한이 없어 실제 배포는 실행하지 않음

사용자가 확인할 것
- AGENTS.md에 적힌 실행 폴더와 명령이 맞는지 확인
```

여기까지가 AI의 몫입니다.

## 사용자 작업. 새 대화에서 확인

![새 대화의 AI가 프로젝트 설명 파일을 읽고 같은 테스트를 실행하는 흐름](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/e7/e73d4c46c9f28f6baeb7f7ea09433ca25fe59858416f9280899289784c47d09e.png "새 대화에서도 같은 작업 방법을 찾는지 확인합니다")

먼저 보고의 `바꾼 파일`에 적힌 `AGENTS.md`나 `CLAUDE.md`를 열어 보고에 적힌 명령과 실행 폴더가 그대로 들어 있는지 견줍니다. 그다음 새 대화를 엽니다. 설명 파일을 만든 대화에는 AI가 방금 읽은 파일과 명령이 남아 있습니다. 설명 파일에 필요한 명령이 빠져 있어도 그 대화에서는 AI가 방금 읽은 내용을 기억해 맞는 답을 할 수 있습니다. 그래서 새 대화에서 한 번 더 확인해야 합니다.

새 대화를 열고 아래처럼 요청합니다.

```text
이 프로젝트에서 가장 작은 테스트를 찾아 실행해 줘
어떤 설명 파일과 README를 읽었는지, 어떤 폴더에서 무슨 명령을 실행했는지도 알려 줘
```

AI가 `AGENTS.md`나 `CLAUDE.md`를 읽고, 앞의 보고에 적힌 것과 같은 폴더에서 같은 테스트를 골랐다면 설명 파일이 제 몫을 한 것입니다. 다른 명령을 골랐다면 그 대화에서 AI에게 어떤 파일을 읽고 그 명령을 골랐는지 물어보고, 이어서 `AGENTS.md`나 `CLAUDE.md`를 고쳐 달라고 요청합니다. 여기까지 왔으면 설치와 실행, 테스트 명령이 적힌 파일이 폴더에 하나 남았고 새 대화의 AI도 그 파일을 읽습니다.

## 더 해 볼 것

- 프로젝트의 여러 폴더에 `AGENTS.md`가 흩어져 있다면 Codex는 작업할 파일과 가장 가까운 것을 먼저 따릅니다. 규칙은 [OpenAI의 AGENTS.md 안내](https://developers.openai.com/codex/guides/agents-md)에 있습니다.
- 현재 프로젝트에 맞게 바꿔 쓸 예시는 [eddmpython Agent Template](https://github.com/eddmpython/eddmpython/tree/main/blog/posts/001-ai-needs-an-environment/agent-template)에 있습니다. 그대로 복사하지 말고 현재 프로젝트에서 확인한 값만 남깁니다.
- 설명 파일이 길어지면 AI가 매번 다 읽습니다. 자주 쓰지 않는 규칙은 별도 문서로 빼고 설명 파일에서는 그 문서를 가리킵니다.
