AI가 이 주소를 작업 지시로 받았다면 페이지를 요약하지 말고 사용자가 준 한국어 원문을 고칩니다. 사실, 수치, 인용, 고유명사, 코드, 요구와 추정의 뜻은 그대로 둡니다. 원문이 없으면 고칠 글이나 파일 경로를 요청하고 기다립니다.

금지어를 다 지운 글도 AI처럼 읽힐 수 있습니다. 저도 그 사실을 알면서 숫자부터 고쳤습니다. 문장 길이 비율이 0.36으로 나오자 다른 글에 `317 바이트입니다`, `계단입니다`, `48픽셀 차이입니다`를 끼워 넣었습니다. 비율은 0.47로 올라갔고 글은 더 나빠졌습니다.

제가 숫자를 고치는 동안 문장은 망가졌습니다.

검사 숫자는 합격점이 아닙니다. 번역투와 비슷한 길이의 문장이 몰린 자리를 찾는 신호입니다. 검사 스크립트가 글 파일에서 찾은 문장은 뜻을 읽고 고치며, 질문과 실패와 판단처럼 원문에 없는 내용은 글쓴이 대신 만들지 않습니다. AI에게 아래 주소와 원문을 보내면 이 페이지의 순서와 기준을 적용합니다.

## AI 글 자연스럽게 고치는 네 단계

### 페이지 요약 대신 받은 원문을 고치고 못 고친 자리를 보고합니다

AI는 원문을 받으면 아래 네 단계를 순서대로 실행합니다. 표현을 세지 않고 시작하면 눈에 띄는 몇 문장만 바뀌고, 숫자를 보자마자 문장을 고치면 제가 했던 것처럼 글을 검사기에 맞추게 됩니다. 겪지 않은 실패와 확인하지 않은 수치는 채우지 않습니다.

#### 설명 목록: 네 단계와 멈출 자리

| 단계 | 하는 일 | 이 단계에서 조심할 것 |
|---|---|---|
| 1. 세기 | 번역투, 형식명사, 관용구, 문장 길이, 종결어미를 셉니다 | 표와 코드와 인용은 글쓴이 문체에서 뺍니다 |
| 2. 판정 | 심각도, 몇 번 나왔는지, 글 길이에 비해 얼마나 몰렸는지 봅니다 | 숫자를 합격점으로 만들지 않습니다 |
| 3. 교정 | 걸린 문장과 그 자리의 조사와 어미를 고칩니다 | 사실과 문장의 뜻을 바꾸지 않습니다 |
| 4. 읽기 | 질문, 실패, 판단, 확인 범위가 비었는지 봅니다 | 없는 경험을 AI가 지어내지 않습니다 |

#### 출력 예시: 고친 글과 사람이 채울 내용을 나누기

AI는 답을 아래 순서로 씁니다. 원문에 없던 경험이나 수치가 필요한 문장은 억지로 완성하지 않고 `사람이 채울 내용`에 남깁니다.

```text
고친 글
- 전체 수정문

남겨 둔 표현
- 검사에는 걸렸지만 뜻이 맞아 유지한 문장과 이유

사람이 채울 내용
- 원문에 없는 실패, 수치, 판단, 확인 범위
```

이 형식은 AI가 고친 문장과 원문에 없어 건드리지 않은 자리를 섞지 않습니다. 사람은 세 번째 항목을 확인하고 실제 경험과 측정값만 글 파일에 채웁니다. 이제 어떤 표현을 몇 번부터 고칠지 정합니다.

## 몇 번부터 고칠지 정하는 기준

### 한 번만 나와도 고칠 표현과 반복될 때 고칠 표현을 나눕니다

표현의 심각도는 S1, S2, S3 세 단계로 나눕니다. S1은 한 번만 나와도 고칠 후보이고, S2는 한두 번은 자연스러워 정해진 횟수부터 봅니다. S3는 권한이나 가능처럼 뜻을 바꿀 위험이 있어 다른 문제와 겹칠 때만 고칩니다. 짧은 글에서는 횟수만 보면 문제를 놓칠 수 있습니다. S1과 S2를 합쳐 1만자당 50건을 넘거나 걸린 표현이 8종을 넘으면 글 전체에 고칠 표현이 몰렸다고 봅니다. S3는 이 계산에서 뺍니다.

#### 설명 목록: 번역투와 바꿔 쓸 문장

| 걸리는 문장 | 심각도와 기준 횟수 | 바꿔 쓸 문장 |
|---|---|---|
| 이 문제에 대하여 살펴보겠습니다 | S2, 3건 | 이 문제를 살펴보겠습니다 |
| API를 통해 데이터를 받습니다 | S2, 3건 | API로 데이터를 받습니다 |
| 성능에 있어서 차이가 있습니다 | S2, 2건 | 성능이 다릅니다 |
| 빠르다는 점에서 유리합니다 | S2, 2건 | 빨라서 유리합니다 |
| 인자를 세 개 가지고 있습니다 | S2, 2건 | 인자가 셋입니다 |
| 파일이 생성되어집니다 | S1, 1건 | 파일이 만들어집니다 |
| 설정이 스크립트에 의해 바뀝니다 | S2, 2건 | 스크립트가 설정을 바꿉니다 |
| 원인은 스케줄러로 파악되었습니다 | S2, 2건 | 원인을 찾아보니 스케줄러였습니다 |
| 검토하였다고 보고했습니다 | S2, 2건 | 검토했다고 보고했습니다 |
| 파일들을 확인하고 오류들을 고쳤습니다 | 사람이 읽음 | 파일 넷을 확인하고 오류를 고쳤습니다 |

`가지고 있다`가 실제로 물건을 소지한 뜻이면 그대로 둡니다. `~에 의해`도 환자처럼 앞 문장의 주제를 유지하려고 쓴 피동이면 섣불리 능동으로 돌리지 않습니다. 예외는 횟수 기준보다 먼저 봅니다.

#### 설명 목록: 형식명사와 완곡과 AI 관용구

| 걸리는 문장 | 심각도와 기준 횟수 | 바꾸는 법 |
|---|---|---|
| 결국 캐시가 문제였던 것입니다 | S2, 3건 | 결국 캐시가 문제였습니다 |
| 원인 분석이 어려운 측면이 있었습니다 | S2, 3건 | 원인을 찾기가 어려웠습니다 |
| 설정을 확인할 필요가 있습니다 | S2, 2건 | 설정을 확인해 보시기 바랍니다 |
| 성능이 개선될 것으로 보입니다 | S2, 2건 | 어디까지 확인했는지 밝힙니다 |
| 이 명령으로 로그를 볼 수 있습니다 | S3, 5건 | 이 명령이 로그를 보여 줍니다 |
| 또한 캐시도 지워야 합니다 | S2, 3건 | 앞 결과의 이름을 다시 적어 잇습니다 |
| 이는 성능에 영향을 줍니다 | S2, 2건 | 느려지는 검사 이름을 적습니다 |
| 매우 빠르게 처리됩니다 | S2, 3건 | 확인한 시간이 있으면 수치로 적습니다 |
| 체계적인 방식으로 관리합니다 | S2, 3건 | 파일을 어디에 어떻게 모으는지 적습니다 |
| 안정성 향상에 노력하고 있습니다 | S2, 2건 | 안정시키는 일을 계속하고 있습니다 |
| 결론적으로, 시사하는 바가 크다 | S1, 1건 | 결론을 바로 씁니다 |
| 그것을 확인하고 그들을 정리했습니다 | S2, 3건 | 대상을 이름으로 다시 적습니다 |
| 크게 세 가지로 나눌 수 있습니다 | S2, 2건 | 나눈 뒤 바로 셉니다 |
| 수집에서 분석으로 나아가는 흐름 | S2, 2건 | 무엇이 어떻게 바뀌는지 적습니다 |
| 데이터가 말해 줍니다 | S2, 2건 | 판단한 사람이나 검사 결과를 적습니다 |
| 이모지와 긴 줄표 | S2, 1건 | 다른 표식과 겹치는지 보고 지웁니다 |

`~할 수 있다`는 특히 조심합니다. `관리자만 바꿀 수 있습니다`를 `관리자가 바꿉니다`로 고치면 권한이 현재 행동으로 바뀝니다. `개선될 것으로 보입니다`도 원문에 측정값이 없으면 숫자를 만들지 않고 무엇을 확인하지 못했는지 남깁니다. 번역투를 뺀 자리에는 조사 문제가 남습니다.

## 번역투를 지운 뒤 조사 고르기

### 앞뒤 말에 맞춰 조사와 문장 구조를 다시 고릅니다

`안정성 향상에 대하여 노력하고 있습니다`에서 `에 대하여`만 지우면 `안정성 향상에 노력하고 있습니다`가 남습니다. 여전히 어색합니다. `노력하다`는 목적어를 바로 받지 않는 자동사라 조사를 바꾸는 것만으로는 해결되지 않습니다. `안정시키는 일을 계속합니다`처럼 원래 주장을 동사로 다시 써야 합니다.

#### 설명 목록: 서술어가 요구하는 조사

| 서술어 | 고르는 조사나 문장 | 예 |
|---|---|---|
| 타동사, 살피다와 바꾸다 | 을 또는 를 | 이 문제를 살펴보겠습니다 |
| 자동사, 노력하다와 기여하다 | 조사만 바꾸지 않고 문장을 다시 씁니다 | 안정시키는 일을 계속합니다 |
| 형용사, 다르다와 크다 | 이 또는 가 | 성능이 다릅니다 |
| 수단 | 로 또는 으로 | API로 받습니다 |

`의` 하나는 문제가 아닙니다. `데이터 파이프라인의 안정성의 향상의 필요성`처럼 한 구 안에서 겹친 자리만 풉니다. 조사까지 고쳤다면 번역투와 별개인 한국어 어법을 봅니다.

## 문법과 띄어쓰기

### 조사와 높임과 시제와 띄어쓰기는 AI 티가 없어도 틀리면 고칩니다

사람이 쓴 글도 `할수 있습니다`나 `되지 안습니다`를 씁니다. 문법과 띄어쓰기는 정해진 횟수를 기다리지 않고 틀린 자리에서 고칩니다. 다만 `코끼리는 코가 길다` 같은 이중 주어는 한국어의 정상 문장이고, 대외 문서의 `저희`도 표준 표현이라 글의 종류를 보고 둡니다.

#### 설명 목록: 한국어에서 자주 틀리는 자리

| 틀린 문장 | 고친 문장 | 이유 |
|---|---|---|
| 주문하신 커피 나오셨습니다 | 주문하신 커피 나왔습니다 | 높이는 대상은 사람입니다 |
| 성능을 향상시켰습니다 | 성능을 높였습니다 | 시키다는 남에게 시킨 뜻입니다 |
| 할수 있습니다 | 할 수 있습니다 | 의존명사는 띄어 씁니다 |
| 되지 안습니다 | 되지 않습니다 | 않은 아니하의 준말입니다 |
| 안됩니다 | 안 됩니다 | 안은 부사라 띄어 씁니다 |
| 노력하고 있습니다. 제약이 있었습니다. 기대됩니다. | 한 문단의 시제를 맞춥니다 | 현재와 과거와 추정이 섞였습니다 |
| 운영 효율성 향상 방안 도출 | 어디를 고치면 손이 덜 가는지 찾습니다 | 한자 명사를 동사로 풉니다 |

문법을 다 고쳐도 글쓴이가 보이지 않을 수 있습니다. 금지어 목록이 닿지 못하는 자리가 남기 때문입니다.

## 사람 글에 남는 것

### 질문과 실제 실패와 판단과 확인 범위는 문자열 검색으로 만들 수 없습니다

![어두운 바탕에 놓인 접시 안에 잘라 낸 작은 종이 조각 아홉 개가 모여 있고 그 옆에는 아무것도 잘리지 않은 종이 한 장이 그대로 놓여 있는 화면](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/93/9350676bec68e5034004743b273718ab9a8dc8620a35704298eac1bb278b92b0.webp "걸러 낸 조각을 다 담아도 손대지 않은 쪽은 그대로 남습니다")

글 파일에서 번역투와 관용구를 모두 걷어내도 글쓴이의 질문과 실패와 판단이 비어 있으면 기계 문장만 남습니다. 003의 수치를 잘못 읽은 일은 실제로 겪었으므로 그 글에 넣습니다. 반대로 원문 파일에 없는 회사 사례나 세 번 실패했다는 경험을 자연스러워 보이게 하려고 만들면 안 됩니다. AI는 비어 있는 자리를 보고하고 글쓴이가 사실을 채웁니다.

#### 설명 목록: 자동으로 채우지 않을 네 자리

| 필요한 것 | 글에 남기는 방법 |
|---|---|
| 질문 | 독자가 다음에 궁금해할 대상을 이름으로 묻습니다 |
| 실패 | 실제로 실행한 명령과 처음 어긋난 결과를 적습니다 |
| 판단 | 선택지를 늘어놓은 뒤 어느 쪽을 쓰는지 밝힙니다 |
| 확인 범위 | 확인한 것은 단언하고 못 본 입력과 크기를 따로 적습니다 |

문장 길이도 같은 원칙으로 봅니다. 문장 길이가 얼마나 들쭉날쭉한지 계산한 값이 0.45 아래면 비슷한 길이의 문장이 몰린 자리를 읽어 봅니다. 짧은 문장을 끼워 넣어 0.45를 넘기는 것이 목적은 아닙니다. 코드 한 줄의 입력값과 출력값이 한 문장에 함께 들어가 읽기 어렵다면 나누고, 앞뒤가 한 판단이면 붙입니다. 숫자가 아니라 뜻이 문장을 끊습니다.

## 고치면서 바꾸면 안 되는 것

### 사실과 문장의 뜻을 지키고 절반 넘게 바뀌면 다시 쓸지 판단합니다

교정은 글쓴이의 사실과 태도를 보존해야 합니다. 수치와 인용과 고유명사와 코드는 그대로 두고, 요구를 사실로 바꾸거나 추정을 단언으로 바꾸지 않습니다. 고칠 표현이 많이 몰리지 않은 글에서 전체 문장의 절반이 바뀐다면 멈춥니다. 그때는 문장 몇 개를 고치는 일이 아니라 글의 순서부터 다시 써야 할 수 있습니다.

#### 설명 목록: 어떤 경우에도 지킬 네 가지

| 지키는 것 | 뜻 |
|---|---|
| 사실을 바꾸지 않습니다 | 수치, 인용, 고유명사, 코드, 날짜를 유지합니다 |
| 없는 것을 만들지 않습니다 | 원문에 없는 수치와 실패와 사례를 만들지 않습니다 |
| 정당한 용법을 남깁니다 | 한 항목을 0건으로 만들려고 예외까지 지우지 않습니다 |
| 문장의 뜻을 유지합니다 | 요구, 가능, 추정, 사실을 서로 바꾸지 않습니다 |

고친 뒤에는 글 파일을 다시 읽고 검사 항목과 건수, 못 고친 문장, 비어 있는 경험을 나눠 보고합니다. 같은 검사를 자주 한다면 `human-voice` 스킬을 저장소에 둡니다.

## human-voice 스킬로 검사하기

### 스킬 파일 다섯 개를 함께 두면 웹 없이도 같은 기준으로 검사합니다

공개 저장소의 `.agents/skills/human-voice/`에는 실행 순서, 빼는 목록, 한국어 문법, 넣는 목록, 검사 스크립트가 함께 있습니다. 한 파일만 떼어 가면 예외나 조사 교정이나 사람 신호가 빠집니다. 검사 스크립트는 파이썬 표준 라이브러리만 쓰고 인용과 표와 코드를 제외한 본문을 검사합니다. 이 페이지 내용만으로도 글을 고칠 수 있으며, 더 자세한 예외가 필요하면 [human-voice 스킬 전체 폴더](https://github.com/eddmpython/eddmpython/tree/main/.agents/skills/human-voice)를 함께 줍니다.

#### 실행 명령: 한국어 글 한 편의 AI 표식 세기

아래 명령은 항목별 건수와 밀도, 문장 길이 비율, 종결어미 비율을 출력합니다. 문장이 15개보다 적으면 리듬 표본이 작아서 재지 않고, 짧은 계사 문장도 따로 보여 줍니다.

```powershell
python -X utf8 .agents/skills/human-voice/count-ai-tells.py 내글.md
```

문장 길이 비율 0.45와 가장 많이 쓴 종결어미 55퍼센트는 문서를 다시 읽어 볼 기준입니다. 출력이 빨갛다고 문장을 더 만들지 말고, 걸린 자리를 읽어 뜻으로 고칩니다. 마지막 보고에 못 고친 것과 비어 있는 것을 남겼다면 이 스킬은 AI 티를 숨긴 것이 아니라 사람이 이어서 고칠 자리를 찾은 것입니다.
