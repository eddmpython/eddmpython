Python을 공부할 때 가장 자주 끊기는 순간은 문법을 모를 때가 아닙니다. 설명을 읽고 예제도 이해했는데,
내 손으로 값을 바꾸고 실행하려면 갑자기 설치, 가상환경, 에디터 설정부터 해야 할 때입니다. 겨우 실행한
코드도 강의 페이지를 닫는 순간 사라집니다. 나중에 실제 파일이나 반복 업무에 쓰려면 다시 처음부터
작업 환경을 만들어야 합니다.

Codaro는 이 끊김을 줄이기 위한 Python 학습과 개인 자동화 스튜디오입니다. Web에서는 설치 없이
레슨을 읽고 코드를 수정하고 실행합니다. Local에서는 같은 문서와 학습 기록을 실제 파일, 패키지,
터미널, 일정 실행으로 넓힙니다. 이 글은 기능 목록을 늘어놓기보다 첫 레슨을 여는 순간부터 실행한
코드를 자동화로 가져가는 순간까지 한 흐름으로 따라갑니다. 중간에는 이 페이지를 떠나지 않고 직접
고쳐 실행할 수 있는 예제 셀도 준비했습니다.

## Codaro는 코드를 읽는 곳이 아니라 고쳐서 증명하는 곳입니다

![편집과 실행과 검증을 거친 Python 셀이 반복 가능한 작업으로 이어지는 작업대](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/75/75e8abd651ab9e1d1dd850e8e5c64c3bc1b396a2cf4517652ce075f476f9c6a3.webp "Codaro의 기본 단위는 읽고 끝나는 예제가 아니라 수정과 실행과 검증을 통과한 셀이다")

일반적인 Python 강의 페이지는 설명, 완성 코드, 정답을 차례로 보여 줍니다. 읽는 동안에는 이해한 것
같지만 숫자 하나를 바꾸면 어디가 달라지는지, 다른 입력에서도 같은 코드가 버티는지는 확인하기
어렵습니다. 반대로 빈 에디터만 주는 도구는 자유롭지만 무엇을 왜 만들어야 하는지 처음부터 사용자가
정해야 합니다.

Codaro의 학습 흐름은 둘 사이를 잇습니다. 먼저 이번 레슨에서 남길 결과와 완성된 입출력 장면을
보여 줍니다. 그다음 설명 바로 아래의 코드를 직접 수정하고 실행하게 합니다. 실행 결과와 오류는 같은
흐름 안에서 갱신되고, 레슨이 요구한 조건을 만족했는지는 구조화된 검증으로 확인합니다. 정답을 한 번
맞히는 데서 끝내지 않고 입력을 바꿔 보거나 실제 데이터와 산출물로 옮기는 변주가 뒤따릅니다.

그래서 Codaro를 단순한 온라인 코드 실행기로 보면 중요한 절반을 놓칩니다. 실행기는 코드가 돌아가는지
알려 줍니다. Codaro는 무엇을 만들려 했는지, 어떤 증거로 성공을 판단하는지, 이 작업을 다음에 어디에
쓸지를 같은 문서 안에 남기는 데 초점을 둡니다.

## 설치 없이 Web에서 첫 레슨을 시작합니다

![설치 장벽을 지나지 않고 바로 Python 학습 작업대로 들어가는 열린 웹 진입로](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/a6/a6880c33189b23b51c6700d7c27bba8fbfc383e57c44b1d28d22c4e0bb6796c2.webp "Web은 가벼운 체험판이 아니라 설치 없이 시작하는 Codaro의 기본 학습 입구다")

처음에는 [Codaro Web 학습](https://eddmpython.com/codaro/learn/)을 엽니다. 계정을 만들거나 Python을
먼저 설치할 필요는 없습니다. 학습 화면에서 목표 경로와 주제를 고르고, 각 레슨이 Web에서 실행되는지
Local 기능이 필요한지 확인할 수 있습니다. Web 지원 레슨을 열면 설명, 완성 예제, 편집 가능한 실습이
한 화면의 읽기 순서로 이어집니다.

첫 레슨에서는 다음 세 가지에 집중하면 됩니다.

1. 제목 아래에서 이 레슨이 만들 결과를 먼저 확인합니다.
2. 예제 코드를 그대로 한 번 실행해 입력과 출력의 관계를 봅니다.
3. 값이나 조건을 하나 바꾼 뒤 다시 실행하고 검증 결과가 왜 달라졌는지 읽습니다.

브라우저 실행은 시뮬레이션이 아닙니다. Web Run은 브라우저 안의 Python 런타임에서 실제 코드를
실행합니다. 다만 모든 Python 작업이 Web에서 가능한 것은 아닙니다. 운영체제 파일, 네이티브 패키지,
시스템 터미널, 자격증명, 일정 실행처럼 로컬 컴퓨터의 권한이 필요한 레슨은 처음부터 Local로
표시합니다. 공개적으로 읽을 수 있다는 사실과 브라우저에서 실행할 수 있다는 사실을 섞지 않는 것이
Codaro의 실행 환경 원칙입니다.

## 이 글 안에서 Codaro 방식의 셀을 실행해 봅니다

![기술 글의 한가운데 놓인 편집 가능한 셀이 브라우저 실행 장치와 연결된 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/ef/ef8d12c5a20a452518c8d7d084d5811a6650ed0f678ccadead0d4ccd58b4cf75.webp "설명을 읽은 자리에서 값을 바꾸고 결과를 확인하면 개념과 실행 사이의 거리가 짧아진다")

아래 셀에는 도시별 매출 네 건이 들어 있습니다. 서울은 두 번 등장하므로 먼저 도시별 합계를 만들고,
합계가 큰 순서로 정렬해 1위를 찾습니다. 코드를 읽기만 하지 말고 서울의 두 번째 금액을 `40`에서
`10`으로 바꾸거나 새로운 도시를 한 줄 추가한 뒤 실행해 보세요. 마지막 두 줄을 바꾸면 1위뿐 아니라
전체 순위도 출력할 수 있습니다.

https://eddmpython.com/codaro/run/?example=city-sales-ranking

이 미리보기 셀은 Codaro 입문 예제를 블로그 안에서 빠르게 실행하기 위한 좁은 표면입니다. 코드는
서버로 보내지지 않고 현재 브라우저의 Python 머신에서 실행됩니다. 처음 실행할 때는 런타임을 준비하느라
잠시 걸릴 수 있지만, 같은 페이지에서 다시 실행할 때는 준비된 머신을 이어 씁니다.

여기서는 코드 수정과 출력 확인까지만 제공합니다. Codaro 전체 레슨에서 제공하는 구조화된 강검증,
오류 피드백, 진도 저장, 다음 학습 이동까지 미리보기에서 제공한다고 말하면 기능 경계가 흐려집니다.
셀 아래의 전체 화면 링크를 열면 같은 방식으로 코드를 고치면서 정식 학습 흐름을 이어 갈 수 있습니다.

## 셀은 노트북 화면에 갇히지 않고 Python 파일로 남습니다

![여러 셀 경계를 품으면서도 하나의 온전한 Python 파일로 이어지는 긴 종이 문서](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/37/3761a5cf6e8376ae9f47157e8e1f5c140ca5cf49a6b14d853cd1a469e1db7178.webp "화면에서는 셀로 나뉘지만 저장된 문서는 평범한 Python 파일로 계속 실행된다")

Codaro의 기본 저장 형식은 `.ipynb` JSON이 아니라 Percent Format의 `.py` 파일입니다. 코드 셀과
마크다운 셀의 경계는 `# %% [code]`, `# %% [markdown]` 같은 주석으로 표시합니다. 셀 안의 Python은
함수로 감싸거나 특별한 `return` 규칙을 따르지 않고 모듈 수준의 평범한 코드로 남습니다.

이 선택은 화면보다 파일의 수명을 길게 만듭니다. Codaro에서 만든 문서를 `python file.py`로 실행할 수
있고, VS Code, Spyder, Jupytext도 같은 셀 경계를 인식합니다. Git에서는 거대한 노트북 JSON 대신 사람이
읽을 수 있는 Python 차이를 검토할 수 있습니다. 필요하면 `.ipynb`로 가져오거나 내보내는 호환 경로도
유지합니다.

중요한 점은 셀이 별도의 작은 프로그램 여러 개가 아니라는 사실입니다. 파일은 하나이고, Codaro가
그 안의 경계를 읽어 실행 단위와 설명 단위를 나눕니다. 나중에 이 문서를 자동화 태스크로 실행할 때도
학습용 코드를 다른 형식으로 다시 옮길 필요가 없습니다.

## 값을 바꾸면 필요한 셀만 다시 실행됩니다

![한 입력의 변화가 연결된 하위 장치에만 차례로 전달되는 정밀한 의존 경로](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/6e/6ebdaedaa799739561dd8edcb3ff82d014ca58dca6652f81b2437f63c5f28aec.webp "Codaro는 변수의 정의와 사용 관계를 읽어 영향을 받는 하위 셀만 다시 실행한다")

여러 셀이 같은 변수를 공유하면 실행 순서가 꼬이기 쉽습니다. 위쪽 셀의 값을 바꿨는데 아래쪽 출력은
예전 상태로 남거나, 어떤 셀부터 다시 실행해야 하는지 사람이 기억해야 합니다. Codaro는 각 셀의
Python AST를 읽어 어떤 변수를 정의하고 어떤 변수를 사용하는지 추론합니다.

예를 들어 첫 셀이 `sales`를 만들고, 둘째 셀이 `sales`로 `totals`를 계산하고, 셋째 셀이 `totals`로
순위를 만든다고 합시다. 첫 셀의 금액을 바꾸면 둘째와 셋째 셀이 차례로 다시 실행됩니다. 순위 출력의
표현만 바꾸면 매출 원본을 만드는 셀까지 거꾸로 실행하지 않습니다. 중간에 오류가 나면 그 아래로
잘못된 상태를 전파하지 않고 멈춥니다.

셀마다 네임스페이스도 분리하지만 사용자는 격리를 위한 보일러플레이트를 쓰지 않습니다. 필요한
변수만 실행 시점에 주입하고, 셀이 삭제되면 그 셀이 정의한 변수도 레지스트리에서 제거합니다. 사용자는
평범한 Python을 쓰고, 실행 순서와 오래된 상태를 줄이는 일은 엔진이 맡는 구조입니다.

## 실행 성공과 학습 성공을 같은 말로 쓰지 않습니다

![실행 결과가 여러 측정 장치를 통과해 재사용 가능한 증거로 남는 검증 작업대](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/30/3019906f6f342dee32f2258a63c3acbf539260fe75f811c5f2092deb546558b6.webp "오류가 없다는 사실과 목표를 달성했다는 증거를 분리해야 학습 결과를 믿을 수 있다")

코드가 예외 없이 끝났다는 사실만으로는 문제를 제대로 풀었다고 말할 수 없습니다. 빈 목록을 반환해도
오류는 없을 수 있고, 예시 입력 하나에만 맞춘 하드코딩도 실행 자체는 성공합니다. Codaro의 Web 지원
레슨은 실행 결과와 별도로 CheckSpec에 따른 강한 검증을 적용합니다.

검증은 레슨이 요구한 결과의 모양과 값을 확인하고, 실패하면 단순한 빨간 표시보다 무엇이 달랐는지와
다음 수정 지점을 보여 주는 쪽을 택합니다. 레슨의 실행 환경, 검사 결과, 진도는 같은 증거 계약으로
기록됩니다. Web에서 통과한 사실을 Local 전용 파일 작업까지 끝낸 것처럼 부풀리지 않고, 어떤 실행
환경에서 어떤 조건을 통과했는지를 남깁니다.

학습자에게도 이 구분이 중요합니다. 실행 버튼을 눌러 출력이 나왔으면 첫 단계는 끝났습니다. 그다음에는
입력을 바꿔도 조건을 만족하는지, 실패 메시지를 읽고 스스로 수정할 수 있는지, 비슷한 실제 작업에
옮길 수 있는지를 확인해야 합니다. Codaro의 목표는 한 번 돌아간 코드를 모으는 것이 아니라 다시
검증할 수 있는 작업을 남기는 것입니다.

## Web에서 배운 작업은 Local에서 파일과 자동화로 이어집니다

![브라우저 학습 작업대가 파일 보관함과 일정 장치와 자동화 기계로 확장되는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/ce/ce37d5158878f9fc652190955d9a41a353843856065191a3a7a79f0f9c7822d3.webp "Local은 Web을 버리고 다시 시작하는 제품이 아니라 같은 문서에 더 넓은 실행 권한을 더한다")

브라우저에서 목록과 딕셔너리를 익히는 동안에는 Web이 가장 빠른 환경입니다. 하지만 CSV 파일을
정리하고, 회사 내부 패키지를 설치하고, 매일 아침 같은 보고서를 만들려면 로컬 파일과 프로세스에
접근해야 합니다. 이 지점에서 [Codaro Local](https://github.com/eddmpython/codaro/releases/latest)로
확장합니다. 현재 Windows에서는 런처가 권장 경로이고, Python 개발 환경에서는 `uvx codaro`로 시작할
수 있습니다. 패키지 실행에는 Python 3.12 이상이 필요합니다.

Local은 별도의 학습 자료를 다시 여는 곳이 아닙니다. Web의 문서, 초안, 진도와 검증 증거를 이어받고,
그 위에 실제 파일 시스템, 필요한 Python 패키지, 터미널, 일정과 운영체제 권한을 더합니다. 레슨별
외부 패키지는 처음부터 전부 설치하지 않고 메타데이터에 선언한 뒤, 필요한 순간에 확인하고 빠진 것만
준비합니다.

검증된 `.py` 문서는 자동화 태스크로 키울 수 있습니다. 수동 실행에서 시작해 일정이나 Webhook으로
호출하고, 여러 태스크를 의존 관계로 묶을 수 있습니다. 실행 결과와 오류는 감사 로그와 결과물로
남습니다. 파일 쓰기, 네트워크, 외부 프로세스처럼 위험이 있는 태스크는 범위 확인 없이 자동 활성화하지
않고, 문서나 일정 또는 권한 범위가 바뀌면 다시 확인합니다. 즉 학습에서 자동화로 이어진다는 말은
안전 경계를 건너뛴다는 뜻이 아니라, 같은 코드를 더 강한 실행 환경에서 다시 검증한다는 뜻입니다.

## Codaro가 맞는 순간과 다른 도구가 나은 순간을 구분합니다

![가벼운 웹 학습과 넓은 로컬 작업이 서로 다른 방향으로 갈라지는 차분한 선택 지점](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/8e/8ec901a50dc312e29204cff5ab8bbbbd7fab616590dfcc9982298e2e216f9e9e.webp "도구 선택은 기능 수보다 지금 필요한 실행 범위와 남겨야 할 증거에서 시작한다")

설치 없이 Python 개념을 익히고, 예제를 직접 바꾸고, 결과와 검증을 같은 화면에서 보고 싶다면 Web에서
시작하는 것이 맞습니다. 학습한 코드를 사람이 읽을 수 있는 `.py`로 보존하고 실제 파일, 패키지,
터미널, 예약 실행까지 연결하려면 Local로 넓히면 됩니다. 내부 FastAPI나 Django 서비스에 노트북
표면을 마운트하려는 개발자라면 `createServerApp()` 통합 경로도 사용할 수 있습니다.

반대로 데이터 탐색만을 위한 익숙한 노트북 생태계와 수많은 확장이 우선이라면 Jupyter가 더 자연스러울
수 있습니다. 반응형 애플리케이션 UI 하나를 빠르게 배포하는 것이 목표라면 Streamlit 같은 도구가 더
직접적일 수 있습니다. Codaro의 강점은 모든 Python 도구를 대신하는 데 있지 않습니다. 학습 셀과 실제
파일, 검증된 코드와 반복 자동화 사이의 단절을 줄여야 할 때 가장 분명해집니다.

처음부터 자동화를 설계할 필요도 없습니다. [첫 Web 레슨](https://eddmpython.com/codaro/learn/lesson/30days/day01_%ED%97%AC%EB%A1%9C%EC%9B%94%EB%93%9C)을
열어 예제를 한 번 실행하고 값 하나를 바꿔 보세요. 그다음에는 결과가 달라진 이유를 설명하고 검증을
통과해 봅니다. 이 작은 반복이 편해졌을 때 파일이 필요한 과제로 넘어가면 됩니다. Codaro를 잘 쓰는
기준은 기능을 많이 여는 것이 아니라, 방금 배운 코드를 다음 작업에서도 다시 실행하고 증명할 수 있게
남기는 것입니다.
