업무자동화란 무엇인가를 알아보려고 Python부터 설치하면 순서가 거꾸로 됩니다. 먼저 컴퓨터에 어떤
파일을 주고, 어떤 규칙으로 바꾸며, 마지막에 어떤 숫자가 맞아야 하는지 사람이 설명할 수 있어야 합니다.

이 글에서는 부서별 지출내역 Excel 세 개를 결과 파일 하나로 만드는 업무를 끝까지 따라갑니다. 입력,
처리, 판단, 출력, 검증을 실제 5행 데이터에 연결하고, 자동화하면 안 되는 경우와 실패 복구까지 확인합니다.

## 업무자동화란 무엇인가: 다섯 칸입니다

### 사람이 하던 반복업무를 입력부터 검증까지 정해진 순서로 다시 실행합니다

![부서별 Excel 파일 세 개가 처리와 판단을 지나 결과 통합문서와 숫자 검증표로 이어지는 자동화 다섯 단계](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/ae/ae106aa16983b88a6e84d688759b9580f32a9a1978a9689857fc228314ce7470.png "왼쪽의 원본 파일부터 오른쪽의 검증 숫자까지 모두 정해야 자동화가 끝납니다")

업무자동화는 컴퓨터가 알아서 회사를 이해하는 일이 아닙니다. 사람이 반복하던 일을 입력, 처리, 판단,
출력, 검증으로 나누고, 컴퓨터가 같은 조건과 순서를 다시 실행하게 만드는 일입니다.

여기서 반복은 마우스를 여러 번 누른다는 뜻만이 아닙니다. 같은 종류의 파일을 받고, 같은 열을 고르고,
같은 기준으로 행을 나누며, 같은 모양의 결과를 만드는 일이 한 달에 한 번이라도 되풀이되면 반복업무입니다.

자동화의 핵심은 속도가 아니라 재현성입니다. 재현성은 같은 입력과 같은 규칙을 주었을 때 같은 결과가
다시 나오는 성질입니다. 담당자가 바뀌어도 결과 행 수와 금액 합계가 같다면 재현할 수 있는 업무입니다.

반대로 담당자의 경험과 추가 대화가 매번 필요한 결정은 그대로 자동화하기 어렵습니다. 예를 들어
`거래처가 화가 난 것 같으면 이번 달만 예외로 인정한다`는 규칙에는 측정할 값과 명확한 경계가 없습니다.
컴퓨터는 화가 난 정도를 회사 사정에 맞춰 스스로 정할 수 없습니다.

Python, Excel 매크로, RPA, AI는 자동화를 구현하는 서로 다른 도구입니다. 업무자동화라는 말은 특정
도구를 뜻하지 않습니다. 먼저 다섯 칸을 정하고 나서 파일 처리에는 Python, 화면 클릭에는 RPA처럼
업무에 맞는 도구를 고릅니다.

#### 설명 목록: 자동화 다섯 단계가 맡는 일

- **입력:** 컴퓨터가 받을 원본 파일, 값, 화면입니다.
- **처리:** 열 이름을 맞추거나 표를 합치는 변화입니다.
- **판단:** 어느 행을 정상과 확인필요로 나눌지 정한 조건입니다.
- **출력:** 사람이 열어 보거나 다른 프로그램에 넘길 결과입니다.
- **검증:** 누락, 중복, 금액 차이를 발견하는 숫자와 검사입니다.

다섯 칸 가운데 하나라도 비어 있으면 프로그램은 실행될 수 있어도 업무는 끝나지 않습니다. 특히 출력과
검증을 같은 것으로 생각하면 빈 Excel 파일이 만들어진 상황도 성공으로 착각할 수 있습니다.

## 완성된 결과부터 비교합니다

### 원본 세 개와 결과 파일 하나를 먼저 보면 자동화할 이유가 바로 보입니다

![서로 다른 부서의 원본 Excel 세 개와 통합내역 및 부서별요약과 확인필요 시트를 가진 결과 파일 하나의 비교](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/a4/a477f773e96da1023dd6c41ea4ef19dbb34199731d8e9d46ae7c79fd672e523f.png "자동화 전에는 세 파일을 따로 열지만 자동화 후에는 한 결과 파일의 시트만 확인합니다")

자동화를 설계할 때는 완성 화면을 먼저 그리는 편이 쉽습니다. 왼쪽에는 원본 Excel 세 개가 있고,
오른쪽에는 `expense_result.xlsx` 하나가 있습니다. 결과 파일에는 통합내역, 부서별요약, 확인필요,
검증결과 시트가 들어갑니다.

결과부터 정하면 `Excel을 자동화한다`처럼 넓은 목표를 피할 수 있습니다. 원본 세 개를 읽어 시트 네
개가 있는 파일 하나를 만든다고 적으면 프로그램이 어디에서 끝나야 하는지 보입니다.

예제 입력은 일부러 다섯 행만 사용합니다. 영업팀 교통비 12만원, 영업팀 식비 3만원, 관리팀 비품비
9만원, 개발팀 서버비 25만원, 부서가 비어 있는 교육비 5만원입니다. 전체 금액은 54만원입니다.

판단 규칙은 두 개입니다. 금액이 10만원 이상이거나 부서가 비어 있으면 `확인필요`로 표시합니다.
따라서 교통비, 서버비, 교육비 세 행이 확인필요로 가고 나머지 두 행은 정상으로 남아야 합니다.

이 작은 예에는 정상값, 금액 경계, 누락값이 함께 있습니다. 실제 회사 파일을 넣기 전에 다섯 행으로
결과를 손으로 계산하면 프로그램이 내놓아야 할 정답을 먼저 확보할 수 있습니다.

#### 입력 예시: 결과를 손으로 계산할 수 있는 다섯 행

| 원본 파일 | 부서 | 항목 | 금액 | 예상 분류 |
|---|---|---|---:|---|
| `영업팀.xlsx` | 영업팀 | 교통비 | 120000 | 확인필요 |
| `영업팀.xlsx` | 영업팀 | 식비 | 30000 | 정상 |
| `관리팀.xlsx` | 관리팀 | 비품비 | 90000 | 정상 |
| `개발팀.xlsx` | 개발팀 | 서버비 | 250000 | 확인필요 |
| `개발팀.xlsx` | 비어 있음 | 교육비 | 50000 | 확인필요 |

결과 파일은 다섯 행과 54만원을 그대로 보존해야 합니다. 이 정답을 먼저 적어 두면 뒤에서 파일이
생겼다는 사실이 아니라 내용이 맞다는 사실을 검사할 수 있습니다.

## 입력은 컴퓨터가 받을 자료입니다

### 파일 이름과 시트 및 열을 적으면 컴퓨터가 어디에서 무엇을 읽을지 정해집니다

![input 폴더 안의 Excel 세 파일과 각 파일의 일자 부서 항목 금액 비고 다섯 열이 한 입력 명세 카드로 연결된 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/81/810a0a376579b205d73f87a350ee8ad7eb56ed0b2afe2f860e57a5062725829d.png "입력은 Excel이라는 말이 아니라 폴더와 파일 수와 열 이름까지 적어야 실행할 수 있습니다")

입력은 업무를 시작할 때 컴퓨터가 받는 자료입니다. `Excel 파일을 읽는다`만 적으면 어느 폴더의 몇
개 파일인지 알 수 없습니다. `input` 폴더의 `.xlsx` 파일 세 개처럼 위치와 형식을 함께 적어야 합니다.

입력 설명에는 파일 안쪽 모양도 들어갑니다. 이번 예제의 시트 이름은 `지출내역`이고, 열은 `일자`,
`부서`, `항목`, `금액`, `비고` 다섯 개라고 정합니다. 첫 행이 제목인지도 미리 확인해야 합니다.

같아 보이는 Excel 파일도 실제 값은 다를 수 있습니다. 금액 열에 숫자 `120000`이 들어올 수도 있고,
문자 `120,000원`이 들어올 수도 있습니다. 빈 셀, 합계 행, 숨긴 행이 섞이면 읽은 행 수가 달라집니다.

이런 조건을 입력 계약이라고 부릅니다. 계약은 어려운 법률 문서가 아니라 프로그램이 받기로 한 파일의
약속입니다. 약속과 다른 파일은 조용히 계산하지 않고 어떤 값이 다른지 알려 주며 멈춰야 합니다.

파일 수까지 무조건 세 개로 고정할 필요는 없습니다. 매달 부서 수가 달라진다면 `input 폴더의 모든
.xlsx 파일`이라고 적는 편이 맞습니다. 다만 임시 파일이나 지난달 결과가 같은 폴더에 들어올 가능성을
함께 막아야 합니다.

#### 확인 목록: 실행 전에 고정할 입력 계약

- 파일이 들어오는 폴더와 포함할 파일 이름 규칙을 적습니다.
- 읽을 확장자, 시트 이름, 첫 행의 위치를 적습니다.
- 반드시 있어야 하는 열과 없어도 되는 열을 나눕니다.
- 숫자, 날짜, 빈값이 어떤 모양으로 들어오는지 적습니다.
- 계약과 다른 파일은 건너뛸지 즉시 멈출지 정합니다.

입력 계약이 구체적이면 오류 메시지도 구체적으로 만들 수 있습니다. `처리 실패`보다
`관리팀.xlsx의 금액 열에서 120,000원을 숫자로 바꾸지 못했습니다`가 고칠 위치를 훨씬 빨리 알려 줍니다.

## 처리와 판단은 사람이 정한 규칙입니다

### 파일을 합치는 순서와 확인이 필요한 행을 나누는 조건을 따로 적습니다

![Excel 행들이 열 정리와 표 합치기 처리 단계를 지난 뒤 정상과 확인필요 두 갈래로 나뉘는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/83/83566263ff5ad840db5f704af3c03b83fc3a8e0c17c964c5a2ecae60b496b777.png "표를 바꾸는 처리와 조건에 따라 나누는 판단을 분리하면 수정할 규칙을 찾기 쉽습니다")

처리는 자료의 모양을 바꾸는 순서입니다. 파일을 하나씩 읽고, 필요한 열만 남기고, 금액을 숫자로
바꾸고, 원본 파일명을 새 열에 넣은 뒤 세 표를 위아래로 합치는 동작이 처리에 해당합니다.

판단은 값에 따라 결과를 나누는 규칙입니다. 금액이 `100000` 이상이면 확인필요로 표시하고, 부서가
비어 있어도 확인필요로 보냅니다. 처리와 판단을 나누면 열 이름 변경과 금액 기준 변경을 다른 일로 볼
수 있습니다.

경계값은 결과가 바뀌는 바로 그 값입니다. `100000 이상`이라면 99999원은 정상이고 100000원은
확인필요입니다. `100000 초과`로 쓰면 100000원은 정상으로 남습니다. 한 단어 차이가 실제 행의 분류를
바꾸므로 예제에는 경계 바로 아래, 경계와 같은 값, 경계 바로 위 값을 넣어야 합니다.

AI에게 `큰 금액을 찾아 줘`라고 말하면 큰 금액의 기준을 AI가 추측하게 됩니다. `금액이 100000 이상인
행을 확인필요로 표시해 줘`라고 말하면 입력값과 결과를 사람이 계산할 수 있습니다. AI는 규칙을 실행할
수 있지만 회사가 원하는 기준을 책임지고 결정하지는 못합니다.

#### 예시 코드: 처리 순서와 판단 조건을 분리한 의사코드

아래 내용은 실행용 Python이 아니라 사람이 규칙을 검토하기 위한 의사코드입니다. 의사코드는 정확한
문법보다 순서를 읽기 쉽게 적은 설명입니다. 입력 파일을 합친 뒤 두 판단 조건을 적용한다는 점을
확인하면 됩니다.

```text
각 Excel 파일을 읽는다
금액을 숫자로 바꾼다
출처파일 열을 추가한다
모든 행을 하나로 합친다

금액이 100000 이상이면 확인필요로 표시한다
부서가 비어 있으면 확인필요로 표시한다
```

이 의사코드의 출력은 정상 두 행과 확인필요 세 행입니다. 실제 Python 코드를 만들 때도 처리 함수와
판단 함수를 나누면 어느 규칙이 결과를 바꿨는지 찾기 쉽습니다.

판단 순서가 결과를 바꾸는 경우도 있습니다. 취소 거래를 먼저 제외할지, 큰 금액으로 먼저 표시할지에
따라 같은 행이 다른 결과로 갈 수 있습니다. 조건이 겹친다면 우선순위와 최종 분류를 표로 적어야 합니다.

## 출력은 파일이고 검증은 숫자입니다

### 결과 파일이 생긴 뒤 입력과 출력의 건수와 금액이 같은지 확인합니다

![결과 Excel 파일 옆에서 입력과 출력의 파일 수 행 수 금액 합계를 서로 맞춰 보는 검증 카드](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/75/7588515483d961e23b1e6e595a4e5a6e92fedbd75cd056fd8078b693e5590819.png "파일 생성은 실행 성공이고 건수와 금액 차이가 0인 것은 결과 검증입니다")

출력은 자동화가 만든 실제 파일입니다. 파일 이름과 시트 구성을 미리 적어 두면 실행 뒤 무엇을 열어야
할지 알 수 있습니다. 하지만 파일이 생겼다는 사실만으로 내용이 맞다고 말할 수는 없습니다.

검증은 예상한 값과 실제 결과를 비교하는 일입니다. 예제에서는 입력 3개, 전체 5행, 금액 54만원,
확인필요 3행이 정답입니다. 결과 파일의 숫자가 하나라도 다르면 어느 단계에서 값이 달라졌는지 찾아야
합니다.

행 수는 같지만 금액이 다를 수도 있습니다. 금액 문자열 변환에 실패한 행을 0원으로 바꾸면 5행은
유지되지만 합계가 줄어듭니다. 그래서 행 수와 금액 합계를 함께 확인해야 합니다.

같은 입력으로 두 번 실행하는 검사도 필요합니다. 두 번째 실행에서 기존 결과 뒤에 행을 다시 붙이면
5행이 10행이 됩니다. 같은 입력으로 여러 번 실행해도 같은 결과가 나오는 성질을 멱등성이라고 부릅니다.

원본 보호도 검증에 포함됩니다. 프로그램이 원본 파일에 새 열을 쓰거나 저장 시각을 바꾸면 결과 숫자가
맞더라도 안전한 자동화가 아닙니다. 입력 파일은 읽기만 하고 결과는 별도 `output` 폴더에 저장하는 편이
복구하기 쉽습니다.

#### 확인 목록: 다섯 행 예제의 완료 증거

- 입력 파일 수와 처리 파일 수는 모두 `3`입니다.
- 입력 행 수와 통합내역 행 수는 모두 `5`입니다.
- 입력 금액과 결과 금액은 모두 `540000`원입니다.
- 확인필요 행 수는 `3`입니다.
- 같은 입력으로 다시 실행해도 전체 행 수는 `5`입니다.
- 원본 파일의 내용과 수정 시각은 바뀌지 않습니다.

검증이 실패하면 결과 파일을 손으로 고쳐서 넘기지 않습니다. 첫 입력 다섯 행으로 돌아가 어느 단계에서
숫자가 처음 달라졌는지 확인해야 같은 문제가 다음 달에 반복되지 않습니다.

### 오늘 반복한 업무의 실제 파일과 규칙 및 확인 숫자를 한 줄씩 채웁니다

![비어 있는 입력 처리 판단 출력 검증 다섯 카드가 지출내역 업무의 파일명과 조건 및 숫자로 채워지는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/57/57c42bdb79c83cc315f2d0ab0376b48d87d47bac1709134f1b68defe89ccc291.png "도구 이름보다 오늘 사용한 파일과 조건을 적으면 첫 자동화 설명이 완성됩니다")

지금 자동화할 업무 하나를 고릅니다. Python이나 AI 이름은 아직 적지 않습니다. 오늘 받은 파일,
직접 반복한 순서, 사람에게 물어본 조건, 마지막으로 만든 파일, 맞는지 확인한 숫자를 다섯 칸에 적습니다.

좋은 첫 대상은 규칙이 안정되고 결과를 숫자로 확인할 수 있는 일입니다. 매주 같은 열을 가진 파일을
합치거나 정해진 이름으로 보고서를 저장하는 일은 첫 자동화에 적합합니다.

반대로 입력 형식과 판단 기준이 매번 바뀌고, 잘못된 결과가 바로 고객이나 회계에 영향을 주는 일은
처음부터 전부 자동화하지 않는 편이 안전합니다. 이런 일은 자료 수집과 초안 생성만 자동화하고 최종
승인은 사람이 맡을 수 있습니다.

시간이 오래 걸린다는 이유만으로도 충분하지 않습니다. 한 해에 한 번 하는 20분짜리 일보다 매일 5분씩
반복하는 일이 자동화 효과가 클 수 있습니다. 빈도, 규칙의 안정성, 오류 위험, 검증 가능성을 함께 봅니다.

다섯 칸을 적은 뒤에는 다른 사람이 그 문장만 읽고 같은 결과를 만들 수 있는지 확인합니다. `적당히`,
`필요하면`, `큰 금액` 같은 말이 남았다면 아직 컴퓨터가 실행할 규칙이 아닙니다.

#### 예시 코드: 지출내역 업무를 실행 가능한 다섯 줄로 표현하기

아래 다섯 줄은 프로그램 코드가 아니라 자동화 기획의 최소 입력입니다. 각 줄에는 실제 파일, 바꿀
동작, 경계값, 결과 파일, 검증 숫자가 들어 있습니다. 다른 사람이 읽어도 추가 질문 없이 예제 결과를
계산할 수 있어야 합니다.

```text
입력: input 폴더의 부서별 Excel 3개, 일자·부서·항목·금액·비고 열
처리: 파일을 읽고 금액을 숫자로 바꾼 뒤 출처파일 열을 추가해 하나로 합침
판단: 100000원 이상 또는 부서 누락이면 확인필요
출력: expense_result.xlsx의 통합내역·부서별요약·확인필요·검증결과 시트
검증: 5행, 540000원, 확인필요 3행, 재실행 뒤에도 같은 값, 원본 변경 없음
```

이 다섯 줄을 손으로 검토할 수 있으면 어떤 도구를 쓰더라도 같은 목표를 전달할 수 있습니다. 입력이나
검증이 비어 있다면 Python을 설치하기 전에 실제 파일 이름과 마지막으로 맞춰 본 숫자부터 찾아야 합니다.

업무자동화는 사람을 빼는 일이 아니라 반복 가능한 부분과 사람이 책임질 판단을 구분하는 일입니다.
다섯 칸이 채워진 뒤에야 Python이나 AI가 맡을 범위와 사람이 마지막으로 확인할 범위가 선명해집니다.
