부서별 지출내역 Excel 세 개를 프로그램으로 합쳤습니다. 결과 파일은 만들어졌고, 행 수도 5행 그대로였습니다.

합계만 390,000원에서 300,000원이 되어 있었습니다.

사라진 90,000원은 관리팀 파일의 셀 하나였습니다. 금액 열에 `90,000원`이라고 적혀 있었고, 그것은 숫자가 아니라 글자였습니다. 프로그램은 숫자로 바꾸지 못한 값을 0으로 채웠습니다. 오류 메시지는 나오지 않았습니다. 결과 파일을 열어 봐도 표는 멀쩡했습니다.

업무자동화란 무엇인가를 물으면 대개 반복작업을 컴퓨터가 대신하는 것이라고 답합니다. 이 답은 방금 사라진 90,000원을 설명하지 못합니다. 반복작업은 정확히 대신 실행됐고, 결과만 틀렸기 때문입니다.

아래 명령과 출력은 전부 실제로 돌린 것입니다. 입력은 다섯 행이고, 그중 세 행은 일부러 프로그램을 틀리게 만드는 값입니다.

## 5행이 맞는데 90,000원이 없습니다

![결과 Excel 파일 옆에서 입력과 출력의 파일 수 행 수 금액 합계를 서로 맞춰 보는 검증 카드](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/75/7588515483d961e23b1e6e595a4e5a6e92fedbd75cd056fd8078b693e5590819.png "파일이 생긴 것은 실행 성공이고, 건수와 금액이 함께 맞는 것이 결과 검증입니다")

원본은 세 파일입니다. 영업팀 교통비 120,000원과 식비 30,000원, 관리팀 비품비 90,000원, 개발팀 서버비 100,000원, 부서 칸이 빈 교육비 50,000원. 손으로 더하면 390,000원입니다.

병합 프로그램은 스무 줄이 안 됩니다. `input` 폴더의 `.xlsx` 파일을 차례로 읽고, 어느 파일에서 왔는지 열을 하나 붙이고, 금액을 숫자로 바꾼 뒤 위아래로 이어 붙입니다.

#### 실행 명령: 세 파일을 하나로 합치기

```python
from pathlib import Path

import pandas as pd

tables = []
for path in sorted(Path("input").glob("*.xlsx")):
    table = pd.read_excel(path, sheet_name="지출내역")
    table["출처파일"] = path.name
    tables.append(table)

merged = pd.concat(tables, ignore_index=True)
merged["금액"] = pd.to_numeric(merged["금액"], errors="coerce").fillna(0)

Path("output").mkdir(exist_ok=True)
merged.to_excel("output/expense_result.xlsx", sheet_name="통합내역", index=False)

print(f"파일 {len(tables)}개를 읽어 {len(merged)}행을 저장했습니다")
```

`to_numeric`의 `errors="coerce"`는 숫자로 바꾸지 못한 값을 비어 있는 값으로 만듭니다. 바로 뒤의 `fillna(0)`이 그 빈 값을 0으로 채웁니다. 두 줄 다 오류를 내지 않고 조용히 통과합니다.

#### 예상 결과: 성공처럼 보이는 출력

```text
파일 3개를 읽어 5행을 저장했습니다
```

3과 5. 둘 다 맞습니다.

여기서 멈추면 자동화가 끝난 것처럼 보입니다. 행 수는 몇 개를 읽었는지만 알려 주고 각 행이 무엇을 담고 있는지는 알려 주지 않기 때문입니다. 관리팀의 90,000원이 0으로 바뀌어도 행은 그대로 한 줄이고, 5행이라는 답도 그대로 5행입니다.

그래서 검사를 하나 더 붙입니다. 원본 파일에서 금액을 직접 더한 값과 결과 파일의 합계를 나란히 찍어 보는 것입니다.

#### 예시 코드: 입력과 출력의 숫자 맞춰 보기

```python
expected_rows = 0
expected_total = 0
for path in sorted(Path("input").glob("*.xlsx")):
    source = pd.read_excel(path, sheet_name="지출내역")
    expected_rows += len(source)
    for raw in source["금액"]:
        expected_total += int(str(raw).replace(",", "").replace("원", ""))

result = pd.read_excel("output/expense_result.xlsx", sheet_name="통합내역")

print(f"행 수   기대 {expected_rows} / 결과 {len(result)}")
print(f"금액 합계 기대 {expected_total} / 결과 {int(result['금액'].sum())}")
```

기대값은 프로그램이 아니라 원본에서 만듭니다. 결과 파일에서 뽑은 숫자끼리 비교하면 같은 실수를 두 번 반복할 뿐이라 아무것도 잡지 못합니다. 그래서 `replace`로 쉼표와 원 글자를 직접 떼어 내고 사람이 읽은 대로 더합니다. 병합 코드가 쓰는 `to_numeric`과 일부러 다른 방법을 씁니다.

#### 예상 결과: 90,000원이 사라진 자리

```text
행 수   기대 5 / 결과 5
금액 합계 기대 390000 / 결과 300000

금액이 0으로 바뀐 행:
    출처파일  부서  항목  금액
관리팀.xlsx 관리팀 비품비   0
```

행 수는 통과하고 금액에서 걸립니다. 90,000원 차이가 어느 파일의 어느 행에서 났는지까지 한 번에 나옵니다. 검사 한 줄이 늘었을 뿐인데 결과 파일을 믿을 수 있는지가 달라집니다. 이 출력을 보기 전과 후에 결과 파일은 한 글자도 바뀌지 않았습니다. 바뀐 것은 그 파일을 그대로 넘겨도 되는지에 대한 내 판단입니다.

## 같은 열인데 값의 모양이 다릅니다

![input 폴더 안의 Excel 세 파일과 각 파일의 일자 부서 항목 금액 비고 다섯 열이 한 입력 명세 카드로 연결된 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/81/810a0a376579b205d73f87a350ee8ad7eb56ed0b2afe2f860e57a5062725829d.png "폴더와 파일 수만이 아니라 열마다 어떤 모양의 값이 들어오는지까지 적어야 실행할 수 있습니다")

관리팀 파일을 열어 보면 금액 칸에 `90,000원`이 들어 있습니다. 사람 눈에는 9만원입니다. Excel에게는 글자 다섯 개짜리 문자열입니다.

같은 부서가 매달 같은 양식을 쓴다고 해도 이런 값은 섞입니다. 담당자가 바뀌거나, 다른 시스템에서 내려받거나, 셀 서식을 손으로 고치면 그때부터 모양이 달라집니다.

그래서 입력을 적을 때 `Excel 파일을 읽는다`만으로는 부족합니다. 어느 폴더의 어떤 확장자인지, 시트 이름이 무엇인지, 첫 행이 제목인지, 그리고 각 열에 어떤 모양의 값이 들어올 수 있는지까지 적어야 프로그램이 무엇을 받을지 정해집니다. 이 약속을 입력 계약이라고 부릅니다. 어려운 문서가 아니라 프로그램이 받기로 한 파일의 조건 목록입니다.

#### 설명 목록: 이번 예제의 입력 계약

- 폴더는 `input`이고 확장자는 `.xlsx`입니다.
- 시트 이름은 `지출내역`이고 첫 행은 제목입니다.
- 필수 열은 `일자`, `부서`, `항목`, `금액`이고 `비고`는 없어도 됩니다.
- `금액`은 숫자여야 하며 `90,000원` 같은 문자열은 계약 위반입니다.
- `부서`는 비어 있을 수 있고, 비면 확인필요로 보냅니다.

계약을 적어 두면 오류 메시지도 구체적으로 만들 수 있습니다. `처리 실패`보다 `관리팀.xlsx의 금액 열에서 90,000원을 숫자로 바꾸지 못했습니다`가 고칠 자리를 훨씬 빨리 알려 줍니다.

여기까지가 값이 들어오는 모양의 문제입니다. 다음은 값이 다 맞게 들어왔을 때도 결과가 갈리는 자리입니다.

## 100,000원은 확인필요입니까?

![Excel 행들이 열 정리와 표 합치기 처리 단계를 지난 뒤 정상과 확인필요 두 갈래로 나뉘는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/83/83566263ff5ad840db5f704af3c03b83fc3a8e0c17c964c5a2ecae60b496b777.png "같은 표와 같은 값이라도 경계를 어느 쪽으로 정하느냐에 따라 갈라지는 행이 달라집니다")

`10만원 넘는 건은 확인필요로 빼 주세요`라는 요청을 받았다고 하겠습니다. 개발팀 서버비가 정확히 100,000원입니다. 이 행은 어느 쪽입니까?

넘는다는 말은 한국어에서 두 가지로 읽힙니다. 100,000원을 포함하면 이상이고, 포함하지 않으면 초과입니다. 사람끼리는 대충 넘어가지만 프로그램은 둘 중 하나를 골라야 합니다.

같은 데이터에 두 기준을 각각 적용해 봤습니다.

#### 실행 명령: 경계를 이상과 초과로 각각 돌리기

```text
> python classify.py 이상
기준: 100000 이상
 부서  항목     금액   분류

관리팀 비품비      0   정상

> python classify.py 초과
기준: 100000 초과
 부서  항목     금액   분류
개발팀 서버비 100000   정상
NaN 교육비  50000 확인필요
관리팀 비품비      0   정상
영업팀 교통비 120000 확인필요
영업팀  식비  30000   정상

```

확인필요가 3행에서 2행으로 바뀌었습니다. 데이터는 한 글자도 건드리지 않았고 바뀐 것은 부등호 하나입니다.

이래서 예제 데이터에는 경계와 정확히 같은 값이 들어 있어야 합니다. 서버비 100,000원이 없었다면 이상과 초과 중 무엇을 골라도 결과가 같았을 것이고, 잘못된 선택이 몇 달 뒤 다른 데이터에서 처음 드러났을 것입니다.

AI에게 맡길 때도 같습니다. `큰 금액을 찾아 줘`라고 말하면 큰 금액의 기준을 AI가 정하게 됩니다. `금액이 100000 이상인 행을 확인필요로 표시해 줘`라고 말하면 결과를 사람이 손으로 검산할 수 있습니다. AI는 규칙을 실행하지만 회사가 무엇을 확인하고 싶은지는 대신 정하지 못합니다.

`NaN`으로 찍힌 교육비 행은 부서 칸이 비어 있어서 금액과 무관하게 확인필요로 갔습니다. 조건이 둘 이상이면 어느 것이 먼저인지, 겹치면 어느 쪽으로 보낼지도 함께 적어야 합니다.

## 두 번 돌리면 어떻게 됩니까?

한 번 맞은 결과가 다음 달에도 맞으리라는 보장은 없습니다. 같은 입력으로 다시 실행했을 때 같은 결과가 나오는 성질을 멱등성이라고 부릅니다.

이번 프로그램은 결과 파일을 매번 새로 씁니다. 그래서 두 번 돌려도 5행 그대로입니다. 만약 기존 파일 뒤에 이어 붙이는 방식이었다면 두 번째 실행에서 10행이 됐을 것입니다.

더 자주 일어나는 사고는 따로 있습니다. 결과 파일을 `input` 폴더에 그대로 두고 다음 달에 다시 돌리는 경우입니다. 실제로 넣고 실행해 봤습니다.

#### 실패 예시: 결과 파일이 input 폴더에 섞였을 때

```text
ValueError: Worksheet named '지출내역' not found
```

프로그램이 결과 파일까지 입력으로 읽으려 했고, 그 파일의 시트 이름은 `통합내역`이라 멈췄습니다. 이 경우는 오히려 다행입니다. 조용히 틀린 숫자를 내놓는 대신 실행이 끊겼기 때문입니다.

복구는 간단합니다. 결과를 입력과 다른 폴더에 쓰고, 읽을 파일 이름 규칙을 좁히면 됩니다. 원본은 읽기만 하고 절대 덮어쓰지 않는 편이 되돌리기 쉽습니다.

## 다시, 업무자동화란 무엇인가

여기까지 실제로 확인한 것은 네 가지입니다. 파일이 생겼다는 사실은 결과가 맞다는 뜻이 아니고, 금액 열의 문자열은 오류 없이 0이 되며, 부등호 한 글자가 확인필요 행 수를 바꾸고, 입력 폴더가 오염되면 다음 실행이 멈춥니다.

업무자동화는 컴퓨터가 회사를 이해하는 일이 아닙니다. 사람이 반복하던 일을 컴퓨터가 다시 실행할 수 있을 만큼 구체적으로 적고, 그 결과가 맞는지 사람이 숫자로 확인하는 일입니다. 앞의 네 가지는 전부 그 구체적으로 적는 자리에서 갈렸습니다.

그 자리를 다섯 칸으로 적으면 다른 사람에게 그대로 넘길 수 있습니다.

#### 예시 코드: 이 업무를 다섯 줄로 넘기기

```text
입력: input 폴더의 .xlsx 3개, 시트 지출내역, 금액은 숫자, 부서는 빈값 허용
처리: 파일별로 읽어 출처파일 열을 붙이고 금액을 숫자로 바꾼 뒤 하나로 합침
```
