`AI 코드 분석`을 요청했는데 곧바로 파일이 바뀌면 설명이 맞는지 확인하기 전에 수정부터 검토해야 합니다.
첫 요청에서는 파일 변경을 0개로 고정하고 실행 진입점과 데이터 흐름 및 위험 파일만 찾게 하는 편이 좋습니다.

읽기 전용 분석은 AI를 덜 활용하는 단계가 아닙니다. 잘못된 파일을 고치는 시간을 줄이고 다음 작업지시서에
실제 함수와 테스트 및 위험을 넣기 위한 조사 단계입니다.

## 첫 요청에서 수정 금지 범위를 적습니다

### 파일 생성과 편집 및 설치와 외부 변경을 막고 읽은 경로만 보고하게 합니다

![AI 코드 분석 영역과 파일 수정 금지 영역이 분리되고 읽기 전용 명령만 통과하는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/71/712c72f63a61efa6c2305c1e8571f7a12aa6e80aee01633c45bb76c7a281717e.png "파일 읽기와 검색은 분석 영역으로 들어가고 편집과 설치 및 배포는 금지 경계에서 멈춥니다")

`분석해 줘`만 적으면 AI는 문제를 발견한 뒤 바로 고치려 할 수 있습니다. 이번 단계의 목적은 수정이
아니라고 첫 문장에 적고 파일 생성, 편집, 삭제, 설치, commit, push, 배포를 금지합니다.

실제 파일을 읽을 권한은 열어 둡니다. AI가 추측하지 않게 사용한 경로와 명령 및 확인하지 못한 항목을
결과에 포함하도록 요청합니다.

#### 예시

```text
이 저장소를 읽기 전용으로 분석해 줘.

이번 단계에서는 파일을 만들거나 고치거나 삭제하지 마.
의존성 설치, commit, push, 배포, 외부 서비스 변경도 하지 마.
저장소 규칙을 먼저 읽고 검색과 파일 읽기 및 안전한 상태 확인만 수행해.

결과에는 읽은 파일, 사용한 명령, 확인한 사실, 추정, 미확인 항목을 구분해 적어 줘.
마지막에 git status --short로 변경 파일이 0개인지 확인해 줘.
```

## 진입점부터 출력까지 한 줄로 연결합니다

### 실행 명령과 시작 함수 및 입력과 변환과 저장 파일을 실제 경로로 설명하게 합니다

![터미널 실행 명령에서 Python 진입 함수와 Excel 입력 및 변환 함수와 결과 파일로 이어지는 코드 흐름](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/c9/c971af6073bc2ae4c6df02e812f23090eb417a8287a8943c77d82a3250d650ec.png "실행 명령이 실제 파일의 함수와 입력 표 및 변환 단계를 거쳐 결과 Excel로 이어집니다")

프로젝트 설명은 `데이터를 처리합니다`처럼 넓게 쓰면 검증하기 어렵습니다. 실행 명령이 어느 파일을
열고 어떤 함수에서 시작해 어느 입력을 읽으며 어떤 결과를 저장하는지 한 줄 흐름으로 요청합니다.

각 단계에는 실제 경로와 함수 이름을 붙입니다. 가능하면 줄 번호도 적게 하면 사람이 파일을 열어 설명과
코드를 빠르게 대조할 수 있습니다.

#### 예시

```text
아래 다섯 항목을 실제 경로와 함수 이름으로 설명해 줘.

1. 실행: 사용자가 복사할 명령과 실행 위치
2. 진입점: 처음 실행되는 Python 파일과 함수
3. 입력: Excel 파일을 찾고 읽는 코드
4. 변환: 열 표준화, 오류 분리, 부서 집계 함수
5. 출력: 결과 파일 경로와 네 시트를 저장하는 코드

형식은 `명령 -> 파일:함수 -> 입력 -> 변환 -> 출력` 한 줄 요약과 단계별 근거로 작성해 줘.
```

## 검증과 위험 파일을 따로 찾습니다

### 테스트와 원본 및 비밀값과 생성 결과를 네 종류로 나누어 수정 위험을 표시합니다

![프로젝트 파일 지도가 테스트와 원본 입력 및 비밀 설정과 생성 결과 네 위험 구역으로 나뉜 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/6e/6e9b1729610da9429db505a7542eb91b4e4adb6dffd6f1ae00df6f11c7dd2b86.png "일반 코드에서 네 위험 구역이 분리되고 각 구역에 다른 보호 표시가 붙습니다")

코드 흐름만 알면 어디를 고칠지는 알 수 있지만 어디를 건드리면 안 되는지는 알기 어렵습니다. 테스트,
원본 입력, 비밀값, 생성 결과를 별도 목록으로 찾게 합니다.

위험 이유도 함께 적습니다. 예를 들어 원본 Excel은 덮어쓰면 복구가 어렵고 `.env`는 내용 자체를 출력하면
안 됩니다. `output/`은 생성 폴더라 소스 입력 검색에서 제외해야 할 수 있습니다.

#### 설명 목록

- 테스트: 변경 전후 같은 명령으로 실행할 파일과 기대값을 찾습니다.
- 원본 입력: 읽기만 해야 하는 Excel 폴더와 샘플 및 실제 자료를 구분합니다.
- 비밀값: `.env`와 키 파일은 경로와 변수 이름만 확인하고 값을 읽거나 출력하지 않습니다.
- 생성 결과: `output/`, 보고서, 캐시를 입력과 소스 코드에서 분리합니다.
- 배포 설정: 자동 실행이나 외부 서비스 변경으로 이어지는 파일을 표시합니다.

## AI 설명을 실제 파일과 대조합니다

### 경로와 함수 및 명령을 직접 확인하고 마지막 변경 파일이 0개인지 검사합니다

![AI 분석표의 경로와 함수 및 테스트 명령이 실제 저장소 파일과 하나씩 맞고 Git 변경 파일은 0개인 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/90/90c9bb9977f83bdae5d68d0a7f2748b135efe1d202cf5154a2de2da9e1b62b34.png "분석 결과의 근거가 실제 파일과 연결되고 빈 Git 상태 결과가 수정 0개를 증명합니다")

AI 답변이 자세하다고 정확한 것은 아닙니다. 보고서에 적힌 경로가 실제로 존재하는지, 함수 이름과 명령이
설정 파일에 있는지, 테스트가 현재 환경에서 실행되는지 대조합니다.

읽기 전용 단계의 마지막 완료 조건은 `git status --short`가 시작 전과 같다는 것입니다. 시작할 때 깨끗한
작업 트리였다면 출력이 비어 있어야 합니다.

#### 확인 목록

- 실행 명령과 실행 위치가 저장소 설정에 실제로 존재합니다.
- 진입점과 핵심 함수의 경로 및 이름이 실제 코드와 같습니다.
- 입력과 출력 폴더가 뒤바뀌지 않았습니다.
- 테스트 명령과 기대 결과가 기준선 기록과 같습니다.
- 원본과 비밀값 및 생성 결과의 위험 이유가 구체적입니다.
- 사실과 추정 및 미확인 항목이 구분돼 있습니다.
- `git status --short` 결과가 시작 전과 같고 새 변경은 0개입니다.
