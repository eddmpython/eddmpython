Python 기초문법 배우는 방법을 찾으면 변수부터 함수까지 정의가 차례로 나옵니다. 정의만 외우면
대괄호와 중괄호를 구별할 수는 있어도, 실제 코드에서 무엇을 어디에 써야 하는지는 알기 어렵습니다.
문법은 시험 항목이 아니라 입력값을 원하는 결과로 바꾸는 작은 도구이기 때문입니다.

이 글에서는 부서별 지출 세 건을 검토하는 프로그램 하나를 만듭니다. 각 절의 예시 코드를 그대로
실행한 뒤 금액이나 기준값을 바꿉니다. 마지막에는 합계 `250,000원`과 `확인필요 1건`이 나오는지
확인하고, 없는 열 이름과 문자로 들어온 금액 때문에 실패할 때 어디를 고칠지도 찾습니다.

## Python 기초문법은 한 프로그램에서 연결됩니다

### 여섯 문법이 입력을 저장하고 묶고 판단해 결과로 바꾸는 순서를 먼저 봅니다

![지출내역 입력이 변수와 리스트와 딕셔너리 및 조건과 반복과 함수를 지나 결과표로 바뀌는 전체 코드 지도](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/34/34c96f6b38214b253f61acaa2ef46cb2ee75249bf16873ffc13975249b85ebcd.png "여섯 문법은 따로 놓인 암기 카드가 아니라 같은 입력을 다음 단계로 넘기는 한 프로그램의 부품입니다")

Python 프로그램은 기본적으로 위에서 아래로 실행됩니다. 먼저 값을 만들고, 그 값을 이름으로
가리키고, 여러 값을 묶은 뒤, 필요한 줄을 골라 반복합니다. 함수는 이 규칙에 이름을 붙여 다시
호출할 수 있게 합니다. 이 순서를 알면 처음 보는 코드도 각 줄이 맡은 일을 나눠 읽을 수 있습니다.

`문법`은 Python이 코드를 읽는 규칙입니다. 괄호와 콜론과 들여쓰기를 어디에 쓰는지가 여기에
포함됩니다. `값`은 `120000`, `"영업팀"`, `[50000, 120000]`처럼 프로그램이 실제로 다루는
데이터입니다. 문법은 값을 만드는 것이 아니라 값을 저장하고 찾고 비교하는 방법을 정합니다.

이번 프로그램의 입력은 부서와 금액이 들어 있는 지출내역 세 건입니다. 출력은 전체 합계와 거래별
분류 결과입니다. 여섯 문법은 그 사이에서 다음 일을 맡습니다.

#### 설명 목록: 지출 검토 프로그램에서 여섯 문법이 맡는 일

| 문법 | 코드에서 보이는 모양 | 이번 예제에서 하는 일 |
|---|---|---|
| 변수 | `amount_limit = 100000` | 기준금액 하나를 이름으로 가리킴 |
| 리스트 | `[50000, 120000, 80000]` | 여러 거래를 입력 순서대로 묶음 |
| 딕셔너리 | `{"조직": "영업팀"}` | 항목 이름과 값을 한 쌍으로 묶음 |
| 조건문 | `if amount >= amount_limit:` | 기준 이상인지에 따라 결과를 고름 |
| 반복문 | `for record in records:` | 모든 거래에 같은 일을 적용함 |
| 함수 | `classify_expense(amount)` | 분류 규칙을 이름으로 다시 호출함 |

이 표를 외울 필요는 없습니다. 다음 절부터 `영업팀`, `120000`, `100000`을 직접 바꾸면 각 문법이
어떤 결과를 바꾸는지 보입니다. 첫 단계는 값에 이름을 붙여 다음 줄에서 다시 쓰는 것입니다.

## 변수는 값에 다시 쓸 이름을 붙입니다

### 등호 오른쪽 값을 먼저 계산한 뒤 왼쪽 이름으로 다음 줄에서 다시 사용합니다

![부서와 금액과 기준값 카드가 각각의 변수 이름표에 연결되고 출력 문장에 다시 사용되는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/18/18a507345379e23d2ab8b2b34821da8648e06fceeecf2368abdf6158aa476154.png "등호는 두 값이 같다는 질문이 아니라 오른쪽 값을 왼쪽 이름으로 가리키게 하는 할당입니다")

변수는 값을 다시 찾기 위해 붙이는 이름입니다. `department = "영업팀"`을 실행하면 Python은
오른쪽의 글자를 먼저 만들고 `department`라는 이름이 그 값을 가리키게 합니다. 이 동작을
`할당`이라고 부릅니다. 수학의 등호와 달리 같음을 묻는 기호가 아닙니다.

값에는 종류가 있습니다. `"영업팀"`은 따옴표로 감싼 글자이므로 문자열 `str`이고, `120000`은
정수 `int`입니다. 변수 자체에 자료형이 고정되는 것은 아닙니다. 같은 이름에 다른 값을 다시
할당할 수 있지만, 금액 이름에 글자를 넣으면 뒤의 비교나 합계에서 오류가 생길 수 있습니다.

변수 이름은 숫자로 시작할 수 없고 띄어쓰기를 넣을 수 없습니다. `amount_limit`처럼 단어 사이에
밑줄을 쓰면 뜻을 읽기 쉽습니다. Python은 대문자와 소문자를 구분하므로 `amount`와 `Amount`는
서로 다른 이름입니다.

#### 예시 코드: 부서와 금액과 기준값을 변수에 저장하기

입력은 부서 이름, 지출 금액, 검토 기준금액입니다. 첫 세 줄이 값을 변수에 할당하고, 마지막
f-string은 중괄호 안의 변수값을 읽어 한 문장으로 만듭니다. 금액 뒤의 `:,`는 천 단위 쉼표를
표시할 뿐 원래 정수값을 바꾸지 않습니다.

```python
department = "영업팀"
amount = 120000
amount_limit = 100000

message = f"{department}: {amount:,}원, 기준 {amount_limit:,}원"
print(message)
```

출력은 `영업팀: 120,000원, 기준 100,000원`입니다. `department`를 `"관리팀"`으로 바꾸면
출력의 부서만 바뀝니다. `amount_limit`을 `150000`으로 바꾸면 기준 표시만 바뀝니다. 한 값을 한
곳에서 바꾸고 그 이름을 사용하는 모든 줄에 같은 값이 전달되는 것이 변수의 쓸모입니다.

https://eddmpython.com/codaro/run/?example=expense-variables

아직 값을 한 개씩만 저장했습니다. 거래가 열 건으로 늘어나면 변수 열 개를 만들기보다 여러 값을
하나로 묶어야 하며, 그때 리스트가 필요합니다.

## 리스트는 같은 종류의 값을 순서대로 묶습니다

### 대괄호 안의 금액을 입력 순서대로 저장하고 개수와 합계를 함께 계산합니다

![금액 카드 세 장이 대괄호 모양 목록에 입력 순서대로 들어가고 건수와 합계 결과로 이어지는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/96/96aca7768b408fc5f4d264436f5c513e03c7fe4fb0469311fc973073afd63d54.png "리스트에 값 하나를 추가하면 같은 목록을 읽는 거래 건수와 전체 합계가 함께 달라집니다")

리스트는 여러 값을 순서대로 담는 자료형입니다. 대괄호 `[]` 안에 값을 쉼표로 나눠 적습니다.
Python은 첫 번째 위치를 `0`부터 세므로 `amounts[0]`은 `50000`이고 `amounts[1]`은
`120000`입니다. 위치 번호를 인덱스라고 부릅니다.

리스트의 내용은 실행 중에 바꿀 수 있습니다. 이런 성질을 `변경 가능하다`고 말합니다.
`amounts.append(30000)`은 목록 끝에 새 금액을 추가합니다. `len()`은 항목 개수를 세고,
`sum()`은 숫자 항목을 모두 더합니다.

빈 리스트 `[]`도 정상적인 리스트입니다. `len([])`과 `sum([])`은 모두 `0`이므로 거래가 없는 날도
건수와 합계를 계산할 수 있습니다. 반면 빈 리스트에서 `amounts[0]`을 읽으면 첫 항목이 없기 때문에
`IndexError`가 발생합니다. 위치로 값을 읽기 전에는 목록이 비어 있지 않은지 확인해야 합니다.

#### 예시 코드: 거래 금액을 리스트에 추가하고 합계 계산하기

입력 리스트에는 정수 금액 세 개가 있습니다. `append()`가 네 번째 값을 같은 리스트 끝에 넣고,
`len()`과 `sum()`이 변경된 목록을 읽습니다. 핵심은 금액을 추가한 뒤 계산 줄을 복사하지 않아도
목록 전체의 건수와 합계가 다시 계산된다는 점입니다.

```python
amounts = [50000, 120000, 80000]
amounts.append(30000)

count = len(amounts)
total = sum(amounts)
first_amount = amounts[0]

print(f"첫 거래 {first_amount:,}원")
print(f"{count}건, 합계 {total:,}원")
```

예상 출력은 `첫 거래 50,000원`과 `4건, 합계 280,000원`입니다. `append(30000)`을 지우면 다시
3건과 250,000원이 나옵니다. 리스트는 순서가 중요한 거래 모음에 맞지만, 각 값이 어느 부서의
금액인지 이름으로 찾을 수는 없습니다.

https://eddmpython.com/codaro/run/?example=expense-list-total

부서와 금액처럼 한 거래 안의 항목마다 이름이 필요하면 위치 번호 대신 키로 값을 찾는 딕셔너리를
사용합니다.

## 딕셔너리는 이름으로 값을 찾습니다

### 중괄호 안에서 키와 값을 한 쌍으로 저장하고 열 이름으로 필요한 값을 꺼냅니다

![원본 Excel 열 이름 카드 세 장이 각각의 표준 열 이름 카드와 한 쌍으로 연결된 변환표](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/71/716598bedae7e253bc30eb531341bdc6f91267aad3f4767b4b07b799dab5694e.png "딕셔너리는 왼쪽 키 하나를 찾았을 때 연결된 오른쪽 값 하나를 돌려주는 이름표입니다")

딕셔너리는 키와 값을 한 쌍으로 묶는 자료형입니다. 중괄호 `{}` 안에서 콜론 왼쪽에 키를, 오른쪽에
값을 적습니다. `column_map["사용금액"]`처럼 키를 대괄호에 넣으면 연결된 값 `"금액"`을 얻습니다.
리스트가 위치로 찾는 자료형이라면 딕셔너리는 이름으로 찾는 자료형입니다.

한 딕셔너리 안에서 키는 겹칠 수 없습니다. 같은 키를 다시 저장하면 이전 값이 새 값으로 바뀝니다.
문자열과 숫자는 키로 쓸 수 있지만 내용이 바뀔 수 있는 리스트는 키로 쓸 수 없습니다. 업무
코드에서는 열 이름, 부서 코드, 설정 이름처럼 중복되지 않는 표식을 키로 많이 사용합니다.

아래 예제는 서로 다른 Excel 열 이름을 하나의 표준 이름으로 연결합니다. 실제 파일마다 `조직`,
`부서명`, `소속부서`처럼 이름이 다를 때 원본 이름을 표준 이름 `부서`로 바꾸는 규칙의 기초가 됩니다.

#### 예시 코드: 원본 Excel 열 이름을 표준 이름으로 찾기

입력은 원본 열 이름 세 개와 표준 열 이름 세 개의 대응표입니다. `column_name`에 찾을 키를 넣고
`column_map[column_name]`을 실행하면 그 키와 한 쌍인 값이 나옵니다. `사용금액`을 `조직`으로
바꾸면 같은 코드가 `부서`를 돌려줍니다.

```python
column_map = {
    "사용일": "일자",
    "조직": "부서",
    "사용금액": "금액",
}

column_name = "사용금액"
standard_name = column_map[column_name]

print(f"{column_name} -> {standard_name}")
```

예상 출력은 `사용금액 -> 금액`입니다. Python 공식 문서도 딕셔너리를 고유한 키와 값의 쌍으로
설명합니다. 자세한 동작은 [딕셔너리 공식 설명](https://docs.python.org/3/tutorial/datastructures.html#dictionaries)에서
확인할 수 있습니다.

https://eddmpython.com/codaro/run/?example=expense-column-map

#### 실패 예시: 딕셔너리에 없는 열 이름을 찾기

`column_map["결제금액"]`처럼 없는 키를 대괄호로 찾으면 `KeyError`가 발생하고 그 줄에서 실행이
멈춥니다. 입력 파일에서 처음 보는 열 이름을 허용하려면 먼저 `in`으로 존재를 확인하거나
`column_map.get("결제금액")`을 사용합니다. `get()`은 키가 없을 때 기본적으로 `None`을 돌려주므로
오류와 누락을 구분해 처리할 수 있습니다.

```python
column_name = "결제금액"

if column_name in column_map:
    print(column_map[column_name])
else:
    print(f"등록되지 않은 열: {column_name}")
```

이 코드의 출력은 `등록되지 않은 열: 결제금액`입니다. 여기서 처음 등장한 `if`와 `else`는 키가
있는 경우와 없는 경우 중 실행할 줄을 고릅니다. 다음 절에서는 이 선택이 어떻게 만들어지는지
금액 경계값으로 확인합니다.

## 조건문은 비교 결과로 실행 줄을 고릅니다

### 금액과 기준을 비교해 참이면 확인필요를, 거짓이면 정상을 선택합니다

![지출 금액과 기준금액이 비교 지점에 들어가고 닫힌 결과 카드와 열린 결과 카드 중 하나가 선택되는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/52/5274db969e51c93221735e8d221b39f0c4a8e985a36de149a71cb6fba2722c50.png "금액이 기준과 같은 순간에도 어느 쪽으로 가는지는 비교 연산자의 등호 포함 여부가 결정합니다")

조건문은 비교 결과에 따라 실행할 코드 묶음을 고릅니다. 비교 결과는 `True` 또는 `False` 두 값 중
하나이며, 이를 불리언 `bool`이라고 부릅니다. `amount >= amount_limit`은 금액이 기준보다 크거나
같은지 묻습니다. `>=`에는 같은 값이 포함됩니다.

`if` 뒤의 조건이 `True`이면 콜론 아래 들여쓴 줄을 실행합니다. `False`이면 `else` 아래 들여쓴 줄을
실행합니다. 들여쓰기는 보기 좋게 넣는 공백이 아니라 어느 줄이 조건에 속하는지 정하는 문법입니다.
같은 코드 묶음은 보통 공백 네 칸으로 맞춥니다.

비교 기호를 정확히 구분해야 합니다. `>`는 초과, `>=`는 이상, `<`는 미만, `<=`는 이하입니다.
`==`는 두 값이 같은지 묻고 `!=`는 다른지 묻습니다. 값을 할당하는 `=`와 같은지 비교하는 `==`는
서로 다른 문법입니다.

#### 예시 코드: 기준금액과 같은 거래까지 확인필요로 분류하기

입력은 지출 금액 `100000`과 같은 기준값입니다. 비교식이 `True`이므로 첫 번째 코드 묶음이
실행되고 `result`에는 `"확인필요"`가 들어갑니다. 금액을 `99999`로 바꾸면 비교식이 `False`가 되어
`else` 묶음의 `"정상"`이 선택됩니다.

```python
amount = 100000
amount_limit = 100000

if amount >= amount_limit:
    result = "확인필요"
else:
    result = "정상"

print(f"{amount:,}원: {result}")
```

| 금액 | `amount >= 100000` | 결과 |
|---:|---|---|
| 99,999 | `False` | 정상 |
| 100,000 | `True` | 확인필요 |
| 120,000 | `True` | 확인필요 |

https://eddmpython.com/codaro/run/?example=expense-condition

실무 오류는 경계에서 자주 생깁니다. 규칙이 `100,000원 초과`라면 `>`를 써야 하고, `100,000원
이상`이라면 `>=`를 써야 합니다. 한 거래의 선택을 확인했으므로 이제 같은 선택을 목록의 모든
거래에 적용할 차례입니다.

## 반복문은 목록의 모든 값에 같은 일을 합니다

### 리스트에서 금액을 하나씩 꺼내 같은 비교를 실행하고 결과 목록에 차례로 추가합니다

![금액 목록의 세 카드가 같은 비교 코드 블록을 차례로 통과해 세 줄의 결과 목록으로 쌓이는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/c4/c488ba7323bf36a02f765f8644dfac04919af49d124d8a564f2fb9cca9f1ccfc.png "반복문 본문은 입력 항목 수만큼 실행되므로 목록에 거래 하나를 추가하면 결과도 한 줄 늘어납니다")

반복문은 여러 항목에 같은 코드를 적용합니다. `for amount in amounts:`는 리스트의 첫 금액부터
마지막 금액까지 하나씩 꺼냅니다. 꺼낸 값은 매번 `amount` 변수에 들어가고, 콜론 아래 들여쓴 코드가
한 번 실행됩니다.

결과를 나중에 다시 쓰려면 빈 리스트 `results = []`를 먼저 만들고 매 반복에서 `append()`로 한 줄씩
추가합니다. 이처럼 반복 전 값을 준비하고 반복 중에 값을 모으는 변수를 누산기라고 부르기도 합니다.
여기서는 합계를 더하는 대신 분류 문장을 쌓습니다.

입력 리스트가 비어 있으면 반복 본문은 한 번도 실행되지 않고 `results`도 빈 리스트로 남습니다.
이 동작은 오류가 아닙니다. 반대로 순회 중인 `amounts`에 값을 추가하거나 지우면 다음에 처리할
위치가 달라져 항목을 놓칠 수 있습니다. [Python 공식 문서](https://docs.python.org/3/tutorial/controlflow.html#for-statements)도
순회 중 같은 모음을 수정해야 할 때는 복사본을 돌거나 새 모음을 만들도록 안내합니다.

#### 예시 코드: 모든 거래 금액을 같은 기준으로 분류하기

입력 리스트에는 금액 세 개가 있고 기준값은 `100000`입니다. 반복문은 세 번 실행됩니다. 각 실행에서
조건문이 한 개의 라벨을 고르고 `append()`가 결과 리스트에 문장을 추가합니다. 마지막 `join()`은
세 문장을 줄바꿈 문자 `\n`으로 연결해 읽기 좋게 출력합니다.

```python
amounts = [50000, 120000, 80000]
amount_limit = 100000
results = []

for amount in amounts:
    if amount >= amount_limit:
        label = "확인필요"
    else:
        label = "정상"
    results.append(f"{amount:,}원: {label}")

print("\n".join(results))
```

출력은 `50,000원: 정상`, `120,000원: 확인필요`, `80,000원: 정상` 세 줄입니다. 입력 목록 끝에
`100000`을 추가하면 결과가 네 줄로 늘고 마지막 줄도 확인필요가 됩니다. 같은 조건문을 네 번
복사하지 않아도 입력 개수만큼 실행되는 것이 반복문의 쓸모입니다.

https://eddmpython.com/codaro/run/?example=expense-loop

현재 코드는 반복문 안에 분류 규칙이 들어 있습니다. 다른 화면에서도 같은 규칙을 쓰려면 코드를
복사하기보다 함수로 묶어 이름으로 호출하는 편이 안전합니다.

## 함수는 입력과 결과가 있는 규칙입니다

### 금액과 기준을 매개변수로 받아 분류한 뒤 return으로 호출한 곳에 결과를 돌려줍니다

![서로 다른 금액 카드가 금액과 기준 입력칸이 있는 하나의 함수 코드 블록을 지나 분류 결과로 나오는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/09/09f955a54389759a8505a136952fc826f81956cccf9d13c23efcdffbbe071e82.png "함수 본문은 한 번 적고 호출할 때 금액과 기준만 바꾸면 같은 분류 규칙을 다시 사용할 수 있습니다")

함수는 여러 줄의 코드에 이름을 붙인 것입니다. `def classify_expense(...):`를 실행하면 함수가
정의되지만 분류는 아직 일어나지 않습니다. 아래에서 `classify_expense(50000)`처럼 함수 이름 뒤에
괄호를 붙여 호출해야 본문이 실행됩니다.

함수 정의의 `amount`와 `amount_limit`은 입력을 받을 이름이며 매개변수라고 부릅니다. 호출할 때 넣는
`50000`과 `100000`은 실제 입력값이며 인자라고 부릅니다. `return`은 계산한 결과를 호출한 자리로
돌려줍니다. 반환값을 변수에 저장하거나 리스트에 넣어 다음 계산에 사용할 수 있습니다.

`amount_limit=100000`은 두 번째 인자를 생략했을 때 쓸 기본값입니다. 기본값 덕분에 평소에는
`classify_expense(50000)`처럼 짧게 호출하고, 다른 기준이 필요할 때만
`classify_expense(50000, 30000)`처럼 두 값을 넣을 수 있습니다.

#### 예시 코드: 금액과 기준을 받는 분류 함수 세 번 호출하기

입력은 금액 하나와 선택적인 기준금액입니다. 조건문이 라벨을 고르고 `return`이 문자열을 돌려줍니다.
리스트의 세 금액을 함수에 차례로 넣으면 입력과 같은 순서로 세 결과가 만들어집니다. 함수 안의
매개변수는 호출할 때마다 새 값으로 시작하므로 앞 호출의 금액이 다음 호출에 남지 않습니다.

```python
def classify_expense(amount, amount_limit=100000):
    if amount >= amount_limit:
        return "확인필요"
    return "정상"

samples = [50000, 120000, 80000]
results = []

for amount in samples:
    results.append(classify_expense(amount))

print(results)
print(classify_expense(50000, 30000))
```

첫 출력은 `['정상', '확인필요', '정상']`입니다. 마지막 호출은 기준을 `30000`으로 낮췄으므로
`확인필요`를 출력합니다. 함수에서 `return`을 빼고 `print()`만 쓰면 화면에는 문장이 보여도 호출
결과는 `None`이 됩니다. 뒤에서 결과를 저장하거나 비교해야 한다면 반드시 값을 반환해야 합니다.

https://eddmpython.com/codaro/run/?example=expense-function

이제 여섯 문법의 개별 동작을 확인했습니다. 마지막 절에서는 부서와 금액이 들어 있는 실제 모양의
입력을 하나의 결과표로 바꾸고, 합계와 경계값을 숫자로 검증합니다.

## 여섯 문법으로 지출 검토를 완성합니다

### 부서별 거래 세 건을 분류하고 합계와 확인필요 건수를 출력한 뒤 입력을 바꿔 검증합니다

![부서별 지출 딕셔너리 세 건이 여섯 문법의 코드 단계를 지나 합계와 거래별 분류 결과표로 바뀌는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/24/2488fb08e37335b290eb7f97b6aafd94999e515c5ef34bb4650e9b4554dbfafd.png "완성 예제에서는 여섯 문법이 같은 입력을 공유하므로 금액 하나를 바꾸면 합계와 분류가 함께 달라집니다")

완성 예제의 입력은 딕셔너리 세 개를 담은 리스트입니다. 각 딕셔너리에는 `조직`과 `사용금액`이
있습니다. 변수 `amount_limit`은 모든 거래가 공유하는 기준을 저장합니다. 함수는 거래 하나의 금액을
분류하고 반복문은 세 거래 모두에 그 함수를 호출합니다.

결과 리스트에는 원본 열 이름 대신 `부서`, `금액`, `결과`를 저장합니다. 이때 `column_map`
딕셔너리에서 표준 열 이름을 찾습니다. 전체 합계와 확인필요 건수도 같은 반복문에서 함께 계산하므로
입력 금액을 바꾸면 결과표와 두 숫자가 한 번에 달라집니다.

#### 예시 코드: 부서별 지출을 분류하고 합계와 건수 출력하기

입력은 영업팀 50,000원, 관리팀 120,000원, 영업팀 80,000원입니다. 함수는 금액과 기준을 받아
라벨을 반환합니다. 반복문은 표준 열 이름으로 새 결과 딕셔너리를 만들고, 같은 금액을 `total`에
더합니다. 확인필요인 경우에만 `flagged_count`도 1씩 늘립니다.

```python
column_map = {"조직": "부서", "사용금액": "금액"}
records = [
    {"조직": "영업팀", "사용금액": 50000},
    {"조직": "관리팀", "사용금액": 120000},
    {"조직": "영업팀", "사용금액": 80000},
]
amount_limit = 100000

def classify_expense(amount, limit):
    if amount >= limit:
        return "확인필요"
    return "정상"

results = []
total = 0
flagged_count = 0

for record in records:
    amount = record["사용금액"]
    label = classify_expense(amount, amount_limit)
    results.append({
        column_map["조직"]: record["조직"],
        column_map["사용금액"]: amount,
        "결과": label,
    })
    total = total + amount
    if label == "확인필요":
        flagged_count = flagged_count + 1

print(f"합계 {total:,}원")
print(f"확인필요 {flagged_count}건")
for result in results:
    print(f"{result['부서']}: {result['금액']:,}원, {result['결과']}")
```

정상 출력은 합계 `250,000원`, 확인필요 `1건`, 거래별 결과 세 줄입니다. 관리팀 금액 `120000`을
`90000`으로 바꾸고 다시 실행하면 합계는 `220,000원`, 확인필요는 `0건`이 됩니다. 이 두 숫자가
함께 바뀌어야 입력, 분류, 합계가 모두 같은 값을 읽었다는 증거가 됩니다.

https://eddmpython.com/codaro/run/?example=expense-syntax-together

#### 실패 예시: 없는 키와 문자 금액을 입력했을 때 복구하기

`"사용금액"`을 `"사용 금액"`으로 잘못 쓰면 딕셔너리에 해당 키가 없어 `KeyError`가 납니다.
원본 파일의 열 이름을 확인하고 `records`와 `column_map`에서 같은 철자를 사용해야 합니다. 금액을
`"120000"`처럼 따옴표로 감싸면 문자열이 되어 정수 기준과 비교할 때 `TypeError`가 납니다.
계산할 금액은 따옴표 없는 정수로 바꾸거나 입력 단계에서 `int()`로 변환합니다.

```python
raw_amount = "120000"
amount = int(raw_amount)

print(type(raw_amount).__name__)
print(type(amount).__name__)
print(classify_expense(amount, 100000))
```

출력은 차례로 `str`, `int`, `확인필요`입니다. `int()`는 숫자로만 이루어진 문자열을 정수로
바꿉니다. `"120,000원"`처럼 쉼표와 단위가 섞인 값은 바로 변환할 수 없으므로 먼저 쉼표와 `원`을
제거해야 합니다.

마지막 확인은 간단합니다. 실행 셀에서 관리팀 금액을 `99999`, `100000`, `"100000"`으로 한 번씩
바꿉니다. 앞의 두 값은 정상과 확인필요로 나뉘고, 따옴표가 있는 값은 자료형 오류가 나야 지금까지
배운 변수, 자료형, 조건 경계를 실제 결과로 구분한 것입니다.
