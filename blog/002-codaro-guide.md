Python을 처음 배운다고 해보겠습니다. 강의에는 `print("안녕하세요")`라는 코드가 나옵니다. 코드를
읽었지만 어디에 입력하고 어떤 버튼을 눌러야 하는지는 잘 모르겠습니다. Python 설치 방법을 검색하면
처음 보는 설정과 프로그램 이름이 한꺼번에 나옵니다.

그 전에 할 수 있는 일이 있습니다. 브라우저에서 레슨을 열고, 준비된 코드를 실행하고, 숫자 하나를
바꿔 결과가 달라지는지만 보면 됩니다. 이 글에서 쓰는 도구는 Codaro입니다. Codaro는 Python 학습
화면에서 설명, 코드, 실행, 결과 확인을 한곳에 모아 둔 도구입니다.

아래 순서로 따라가면 됩니다. 먼저 설치 없이 첫 실행을 해보고, 나중에 내 컴퓨터의 파일이 필요할 때
무엇을 설치하면 되는지 알아봅니다.

이 글의 목표는 특정 화면의 버튼 위치만 외우는 것이 아닙니다. 코드, 실행 환경, 결과, 저장 파일이
어떻게 이어지는지 이해하면 화면이 조금 바뀌어도 스스로 다음 행동을 찾을 수 있습니다.

## 설치하지 않고 첫 레슨을 엽니다

### 브라우저 레슨을 열고 실행 버튼을 눌러 결과 칸이 바뀌는지 봅니다

![닫힌 설치 도구 상자 옆으로 브라우저 학습 책상까지 길이 열린 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/5c/5c06900abb00b67f31e460c9a097872ca648c5f397451494c319d2a980e93418.png "Python 설치보다 먼저 브라우저에서 첫 레슨을 열어 볼 수 있다")

[Codaro Web 학습](https://eddmpython.com/codaro/learn/)을 엽니다. Web은 브라우저에서 쓰는
버전이라는 뜻입니다. Chrome이나 Edge에서 페이지를 열 수 있으면 시작할 수 있습니다.

설치 없이 실행한다는 말은 Python 실행기가 필요 없다는 뜻이 아닙니다. 내 컴퓨터에 실행 프로그램을
미리 설치하는 대신, 웹페이지가 브라우저 안에 실행 환경을 준비합니다. 코드를 입력하고 실행 버튼을
누르면 이 환경이 코드를 읽고 결과 칸에 출력합니다.

코드, 실행기, 결과라는 기본 구조는 설치형 Python과 같습니다. 실행기가 준비되는 장소만 다릅니다.

레슨 목록에서 처음 배울 주제를 고릅니다. 레슨을 열면 제목 아래에 이번에 만들 결과가 나옵니다.
설명을 읽은 뒤 코드 입력칸 아래의 `실행` 버튼을 누릅니다. 잠시 뒤 결과 칸에 글자나 숫자가 나오면
첫 실행이 끝난 것입니다.

처음 누를 때는 조금 오래 걸릴 수 있습니다. 웹페이지가 브라우저 안에서 Python을 실행하는 데 필요한
프로그램을 준비하기 때문입니다. 같은 페이지에서 두 번째로 실행할 때는 보통 더 빨라집니다.

첫 실행이 늦다고 여러 번 연속으로 누르면 같은 실행을 겹쳐 요청할 수 있습니다. 실행 표시가 끝날 때까지
한 번 기다린 뒤 결과 칸을 확인합니다. 결과 대신 오류가 보이면 실행 환경까지는 정상적으로 연결됐고
코드에서 고칠 지점을 받았다는 뜻일 수 있습니다.

브라우저 버전은 연습용 코드에는 충분하지만 내 컴퓨터의 모든 파일을 읽을 수는 없습니다. 다운로드
폴더의 CSV 파일을 열거나 Windows 프로그램을 실행하는 수업은 Local이라고 표시됩니다. CSV는 엑셀로도
열 수 있는 표 파일이고, Local은 뒤에서 설명할 설치형 버전입니다.

#### 확인 목록: 브라우저 첫 실행이 끝났다는 증거

- 레슨 제목과 설명이 보이고 코드 입력칸을 클릭할 수 있습니다.
- 실행 버튼을 한 번 누른 뒤 실행 중 표시가 사라집니다.
- 결과 칸에 출력이나 오류 중 하나가 새로 나타납니다.
- 같은 코드를 다시 실행했을 때 같은 결과가 나옵니다.

마지막 항목은 중요합니다. 아무것도 바꾸지 않았는데 결과가 계속 달라진다면 현재 시간이나 무작위 값처럼
실행할 때마다 변하는 입력이 있는지 먼저 확인해야 합니다.

## 첫 화면에서는 세 가지만 하면 됩니다

### 준비된 코드를 실행하고 값 하나를 바꿔 다시 실행하면 첫 화면은 충분합니다

![하나의 코드 종이가 설명대와 실행 장치와 검사 장치를 차례로 지나가는 어두운 작업대](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/9f/9fa7958302b8bc2111320d52a20623a7dc10b979c58f9bc3c996ea240e8268d8.png "설명을 읽고 코드를 실행한 뒤 숫자 하나를 바꿔 다시 실행하면 된다")

레슨을 열면 설명, 코드 입력칸, 실행 버튼, 결과가 나오는 칸이 보입니다. 처음부터 코드를 새로 만들
필요는 없습니다. 화면에 준비된 코드를 그대로 사용하면 됩니다.

할 일은 세 가지입니다.

1. 준비된 코드를 바꾸지 않고 실행합니다.
2. 결과 칸에 무엇이 나오는지 확인합니다.
3. 숫자나 글자 하나를 바꾼 뒤 다시 실행합니다.

예를 들어 `price = 1000`이라는 줄이 있다면 먼저 그대로 실행합니다. 그다음 `1000`을 `2000`으로
바꾸고 다시 실행합니다. `price`는 값을 담아 두는 이름입니다. 결과도 두 배로 바뀐다면 이 값이
계산에 어떻게 쓰였는지 눈으로 확인한 것입니다.

이 순서를 기준 실행, 한 가지 변경, 결과 비교라고 생각하면 쉽습니다. 기준 실행은 원래 코드와 실행
환경이 정상인지 확인합니다. 한 가지 변경은 원인 후보를 하나로 줄입니다. 결과 비교는 내가 바꾼 값이
어디까지 영향을 주는지 보여 줍니다.

처음부터 여러 줄을 바꾸면 어느 변경 때문에 결과가 달라졌는지 알기 어렵습니다.

처음에는 긴 코드를 모두 이해하려고 하지 않아도 됩니다. 한 줄을 바꾸고 결과가 달라지는지만 보면
됩니다. 오류가 나오더라도 망가진 것이 아닙니다. 방금 바꾼 줄을 원래대로 돌리고 다시 실행하면 됩니다.

#### 설명 목록: 첫 화면의 네 영역이 맡는 일

- **설명:** 무엇을 만들고 어떤 값을 확인할지 알려 줍니다.
- **코드 입력칸:** 컴퓨터가 실행할 명령과 현재 입력값을 담습니다.
- **실행 버튼:** 지금 입력칸의 상태를 실행 환경에 전달합니다.
- **결과 칸:** 출력값, 오류, 정답 검사처럼 실행 뒤 생긴 증거를 보여 줍니다.

## 작성한 코드는 .py 파일로 저장됩니다

### 화면의 여러 셀은 저장할 때 주석으로 나뉜 Python 파일 한 장이 됩니다

![여러 칸으로 나뉜 긴 종이가 끊어지지 않은 파일 한 장으로 이어지는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/81/81903f73887ec755a95234337a970dc97d80f9eef02efb394ea7793545c4ab55.png "화면에서는 여러 칸으로 보이지만 저장할 때는 Python 파일 하나가 된다")

Python 코드를 저장한 파일은 이름 끝에 `.py`가 붙습니다. 사진 파일의 `.jpg`, 문서 파일의
`.docx`와 같은 파일 이름 표시입니다. 예를 들어 매출 계산 코드는 `sales.py`라는 이름으로 저장할
수 있습니다.

Codaro에서는 긴 코드를 여러 셀로 나눠 볼 수 있습니다. 저장할 때는 셀 사이에 다음과 같은 주석이
들어갑니다.

입력은 설명 셀 하나와 코드 셀 하나입니다. 저장 결과는 두 셀의 경계가 주석으로 표시된 `sales.py`
파일 한 장입니다. 주석은 사람이 읽고 도구가 셀 위치를 복원하는 표시이며 실제 매출 계산에는 참여하지
않습니다.

#### 예시 코드: 두 셀이 하나의 Python 파일로 저장되는 모양

```python
# %% [markdown]
# 도시별 매출을 합칩니다.

# %% [code]
sales = [("서울", 120), ("부산", 85), ("서울", 40)]
```

`#`으로 시작하는 줄은 사람에게 보여 주는 설명입니다. Python은 이 줄을 계산하지 않습니다.
`# %%`는 Codaro가 셀의 시작 위치를 찾을 때 사용합니다. 그 아래의 `sales = ...`는 실제로
실행되는 Python 코드입니다.

`[markdown]`과 `[code]` 표시는 각 셀의 역할을 구분합니다. 이 줄이 없어도 일반 Python 코드 자체는
실행할 수 있지만, 다시 Codaro에서 열었을 때 설명과 코드의 경계를 복원하려면 표시를 유지하는 편이
좋습니다. 도구가 이해하는 주석이면서 사람에게도 파일 구조를 알려 주는 셈입니다.

저장된 파일은 Codaro에서만 쓰는 파일이 아닙니다. 다른 Python 편집기에서도 열 수 있습니다. 명령을
입력하는 프로그램인 터미널에서는 `python sales.py`라고 입력해 실행할 수도 있습니다. 나중에
도구를 바꾸더라도 작성한 코드는 그대로 남습니다.

#### 확인 목록: 저장한 파일이 도구 밖에서도 남는지 확인하기

- 파일 이름 끝이 `.py`인지 확인합니다.
- 텍스트 편집기로 열었을 때 설명 주석과 Python 코드가 그대로 보이는지 확인합니다.
- 다른 폴더로 복사한 뒤에도 파일을 다시 열 수 있는지 확인합니다.
- Local이나 터미널에서 실행할 때 필요한 데이터 파일 경로도 함께 옮겼는지 확인합니다.

## 코드가 길어지면 여러 셀로 나눕니다

### 앞 셀의 값을 바꾸면 그 값을 쓰는 다음 셀만 순서대로 다시 실행됩니다

![서로 연결된 코드 블록 가운데 필요한 두 블록에만 불이 들어온 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/e9/e9850269647432bf2f6e97a1400c5a77ebabfa9eef038af5f1a1eeb0fb47c792.png "매출을 바꾸면 합계와 순위를 계산하는 셀이 차례로 다시 실행된다")

코드가 길어지면 한 칸에 모두 넣기보다 하는 일에 따라 나누는 편이 읽기 쉽습니다. 첫 번째 셀에는
매출 원본을 넣고, 두 번째 셀에서는 도시별 합계를 계산하고, 세 번째 셀에서는 1위를 찾을 수 있습니다.

셀을 나누는 기준은 줄 수보다 책임입니다. 원본 입력, 데이터 정리, 계산, 결과 출력처럼 한 문장으로
설명할 수 있는 일을 한 셀에 모으면 어디를 고쳐야 할지 찾기 쉽습니다. 반대로 값 하나를 만들기 위해
여러 셀을 계속 오가야 한다면 지나치게 잘게 나눈 것입니다.

첫 번째 셀에서 서울 매출을 바꾸면 두 번째 셀의 합계도 달라져야 합니다. 합계가 달라지면 세 번째
셀의 순위도 다시 계산해야 합니다. Codaro는 어떤 셀이 `sales`와 `totals`를 사용하는지 확인하고
필요한 셀을 순서대로 다시 실행합니다.

순위 결과의 글자 모양만 바꿨다면 매출 원본까지 다시 계산하지 않습니다. 출력하는 셀만 다시
실행합니다. 합계를 계산하는 도중 오류가 나면 순위 계산은 멈춥니다. 잘못된 합계로 1위를 표시하지
않기 위해서입니다.

앞 셀이 실패했는데 뒤 셀의 예전 결과를 그대로 보여 주면 사용자는 오래된 값을 새 결과로 오해할 수
있습니다. 따라서 의존하는 계산을 멈추고 오류 지점을 먼저 고치는 것이 안전합니다. 화면에 남아 있는
결과가 언제 실행된 것인지 구분하는 습관도 필요합니다.

사용자가 셀 사이의 연결선을 직접 그릴 필요는 없습니다. 평소처럼 앞 셀에서 변수를 만들고 뒤 셀에서
그 변수를 사용하면 됩니다.

#### 설명 목록: 세 셀의 값이 흐르는 순서

- 첫 셀은 `sales`라는 원본 목록을 만듭니다.
- 둘째 셀은 `sales`를 읽어 `totals`라는 도시별 합계를 만듭니다.
- 셋째 셀은 `totals`를 읽어 가장 큰 도시를 찾습니다.
- 첫 셀이 바뀌면 둘째와 셋째 결과를 다시 확인해야 합니다.

## 실행 결과가 맞는지도 확인합니다

### 오류 없이 끝났는지와 문제의 답이 맞는지를 서로 다른 결과로 확인합니다

![실행 장치에서 나온 결과물이 여러 검사 장치를 차례로 지나는 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/02/02c68a2412c2a57b30043f344e41f4ba0401e498713fdf35e67a8c298268371c.png "오류가 없다는 것과 문제의 답이 맞다는 것은 서로 다른 확인이다")

코드가 멈추지 않고 끝났다고 해서 답이 맞는 것은 아닙니다. 도시별 매출을 더하는 문제에서 빈 결과를
보여 줘도 Python 오류는 나지 않을 수 있습니다. 답을 항상 `서울`이라고 적어 놓은 코드도 지금
예제에서는 맞아 보입니다.

그래서 Codaro 레슨은 두 가지를 따로 보여 줍니다. 먼저 Python 코드가 오류 없이 실행됐는지
확인합니다. 그다음 레슨이 요구한 결과가 나왔는지 검사합니다.

첫 검사는 실행 가능성을 봅니다. 문법 오류, 없는 변수, 잘못된 자료형처럼 Python이 작업을 끝내지
못하게 하는 문제가 대상입니다. 둘째 검사는 의미를 봅니다. 코드가 끝까지 실행됐더라도 합계가 틀리거나
필수 도시가 빠졌다면 정답 검사는 실패해야 합니다.

매출 예제라면 서울의 두 금액이 모두 더해졌는지, 다른 도시도 결과에 들어 있는지, 가장 큰 합계의
도시가 1위인지 확인할 수 있습니다. 검사가 실패하면 어느 값이 예상과 달랐는지 보여 줍니다. 사용자는
그 내용을 보고 코드를 고친 뒤 다시 실행합니다.

처음에는 `실행됨`과 `정답`을 구분하는 것만 기억하면 됩니다. 실행 버튼을 눌러 결과가 나오는 것이
첫 단계이고, 숫자를 바꿔도 올바른 답이 나오는지 확인하는 것이 다음 단계입니다.

#### 실패 예시: 실행은 됐지만 정답이 아닌 경우

- 결과 목록을 비워 두면 오류 없이 실행돼도 모든 도시가 빠집니다.
- 1위를 항상 서울이라고 적으면 원래 입력에서는 맞지만 숫자를 바꾸면 틀립니다.
- 서울의 첫 금액만 더하면 두 번째 서울 거래가 빠져 합계가 작아집니다.
- 가장 큰 합계 대신 가장 먼저 나온 도시를 고르면 입력 순서가 바뀔 때 실패합니다.

이런 예시는 한 개 입력에서 맞은 결과만 보는 것으로 충분하지 않음을 보여 줍니다. 값을 바꾼 예제와
경계값을 함께 검사해야 계산 규칙 자체가 맞는지 알 수 있습니다.

## 내 컴퓨터의 파일을 쓸 때는 Local을 엽니다

### 다운로드 폴더의 CSV를 읽을 때 브라우저 버전에서 설치형으로 넘어갑니다

![작은 브라우저 책상이 파일 서랍과 예약 장치가 있는 큰 작업실로 연결된 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/8f/8f0cb0bb269ef4b26d9ff5e89a8eaae3ef99a66cfb426ec143980c6b49a48aa7.png "다운로드 폴더의 CSV를 읽어야 할 때 브라우저 버전에서 Local로 넘어간다")

연습이 끝나면 실제 파일을 다뤄 보고 싶어집니다. 예를 들어 쇼핑몰에서 `sales.csv`를 내려받아
도시별 매출을 계산한다고 해보겠습니다. 이 파일은 내 컴퓨터의 다운로드 폴더에 있으므로 브라우저
레슨에서는 바로 열 수 없습니다.

이럴 때 [Codaro Local](https://github.com/eddmpython/codaro/releases/latest)을 설치합니다. Local은
내 컴퓨터에서 실행되는 Codaro입니다. 브라우저에서 연습한 `.py` 파일을 열고, `sales.csv`를 읽는
코드를 추가할 수 있습니다.

현재 Local 런처는 Windows 실행 파일로 배포됩니다. 릴리스에는 실행 파일뿐 아니라 파일이 바뀌지
않았는지 확인하는 SHA-256 값과 구성 요소 목록이 함께 제공됩니다. 최신 버전이라는 이유만으로 아무
파일이나 받기보다 공식 GitHub 릴리스에서 내려받고 검증 자료를 함께 확인하는 편이 안전합니다.

Local에서는 다음과 같은 일을 할 수 있습니다.

1. 내 컴퓨터의 CSV와 엑셀 파일을 읽습니다.
2. 결과를 새 파일로 저장합니다.
3. 엑셀 파일을 읽는 기능처럼 코드에 필요한 도구를 추가합니다.
4. 완성한 코드를 정해진 시간에 다시 실행합니다.

파일을 읽고 쓰거나 다른 프로그램을 실행하는 일에는 내 컴퓨터의 권한이 필요합니다. Codaro가 사용할
폴더나 명령이 달라지면 다시 확인하는 이유입니다. 처음에는 연습 파일이 들어 있는 폴더 하나만 허용하고
시작하는 편이 이해하기 쉽습니다.

Web과 Local의 차이는 초급과 고급의 서열이 아닙니다. Web은 설치 부담과 파일 권한을 줄인 연습
환경이고, Local은 실제 컴퓨터의 파일과 패키지와 일정 실행이 필요한 작업 환경입니다. 필요한 권한이
커질수록 할 수 있는 일도 늘지만 확인해야 할 안전 경계도 함께 늘어납니다.

#### 확인 목록: Local로 넘어갈 때 준비할 것

- 공식 릴리스에서 받은 설치 파일과 체크섬인지 확인합니다.
- 처음 열 폴더를 연습 자료가 있는 한 곳으로 제한합니다.
- `.py` 파일과 CSV 파일의 실제 위치를 확인합니다.
- 필요한 패키지와 버전을 프로젝트 환경에 기록합니다.
- 결과 파일을 원본과 다른 이름으로 저장해 되돌릴 수 있게 합니다.

## 처음에는 Web만 써도 충분합니다

### 연습은 Web에서, 내 파일과 반복 실행이 필요해질 때 Local에서 이어갑니다

![브라우저 학습 책상과 파일 작업실로 가는 길이 나뉜 모습](https://huggingface.co/datasets/eddmpython/eddmpython-media/resolve/main/objects/sha256/e8/e8e6ecab067341a51ec01d27983f0dd194b95f6ee6b1245f92f22539a9e71340.png "처음에는 브라우저에서 연습하고 실제 파일이 필요해질 때 Local을 설치한다")

Python을 처음 배우는 단계라면 브라우저 버전만 사용해도 됩니다. 설치할 프로그램과 저장할 폴더를
먼저 정하지 않아도 됩니다. 레슨을 열고 코드를 실행한 뒤 숫자 하나를 바꿔 보는 데 집중하면 됩니다.

반대로 브라우저에서 시작해야만 올바른 것도 아닙니다. 이미 Python 환경이 있고 터미널과 파일 경로에
익숙하다면 Local이나 다른 편집기에서 바로 시작해도 됩니다. 중요한 기준은 제품 이름이 아니라 지금
하려는 작업에 필요한 실행 범위입니다.

내 컴퓨터의 CSV나 엑셀 파일을 읽어야 할 때 Local로 넘어갑니다. 매일 같은 코드를 실행하거나 결과
파일을 자동으로 저장하고 싶을 때도 Local이 필요합니다. 브라우저에서 작성한 `.py` 파일을 그대로
열 수 있으므로 처음부터 다시 작성할 필요는 없습니다.

#### 설명 목록: 지금 선택할 실행 환경

- **문법과 작은 계산 연습:** Web에서 설치 없이 시작합니다.
- **내 CSV와 Excel 읽기:** 파일 권한이 있는 Local을 사용합니다.
- **패키지 추가와 반복 실행:** 환경과 일정을 관리할 수 있는 Local이 알맞습니다.
- **기존 개발 환경이 있음:** 익숙한 편집기와 터미널에서 같은 `.py` 파일을 사용할 수 있습니다.

[첫 레슨 열기](https://eddmpython.com/codaro/learn/lesson/30days/day01_%ED%97%AC%EB%A1%9C%EC%9B%94%EB%93%9C)를
누르고 `실행`을 한 번 누릅니다. 결과가 나오면 숫자나 글자 하나를 바꾸고 다시 누릅니다. 이 두 번의
실행이 끝난 뒤에 다음 레슨으로 넘어가면 됩니다.

첫 실행에서 얻어야 할 것은 많은 문법 지식이 아닙니다. 코드를 기준 상태로 실행하고, 값 하나를 바꾸고,
예상 결과와 비교하고, 원래 상태로 복구하는 한 번의 완전한 순환입니다. 이 순환을 이해하면 이후 문법,
파일, 자동화 학습도 같은 방법으로 확장할 수 있습니다.
