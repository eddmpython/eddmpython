# 작가 파이프라인

**글을 쓰기 전에 이 파일을 연다.** 여기를 통과하지 못하면 뒤의 형식 계약을 다 지켜도 실패다.

같이 여는 것이 둘 더 있다.
문체 작법은 `memory/writingVoice.md`, 커리큘럼과 절 사슬은 카테고리 폴더의 `원장.md` 다.
발행 계약과 이미지 규칙은 `blog/PIPELINE.md` 에 있고 그건 다 쓴 뒤에 본다.

## 순서: 절 뼈대가 먼저다

**글자를 쓰기 전에 절 제목부터 세운다.** 문장부터 쓰고 나중에 목차를 정리하면 이음이 죽는다.

1. 이 글이 답할 질문 하나를 적는다
2. **절 제목만 나열한다.** 본문을 쓰지 않는다
3. 절마다 `이 절이 남기는 모르는 것`을 한 줄 적는다
4. 인접한 두 절의 자리를 바꿔 보고 글이 깨지는지 본다. 안 깨지면 뼈대가 틀린 것이다
5. 그 뼈대를 카테고리 폴더의 `원장.md` 에 올린다
6. **뼈대가 통과한 뒤에 본문을 쓴다**
7. 다 쓰고 `python blog/scripts/outline.py` 로 원장과 본문을 대조한다

절 제목만 읽어도 글이 무슨 이야기인지 보여야 한다. 안 보이면 본문을 아무리 잘 써도 안 읽힌다.

## 게이트는 절이지 글자 수가 아니다

**분량으로 막지 않는다.** 하한에 미달할 때 가장 싼 해는 새 사실이 아니라 같은 사실의
재진술이다. 2026-08-17 에 발행 40편을 실측해 확인했다. 막는 것은 절 사슬이다.

## 아홉 가지 관문

운영자가 정한 것이다. 하나라도 아니면 발행하지 않는다.

1. **무조건 쉽게.** 읽는 사람은 코드를 한 줄도 써 본 적이 없다
2. **추상적 문장 금지.** 파일, 화면, 명령, 값, 오류 중 하나가 그 문장 안에 있어야 한다
3. **운영자 문체를 따른다.** 작법은 `memory/writingVoice.md` 다
4. **내용이 자연스럽게 이어진다.** 절과 절 사이가 예고가 아니라 사슬이어야 한다
5. **기승전결이 있다.** 절 순서를 바꾸면 글이 깨져야 한다
6. **절을 뼈대로 먼저 세우고 그것이 학습에 도움이 되는지 본다**
7. **볼거리가 풍부하다.** 영상과 이미지와 실행 칸이 절마다 있는지 본다
8. **퀄리티가 좋다.** 허접해 보이는 자리가 없어야 한다
9. **진짜 공부에 도움이 된다.** 읽고 나서 실제로 할 수 있는 것이 늘어야 한다

## 일곱 가지 함정

위 아홉을 지키려다 빠지는 자리다. 전부 이 저장소에서 실제로 겪었다.

10. **확인한 것만 쓴다.** 돌려 보지 않은 출력과 실측하지 않은 수치를 쓰지 않는다.
    2026-08-19 에 001 을 고치며 절을 이으려고 사실 아닌 인과를 여섯 군데 지어냈다
11. **없는 인과를 지어내지 않는다.** 예고는 지루할 뿐이지만 틀린 인과는 거짓이다.
    이을 말이 없으면 절을 합치거나 순서를 바꾼다
12. **개수를 미리 읊지 않는다.** `이유 세 가지입니다` 를 먼저 말하고 세 절이 차례로 다루면
    그 세 절은 사슬이 아니라 목록이 된다. 자리를 바꿔도 글이 성립한다
13. **자기 판정을 믿지 않는다.** 자기 글의 이음은 언제나 이어져 보인다.
    다른 눈이 인접 절의 자리를 바꿔 보는 검사를 거친다
14. **실패를 하나 보여준다.** 정답만 보여주면 독자는 자기가 막혔을 때 무너진다
15. **검색으로 바로 들어와도 닫힌다.** 앞 글을 먼저 읽으라고 요구하지 않는다.
    필요한 개념은 그 글에서 짧게 정의한다
16. **예제는 독자의 일이어야 한다.** 회사 엑셀과 전표에서 가져온다.
    문법을 설명하려고 만든 가짜 예제를 쓰지 않는다
17. **장면을 먼저 쓰고 이름은 나중에 붙인다.** `변수는 ~입니다` 로 절을 여는 자리가 많으면
    `check:post` 가 정의로 여는 문단이 너무 많다고 막는다. 2026-08-19 에 004 를 쓰다 걸렸다.
    영업팀이 12만원을 썼다는 장면을 먼저 놓고 그 뒤에 이것을 변수라고 부른다고 적는다.

## 다 쓰고 나서

이 순서로 확인한다. 앞에서 막히면 뒤는 볼 필요가 없다.

```text
python blog/scripts/outline.py                      원장의 절 사슬과 본문 H2 대조
cd site && npm run check:post -- <글 파일 경로>      한 편 엄격 검사
cd site && npm test                                  전체 검사
cd site && npm run build                             프로덕션 빌드
cd site && node scripts/visual.mjs capture           화면 캡처
cd site && npm run approve:visual -- --run=<run-id>  캡처를 눈으로 본 뒤 승인
cd site && npm run deploy                            배포
```

**캡처는 눈으로 본다.** DOM 검사가 통과했다고 승인하지 않는다.
데스크톱과 모바일 양쪽을 열어 보고, 실행 칸이 있으면 결과가 실제로 찍혔는지 확인한다.

배포 뒤에는 캐시버스터를 붙인 실제 URL 에서 제목과 H2 개수와 OG 이미지를 확인한다.
`/blog` 목록, `sitemap.xml`, `rss.xml` 도 같이 본다.
