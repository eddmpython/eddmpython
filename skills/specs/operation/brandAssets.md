# 브랜드 자산

## 로고와 디자인 정본을 나눈다

`site/src/brand.ts`는 심볼 작도의 정본이고 `site/src/design.ts`는 색, 테마, 글꼴, 모서리,
공용 글자 위계의 정본이다. **다른 곳에 좌표, 색상값, 공용 수치를 다시 정하지 않는다.**

| 쓰는 곳 | 어떻게 |
|---|---|
| 랜딩 헤더와 푸터 | `components/Logo.tsx` 가 `SYMBOL` 을 읽는다 |
| 운영장·강의방 머리띠 | `shell.ts` 가 `symbolMarkup()` 을 부른다 |
| 강의 모드 바 | `classroom.ts` 가 같은 `symbolMarkup()` 을 부른다 |
| `favicon.svg` 와 `/brand/*.svg` | `vite.config.ts` 의 `brandAssets` 플러그인이 만든다 |
| `og.png` | `npm run og` 가 같은 작도로 그린다 |
| `/brand` 화면 | `pages/Brand.tsx` 가 같은 모듈을 읽어 그 자리에서 그린다 |

**심볼 마크업을 손으로 조립하지 않는다.** `symbolMarkup()` 하나가 획과 점을 함께 낸다.
각자 `<path>` 와 점을 적게 두면 점 색이나 fill 규칙이 한 곳에서만 어긋나고, 실제로 그렇게
어긋난 적이 있다.

공개 블로그와 강의장의 섹션 제목은 `DESIGN.typography.sectionTitle` 하나를 쓴다. 모바일과
데스크톱 크기, 행간, 굵기, 자간을 그 객체에서 정하고 두 렌더러는 CSS 변수로 소비한다.
Tailwind 진입점 `src/styles.css`는 값 없이 `--eddm-*` 의미 변수만 연결하고, React와 Worker는
`designCssVars()`가 만든 같은 변수를 받는다. `npm run check:design`이 값 복제와 두 렌더러의
실제 소비를 함께 검사한다.

강조색은 `DESIGN.accent.dark`와 `DESIGN.accent.light`가 정본이다. 버튼, 링크,
선택 상태와 강의 진행선은 `--eddm-accent`와 그 파생 변수만 소비한다. 강조색을 바꿀 때 화면별
CSS를 찾지 않는다. **로고 점도 같은 값이다.** `BRAND.dot` 이 `DESIGN.palette.brand` 를 읽고,
그래서 심볼의 점과 화면의 강조가 어긋날 수 없다.

**브랜드 자산 파일을 저장소에 두지 않는다.** 사본을 두면 심볼을 고칠 때 그 사본만 옛 형태로
남는다. dev 는 미들웨어로, build 는 dist 파일로 같은 문자열을 낸다. 목록의 정본은
`vite.config.ts` 의 `BRAND_FILES` 이고 그 키가 곧 공개 URL 이다. 여기에 없는 브랜드 파일은
존재하지 않는다.

| URL | 무엇 |
|---|---|
| `/favicon.svg` | 탭 아이콘. `dark` 마감의 앱 아이콘과 같은 것 |
| `/brand/mark-dark.svg` | 심볼 단독, 밝은 획. 어두운 바탕용 |
| `/brand/mark-light.svg` | 심볼 단독, 어두운 획. 밝은 바탕용 |
| `/brand/icon-light.svg` | 밝은 칩 |
| `/brand/icon-dark.svg` | 어두운 칩. 기본값 |
| `/brand/icon-brand.svg` | 강조색 칩. 점도 흰색이다 |
| `/brand/icon-outline.svg` | 테두리 칩 |

`/brand` 화면이 이 목록을 보여 주고 내려받게 한다. 그 화면의 마크는 그림이 아니라 같은
모듈이 그 자리에서 계산해 낸 실물이라 다른 화면과 어긋날 수 없다. 브랜드 시트를 이미지로
떠서 올리지 않는 이유가 이것이다.

제품 마크(DartLab·Codaro 아바타, xlpod·pyproc 마크)는 `site/public/brand/` 에 두고
`src/productMarks.ts` 가 가리킨다. 제품 사이트 공개 brand URL에서 가져온 것이며, 제품
소스를 복제한 것이 아니다.

## 으뜸이 캐릭터

으뜸이는 eddmpython의 SNS 아바타에 쓰는 분홍 뱀 캐릭터다. 브랜드 심볼을 캐릭터로 다시
그린 것이 아니라 사람 으뜸이를 캐릭터화한 별도 자산이다. 심볼을 대신하지 않으며 헤더,
파비콘, 제품 마크에는 쓰지 않는다.

| 파일 | 포즈 | 연결 채널 |
|---|---|---|
| `site/public/brand/euddeum-avatar.webp` | EDDM Python 이름표를 든 원본 아바타 | SNS 공통 |
| `site/public/brand/euddeum-wave.webp` | 꼬리로 인사 | Threads |
| `site/public/brand/euddeum-analyze.webp` | 돋보기로 데이터 분석 | YouTube |
| `site/public/brand/euddeum-build.webp` | 노트북으로 제품 만들기 | GitHub |

2026-08-14에 공개 GitHub 프로필 아바타를 정체성 기준으로 삼아 ImageGen으로 생성했다.
분홍색은 이 캐릭터 이미지 픽셀 안에서만 허용한다. UI 배경, 테두리, 글자, 강조색과
`--eddm-*` 토큰에는 확장하지 않는다.

## 심볼

**한 획으로 그린 나선이다.** 안쪽 끝에서 가로획으로 오른쪽으로 가고, 위로 감아 바깥 바퀴를
한 바퀴 돌고, 오른쪽 아래로 빠져나와 위로 치솟으며 가늘어진다. 치솟은 끝 바로 위에 점이 뜬다.

한 획 안에 네 갈래가 겹친다. 어느 하나만 보여도 틀린 읽기가 아니다.

| 읽기 | 어디가 |
|---|---|
| 소문자 `e` | 가로획과 바깥 바퀴가 e 의 눈과 배 |
| 한글 `으` | 둥근 바퀴가 `ㅇ`, 가로획이 `ㅡ` |
| 뱀 | 감긴 몸통과 빠져나오는 꼬리 |
| 성장 | 가늘어지는 꼬리와 그 위의 정점 |

- 획이 하나의 채움 경로다. **나선이라 갇힌 구멍이 없어서 `fill-rule` 이 필요 없다.**
  가운데 여백은 바깥까지 이어지는 한 줄기 골이다
- 꼬리 끝 위의 점만 별도 요소다. 심볼에서 유일하게 색이 고정된 부분이다
- 꼬리 끝의 x 와 점의 x 가 같다. 꼬리가 점을 겨눈다. 우연이 아니라 작도에서 묶여 있다
- 잉크 경계가 viewBox(`0 0 315 248`) 에 꼭 맞는다. 여백은 쓰는 쪽이 정한다
- 가로세로 1.27 이다. 점이 오른쪽 위로 나오는 만큼 바퀴 자체는 정원이다

## 심볼은 좌표가 아니라 작도 규칙이다

`brand.ts` 의 `GEOMETRY` 열몇 줄이 정본이고 경로 문자열은 거기서 계산되어 나온다.
**손으로 딴 path 를 박아 두지 않는다.** 박아 두면 획 두께 하나를 고치려 해도 좌표 수백 개를
다시 따야 하고, 그때 접선이 어긋난 것을 아무도 못 본다.

작도는 바깥 바퀴의 중심을 원점으로 하고 중심선 반지름을 100 으로 둔다. 나머지 수치는 전부
그 100 에 대한 비율이다. 마디마다 앞 마디와 접선을 공유하는데, 그렇게 **맞춘 것이 아니라
접점 조건에서 풀어서** 쓴다.

- 가로획은 수평 직선이다
- 감아 올리는 호는 가로획에 접한다. 그래서 호의 중심이 가로획 바로 위에 있다
- 같은 호가 바깥 바퀴에도 안쪽에서 접한다. 두 접점 조건이 호의 반지름을 결정한다.
  `ARM_RADIUS` 를 손으로 정하지 않고 연립해서 푸는 이유다
- 꼬리는 바깥 바퀴에서 접선 방향으로 뻗는 3차 베지에다
- 획 두께는 꼬리에 들어서기 전까지 일정하고 꼬리에서만 선형으로 가늘어진다

두께가 일정한 구간은 원호의 평행곡선이 다시 원호라서 `A` 명령 하나로 정확히 적힌다.
근사가 들어가는 곳은 두께가 변하는 꼬리뿐이고, 표본 열두 개의 Catmull-Rom 이면 참 곡선과의
차이가 좌표 단위 0.05 아래다.

**획을 굵게 바꾸면 호의 반지름이 따라 바뀌고 이음매는 저절로 맞는다.** 그것이 이 방식을
쓰는 이유다. 다만 고친 뒤에는 16px 렌더를 눈으로 본다.

**2026-08-26 에 이 형태로 바꿨다.** 운영자가 정본 브랜드 시트를 주었고, 그 래스터에서
바깥 바퀴와 감아 올리는 호를 최소제곱으로 원에 맞춰(잔차 0.3 이하) 작도를 복원했다.
래스터를 그대로 따지 않고 다시 작도한 이유는 AI 가 낸 150px 이미지의 흔들림까지 물려받지
않기 위해서다. 복원한 작도를 다시 래스터화해 원본과 겹쳐 IoU 0.92 를 확인했다.
그 전의 `e` 판과 그보다 앞선 매듭 뱀은 이제 없다.

## 심볼의 점과 강조색은 같은 값이다

`DESIGN.palette.brand` 가 정본이고 값은 `#f56565` 다. **저장소의 모든 강조가 이 한 값에서
갈라진다.** 로고 심볼의 점, 워드마크의 `.py`, 버튼, 링크, 선택 상태, 강의 진행선이 전부
여기서 나온다. 강조색을 바꾸려면 그 한 줄만 고친다.

라이트 테마는 `PALETTE.brandDeep`(`#c53030`) 을 쓴다. 브랜드 색은 다크 배경에서 6.08:1 로
잘 읽히지만 라이트 배경에서는 2.73:1 이라 글자와 선으로 쓸 수 없다. 같은 색조를 유지하면서
4.93:1 까지 올린 값이고 두 값 다 실제로 재서 정했다.

정적 SVG(파비콘, og)는 CSS 변수를 못 읽으므로 `BRAND` 를 통해 원값을 읽는다. 그 밖의 화면은
`--eddm-accent` 와 파생 변수를 쓴다. `npm run check:design` 이 브랜드 색을 화면 파일에
직접 적은 자리와 골드를 함께 막는다.

## 워드마크는 `eddm.py` 다

로고 락업의 글자는 `eddm.py` 이고 `.py` 가 점 색을 쓴다. **문서 본문과 도메인에서 부르는
이름은 `eddmpython` 그대로다.** 워드마크만 짧은 표기를 쓰는 것이고 본문의 브랜드 이름을
이 표기로 바꾸지 않는다.

## 앱 아이콘 마감은 네 가지다

같은 심볼이고 색만 바뀐다. 놓이는 바탕이 밝은지 어두운지가 마감을 정한다. 정본은
`brand.ts` 의 `ICON_FINISHES` 이고 화면과 정적 파일이 같은 표를 읽는다.

| 마감 | 칩 | 획 | 쓰는 자리 |
|---|---|---|---|
| `light` | paper | carbon | 밝은 독과 밝은 문서 위 |
| `dark` | carbon | ivory | 기본값. 파비콘이 쓴다 |
| `brand` | brand | paper | 다른 아이콘 사이에서 튀어야 할 때 |
| `outline` | carbon | ivory + 테두리 | 어두운 바탕에 칩 경계를 보여야 할 때 |

**강조색 칩에서는 점도 흰색이다.** 칩이 이미 강조색이라 점을 강조색으로 두면 바탕에 묻혀
사라진다. 강조를 지고 있는 것이 점에서 칩으로 옮겨 간 것이지 점을 빼는 것이 아니다.
2026-08-26 에 실제로 강조 칩의 점이 안 보이는 판을 렌더하고 나서 고쳤다.

## 작은 크기에서 획을 깎지 않는다

16, 24, 32, 48, 64px 로 렌더해서 확인했다. 16px 에서도 가운데 골이 막히지 않고 점이 2~3px 의
색 점 하나로 남는다. 나선이라 갇힌 구멍이 없는 것이 여기서 값을 한다. 골을 벌리려고 획을
얇게 깎지 않는다.

앞 심볼에서 얻은 결론을 그대로 둔다. 작은 크기에서는 통로 분리보다 덩어리감이 이긴다.
침식해서 통로를 벌린 판을 7 배로 확대해 비교했더니 16px 에서 더 나빴다. 통로는 열리는데
획이 얇아져 마크가 힘을 잃는다. 수치가 가리킨 방향과 눈이 가리킨 방향이 달랐고 눈을 따랐다.

`/brand` 화면의 "작은 크기" 절이 이 검증을 상시로 띄워 둔다. 축소해서 보여 주는 그림이
아니라 실제 픽셀 높이로 그린다. 축소한 그림은 검증이 아니다.

## 파비콘 여백

칩 안에서 12% 여백을 둔다. iOS 스퀘어클과 Android 원형 마스크 양쪽에서 잘리지 않는 값으로
실제 렌더해서 정했다. 0% 는 잘린다.

파비콘은 `currentColor` 를 쓸 수 없다. 문서 문맥 밖에서 렌더되어 상속받을 색이 없고
브라우저가 검정으로 처리한다. 그래서 칩 배경과 심볼 색을 명시한다.

## 심볼을 바꿀 때

1. `site/src/brand.ts` 의 `GEOMETRY` 만 고친다. 경로 문자열을 직접 건드리지 않는다
2. `npm run build` 로 파비콘과 `/brand/*.svg` 가 함께 갱신되는지 확인한다
3. `npm run og` 로 og 이미지를 다시 만든다. 이것만 빌드가 아니라 손으로 돌린다
4. `npm run verify:visual -- --route=brand` 로 `/brand` 화면을 다시 찍는다
5. 16, 24, 32, 48px 로 실제 렌더해서 눈으로 본다. 수치만 보고 정하지 않는다
6. 이 문서의 심볼 절과 README 의 심볼 절을 같은 작업에서 고친다. 형태 설명이 두 곳에 있고
   한쪽만 고치면 공개된 쪽이 낡은 채로 남는다
