# 강의장

오프라인 강의장에서 **운영자가 그 자리에서 만들고 여는 방**이다. 설계 근거와 아직 안 정한
것은 `../eddmpython-course/memory/architecture/courseRoom.md` 에 있다.

## 브랜드 표면

강의장은 별도 제품 팔레트를 만들지 않는다. 색, 테마와 글꼴 정본은 `site/src/design.ts`,
심볼 정본은 `site/src/brand.ts`다. `site/src/styles.css`는 의미 변수만 소비하는 Tailwind
진입점이고, Worker가 HTML을 직접 만드는 강의장은 `designCssVars()`, `DESIGN`, `SYMBOL`을
가져와 같은 값을 쓴다.

로그인, 대기, 과정 목록, 글 화면은 모두 eddmpython 로고 머리띠를 낸다. 브라우저 탭 제목에는
`eddmpython`을 붙이고 파비콘은 `/favicon.svg` 정본을 쓴다. 강의장 전용 hex, 글꼴 스택, 심볼
좌표를 만들지 않는다. `npm run check:design`이 이 경계를 검사한다.

강의장은 머리띠의 해와 달 아이콘 버튼 하나로 라이트와 다크 테마를 바꾼다. 처음 방문했거나 저장한
값이 없으면 라이트 테마로 시작하고, 버튼을 누른 뒤에는 고른 값이 같은 브라우저의 로그인,
대기, 과정 목록, 글 화면에 유지된다. 아이콘은 지금 화면이 아니라 누르면 바뀔 테마를 보여 주며,
접근성 이름도 `라이트 테마로 변경`이나 `다크 테마로 변경`으로 맞춘다. 라이트 테마도
`site/src/design.ts`의 테마 설정에서 파생하며 별도 팔레트를 만들지 않는다. `npm run classroom:shot`은
데스크톱과 모바일에서 라이트와 다크 화면을 각각 찍고 토글과 저장 상태를 확인한다.

강의 모드가 전체 화면을 덮어도 같은 테마 버튼을 왼쪽 화면 축소판 목록 아래에 유지한다. 읽기 화면과 강의 셸의
두 버튼은 현재 테마, 다음 테마 이름, 아이콘을 하나의 상태로 함께 갱신한다. 다른 탭에서 같은 강의장
테마를 바꿔도 현재 탭이 즉시 따라가며, 브라우저 테마 색과 네이티브 폼의 `color-scheme`도 같은 값으로
맞춘다. 코드 블록, 실행 칸, 오류, 영상 받침과 확대 배경은 고정 색을 쓰지 않고 의미 토큰을 소비한다.
`npm run check:design`은 강의장 표면에 고정 hex가 다시 들어오면 실패하고, `npm run classroom:shot`은 강의
셸의 라이트와 다크 전환, 두 버튼 동기화, 다른 탭의 저장 이벤트 배선을 함께 확인한다.

본문 섹션 안의 사례 소제목은 위 설명과 충분히 벌리고 바로 아래 이미지, 캐러셀, 영상에는 붙인다.
소제목에 브랜드 배경과 왼쪽선을 적용해 어떤 시각물의 이름인지 한 묶음으로 보이게 한다.
`npm run classroom:shot`은 소제목과 다음 시각물의 실제 간격과 경계 스타일도 확인한다.

본문 섹션 제목의 크기, 행간, 굵기, 자간은 공개 블로그와 함께
`site/src/design.ts`의 `DESIGN.typography.sectionTitle`을 쓴다. 강의장 CSS에서 별도 수치를 만들지
않으며 `npm run check:design`과 `npm run classroom:shot`이 토큰 소비와 실제 렌더 크기를 확인한다.

## 읽기 모드와 강의 모드

강의장 글은 기본으로 위에서 아래로 읽는 교안이다. 글 제목 오른쪽의 **강의 모드** 버튼을 누르면
현재 읽던 H2부터 전체화면 장면으로 바뀐다. 별도 슬라이드 파일은 없고 같은 마크다운과 KV 묶음의
`scenes` 계약을 사용한다.

- H2 하나가 장면 하나다
- H3는 장면 부제다
- 읽기 모드는 제목, 부제, 시각물, 설명과 보조설명의 원래 본문 순서를 바꾸지 않는다
- 읽기 모드에서 시각물 캡션 보조설명은 16:9 프레임 위에 겹치지 않고 프레임 바로 아래에 둔다.
  캐러셀을 넘기면 아래 보조설명도 현재 시각물에 맞춰 함께 바뀐다
- 읽기 모드의 한 절에 시각물이 둘 이상이면 시각물만 떼어 캐러셀로 만들지 않는다. 각 항목의
  사례 라벨, 16:9 시각물, 캡션 보조설명과 뒤따르는 본문 설명을 한 묶음으로 전환한다. 현재
  시각물과 관계없는 다른 항목의 설명을 화면에 남겨 두지 않는다
- **실행 칸은 강의 시각물이 아니다** (계약 10, 2026-09-03 운영자 지시). 절은 제목, 부제, 시각물,
  설명, 그다음 코드 실습 순서다. 강의 무대에는 시각물만 오르고 실행 칸은 장표에 싣지 않으며 시각물
  수에도 들지 않는다. 읽기 모드의 실행 칸은 codaro 학습 셀처럼 본문 흐름에 놓고 제목 줄과 실행
  버튼, 설명과 할 일, 내용만큼 자라는 코드 칸, 실행한 뒤에만 열리는 출력 상자로 짠다. 크기 조절
  손잡이, 세로 스크롤, 실행 전 상태 글자와 자리 표시 문장은 두지 않는다. 같은 절의 시각물은 실행
  칸 앞뒤에서 각각 캐러셀로 묶이고 실행 칸은 라벨과 설명을 데리고 제자리에 남는다. 규칙의 정본은
  교안 저장소 `scripts/course-scene.mjs` 다
- 사례 라벨 없이 시각물만 이어지고 설명이 그 뒤에 오는 절은 설명이 절 전체의 것이므로 항목별 띠로
  나누지 않고 캐러셀 아래 본문 흐름에 그대로 둔다. 라벨이 있는 묶음만 항목마다 설명을 바꾼다
- **강의 화면은 제목, 부제, 가로줄, 현재 시각물의 캡션 보조설명과 시각물로 짠다.** 일반 본문
  문단은 강의 화면에 옮기지 않는다. 캐러셀을 넘기면 보조설명도 현재 시각물 캡션으로 바뀐다.
  발표자 노트, 발표자 분리 창, 발표 시간은 2026-08-31 운영자 지시로 걷어냈다
- **장면은 첫 beat 를 적용한 완성 화면으로 열린다.** 장면 안에서 다음 beat를 보기 위한 클릭은 만들지 않는다
- **구도는 PPT 하나다.** 제목, 부제, 가로줄, 시각물 캡션과 규격화된 시각자료 무대를 위에서 아래로 둔다.
  넓은 화면도 좌우로 가르지 않고 시각자료가 남은 너비와 높이를 모두 쓴다
- 제목과 부제는 같은 왼쪽 기준선에서 시작하고 시각자료는 남은 무대의 고정 좌표와 크기를 쓴다
- 짧은 코드도 다른 자료와 합치지 않는다. 같은 규격의 단독 무대 안에서 필요한 경우 스크롤한다
- 이미지, SVG, GIF, 영상, 다이어그램, 코드, 실행 칸, 격리된 외부 HTML 렌더러를 시각물로 쓴다
- **표는 강의 시각물이 아니다** (계약 7, 2026-09-02 운영자 지시). 읽기 본문에는 남지만 무대에
  오르지 않고 시각물 수에도 들지 않는다. 표만 있던 절은 실제 화면, 그림, 영상, 실행 칸 가운데
  하나를 갖춰야 발행된다. 규칙의 정본은 교안 저장소 `scripts/course-scene.mjs` 다
- Space, PageDown과 오른쪽 화살표는 다음 장표다. PageUp과 왼쪽 화살표는 이전 장표다
- `F`는 전체화면, `Esc`는 종료다
- URL의 `#lecture=sN.1`이 현재 장표를 복구한다
- Fullscreen API가 실패해도 고정 overlay에서 같은 강의 화면을 유지한다
- 전체화면과 고정 overlay 모두 상단과 하단 막대를 두지 않는다. 왼쪽 화면 축소판 목록과 무대가 viewport를 전부 쓴다
- 왼쪽 목록은 H2 장표마다 실제 강의 장표 전체를 같은 무대 비율과 좌표계로 축소 복제한다. 제목, 부제, 가로줄, 현재 시각물 설명과 16:9 시각물의 위치가 본화면과 같아야 한다
- 현재 시각물의 캡션은 가로줄 아래 보조설명으로 표시한다. 사례 이름과 beat 판단 문장은 강의 화면에
  옮기지 않고 나머지 설명은 강사가 맡는다
- 강의 무대의 제목과 시각물은 같은 유동 너비를 쓰되 시각물은 전체 무대 너비를 끝까지 채우지 않는다. 위아래 여백은 고정 픽셀이 아니라 viewport 높이에 반응하고, 시각물 크기도 함께 줄여 장표 전체가 화면 중앙에 집중되게 한다. 가로줄과 보조설명 사이는 별도 간격으로 분리한다
- 장표와 화면 축소판의 시각물 프레임은 모두 16:9다. 기본 `contain`은 원본 전체를 보이고 `fit: cover`는 중앙을, `fit: cover-top`은 위쪽을 기준으로 잘라 프레임을 채운다
- H2 안의 시각물이 하나면 단일 16:9 프레임으로, 둘 이상이면 같은 자리를 쓰는 16:9 캐러셀로
  보여 준다. 캐러셀은 새 H2 장표가 아니며 읽기와 강의 모드에서 시각물 순서가 같다
- 화면 축소판을 고르면 그 H2 장표로 즉시 이동한다. 좁은 화면에서도 화면 번호와 축소판은 숨기지 않는다
- 상시 노출된 관객 화면에는 내부 단축키 문구를 두지 않는다. 왼쪽 목록 아래에는 진행률, 테마와 전체화면만 둔다
- 장면 카탈로그는 비공개 교안 저장소에서 `npm run scene:catalog`로 읽는다. 이름이 맞아도
  `compare`에 비교 효과가 없거나 `demo`에 실행 대상과 실행 효과가 없으면 교안 검사가 막는다
- 이전, 다음, 화면 가리기와 닫기 버튼은 두지 않는다. 이동은 화면 축소판과 키보드 및 스와이프가 맡는다

글은 전역 `$blog-writing`으로 쓰고, 효과 이름과 허용 형식과 번호는
`scripts/course-scene.mjs`가 검사한다. 이 저장소는
`site/classroom.ts`에서 검사가 끝난 선언 효과만 실행한다. 교안이 임의 JavaScript나 CSS 선택자를
실행 효과로 보내지 못한다.

현재 장면 계약은 효과 이름뿐 아니라 대상 수, 선행 소개와 실행 가능한 시각물을 함께 검사한다.
`enter`, `replace`, `compare`, `compose`는 저작 단계에서 자료의 관계와 순서를 선언한다. 강의 셸은
첫 beat를 장표의 초기 상태로 적용하고 같은 H2의 여러 시각물은 캐러셀 조작으로 바꾼다.
판단 문장은 아무 beat의 `| 문장`으로 기록할 수 있지만 강의 화면에는 나타내지 않는다. `focus`, `run`, `simulate`의
대상은 앞 beat에서 먼저 소개해야 한다. `run`은 영상과 실행 칸, `simulate`는 실행 칸과 격리된
HTML 렌더러에만 쓴다. 강의장은 이전 묶음의 단독 `annotate`도 같은 판단 문장으로 그린다.

화면 배선은 다음 소유권을 지킨다.

```text
course-scene 선언
  -> 비공개 발행기: 역할, 레이아웃, beat 검증과 KV 발행
  -> classroom-render.ts: Markdown 시각물과 장표의 초기 상태 생성
  -> classroom.ts 브라우저 런타임: 현재 H2 장표 하나를 DOM 속성으로 투영
  -> classroom.ts CSS: 위치, 강조, 비교, 주석, 실행 상태를 화면에 표시
```

`site/classroom-render.ts`의 `compileSceneTimeline()`이 장표의 초기 시각물과 상태를 계산한다.
브라우저는 첫 상태만 적용하고 다음 이동에서는 바로 다음 H2 장표를 연다. DOM 쓰기 횟수는 현재
장면의 시각물 수에만 비례한다. 렌더러와 브라우저는 `data-scene-runtime`과
`data-lecture-runtime`이 같을 때만 강의 모드를 연다.

강의 셸은 제품 조작 상태도 함께 책임진다.

- 현재 화면과 효과를 `aria-live`로 알리고 보이지 않는 장면은 `inert`로 키보드 초점에서 뺀다
- 현재 H2 장표의 화면 축소판 하나에만 `aria-current`를 두고 장표가 바뀌면 그 축소판이 보이도록 목록을 스크롤한다
- 전체화면이 해제돼도 왼쪽 목록의 버튼이나 `F`로 다시 시작할 수 있으며 버튼 이름과 눌림 상태가 실제
  Fullscreen API 상태를 따른다
- 모바일은 `100dvh`, 기기 안전영역, 좌우 스와이프를 함께 지원한다. 스와이프 직후 click이 한 번 더
  진행시키지 않으며 실행 칸, 영상, 링크와 입력 위에서는 장면을 넘기지 않는다
- 이미지, 영상과 격리 렌더러를 350ms 안에 받지 못하면 로딩 상태를 보여 준다. 실패하면 깨진 미디어
  아이콘 대신 설명과 다시 불러오기 버튼을 같은 시각물 자리에 남긴다
- 세로가 650px 이하인 넓은 강의 화면(브라우저 125% 확대의 1366x768 프로젝터)에서는 위쪽 정보와
  여백을 줄여 같은 PPT 구도 안에서 시각물 높이를 지킨다. 전체화면 실패는 음성 안내에만 남기지
  않고 강사가 볼 수 있는 화면 알림으로 보여 준다

학습자 화면에는 첫 beat의 작성용 영어 효과 이름 대신 `살펴보기`, `다음 화면`, `핵심`, `비교`,
`판단 기준`, `실행`, `직접 조작` 가운데 해당 안내를 장면 번호 옆에 표시한다. 장표 안에서 효과를
순서대로 재생하는 조작은 두지 않는다.
모든 이동은 opacity와 transform만 쓰고 `prefers-reduced-motion`에서는 애니메이션을 끈다.

외부 HTML 렌더러는 `course-embed`의 https 주소만 받는다. `site/classroom-render.ts`가
`sandbox=\"allow-scripts allow-forms\"` iframe으로 만들며 raw HTML은 계속 글자로 escape한다.
로그인, 결제, 개인정보와 장치 권한을 요구하는 외부 화면은 작성 규칙에서 금지한다.

장면 수, 시각물 수, 계약 번호가 본문과 다르면 읽기 모드는 그대로 제공하고 강의 모드 버튼만
만들지 않는다. 깨진 효과 때문에 교안 전체를 못 읽는 상태를 만들지 않는다.

## 로컬 전체 검수 라우터

`npm run classroom:dev`로 띄운 로컬 Worker의 `/room-test`는 비밀번호와 저장된 강의방 없이
현재 교안 묶음의 모든 카테고리와 글을 연다. 목록에서 글을 고르면 실제 읽기 화면과 같은 구조로
보고 강의 모드를 열어 H2 화면 축소판, 16:9 시각물과 캐러셀을 검사한다.

이 라우터는 `LOCAL_PREVIEW_BYPASS=1`일 때만 열린다. `npm run classroom:dev`만 이 값을 주입하며
배포 설정에는 넣지 않고 공개 강의장 라우팅에도 `/room-test`를 등록하지 않는다. 값이 없으면
404를 돌려 비공개 교안을 내려보내지 않는다.

## 운영장은 배포된 서버에 있다

**주소는 `eddmpython.com/admin` 이다.** 바탕화면 바로가기 `eddmpython 강의 관리`가 그 주소를
연다. 브라우저 하나면 되고 노트북에 아무것도 띄우지 않는다. 다른 기기에서도 들어간다.

운영장이 위고 강의방은 그 아래 하나다. 강의방 주소는 `eddmpython.com/room/<이름>` 이다.

**한때 운영 화면이 운영자 노트북에만 있었다.** 토큰을 브라우저에 안 내리려는 설계였는데,
대가로 운영자가 그 노트북 앞에 앉아 콘솔을 띄워야 강의방을 열 수 있었다. 게다가 그 화면은
로컬과 운영 두 곳을 조종할 수 있었고 목록 순서 때문에 늘 로컬이 잡혀 있었다. 강의 직전에
화면을 연 운영자가 실제 강의장이 아니라 자기 노트북을 조종하는 배선이었다.

주소에 `cr` 이 있던 것도 같이 걷어냈다. 첫 고객사 약자였고, 그 아래에 운영 API 를 두어
운영장이 한 고객사의 부속처럼 배선되어 있었다.

### 공개 주소에 붙은 문을 무엇으로 지키나

| 막는 것 | 어떻게 |
|---|---|
| 비밀번호 추측 | 여덟 번 틀리면 5분 잠근다. 잠금 상태는 Durable Object 가 든다 |
| 비밀번호 유출 뒤의 옛 세션 | 배포 비밀값이 바뀌면 다음 로그인에서 세대를 돌려 옛 쿠키를 전부 끊는다 |
| 남의 페이지가 보낸 요청 | 쿠키가 `SameSite=Lax` 라 다른 출처의 POST 에는 실리지 않는다 |
| 강의방 세션으로 운영장 들어오기 | 쿠키 이름과 경로가 다르고 토큰 안에 쓰임이 적혀 있다 |
| 세션 서명 키 유출 | 운영장이 넘길 수 있는 동작 목록에 `signKey` 가 없다. 그 열쇠가 나가면 모든 방의 쿠키를 위조할 수 있다 |
| 색인 | 모든 화면이 `noindex, nofollow` 다. 어디서도 링크하지 않는다 |

노트북을 잃어버렸으면 운영장 아래쪽 **모든 운영 세션 끊기** 를 누른다. 그 자리에서 전부 끊긴다.

### 운영장에서 하는 일

강의방 만들기, URL과 이름 옮기기, 수강 비밀번호 바꾸기, 수강생 입장 허용, 커리큘럼 포함 체크,
로그인 잠김 풀기, 삭제를 전부 여기서 하고 배포하지 않는다. 공개한 방을 다시 닫지 않고 끝나면
삭제한다.

### 화면은 랜딩과 같은 옷을 입는다

비공개 화면이라고 브랜딩을 빼지 않는다. 머리띠, 색 토큰, 글꼴, 테마 토글이 랜딩과 같다.
디자인 정본은 `site/src/design.ts`의 `DESIGN`이고 공용 크롬은 `site/shell.ts`다.
`npm run check:design`이 hex를 다시 적은 파일과 크롬을 안 입은 운영장을 막고,
`npm run admin:shot` 이 로그인 화면과 조종 화면을 다크와 라이트로 찍어 레이아웃을 보게 한다.

## 강의장에서 벌어지는 일

1. 운영자가 강의 관리 화면에서 URL, 강의방 이름, 수강 비밀번호를 정해 **닫힌 강의방을 만든다**
2. 강의방 카드의 **포함할 커리큘럼** 목록에서 수강생에게 줄 카테고리를 체크한다
3. URL과 비밀번호 및 커리큘럼을 대조한 뒤 **수강생 입장 허용**을 누른다
4. 검수용 방에서 확인했다면 **URL과 이름 저장**으로 제품 이름과 주소로 옮긴다. 비밀번호와
   체크한 커리큘럼은 유지되고 예전 주소는 사라진다
5. 수강생에게 제품 URL과 비밀번호를 알려 준다. `review`, `audit`, `확인용`, `검수용` 이름은
   제품 링크로 전달하지 않는다
6. 수강생이 비밀번호를 치고 들어온다. 입장을 허용한 동안 계속 들어온다. 지각한 사람도 들어온다
7. 진도가 나가면 다음 커리큘럼을 체크한다
8. 끝나면 강의방 카드 우상단의 **삭제**를 누른다. URL이 사라진다

비밀번호는 언제든 운영 화면에서 바꾼다. **바꾸면 이미 들어와 있던 사람도 전부 나간다.**
비밀번호를 바꾸는 이유는 그것이 샜기 때문인데 안에 있는 사람을 그대로 두면 바꾼 의미가 없다.
방을 지웠다 같은 이름으로 다시 만들어도 앞의 쿠키는 죽는다.

주소를 옮길 때는 방을 새로 만들지 않는다. Durable Object 트랜잭션 안에서 비밀번호 해시와 열린
카테고리를 보존한 채 새 주소로 옮기고 예전 주소를 지운다. 예전 주소에서 받은 세션은 끊는다.

## 닫힌 것은 가리지 않고 안 준다

**이 설계의 요점이다.** 미리 다 내려놓고 화면에서만 가리면 수강생이 개발자 도구로 앞 내용을
먼저 본다. 강의장에는 파이썬을 배우러 온 사람들이 앉아 있으므로 그 일이 실제로 생긴다.

`site/classroom.ts` 는 잠긴 카테고리의 본문을 **만들지도 않는다.**

| 상태 | 본문 주소를 직접 쳤을 때 |
|---|---|
| 만들지 않은 방 | 404. 주소 자체가 없다 |
| 로그인 안 함 | 비밀번호 화면 |
| 다른 방의 쿠키 | 비밀번호 화면 |
| 방 닫힘 | 대기 화면. 본문 없음 |
| 방 열림, 카테고리 잠김 | **404** |
| 방 열림, 카테고리 열림 | 200 |

대기 화면은 404 가 아니라 200 이다. 입장을 허용하기 전에는 본문을 주지 않고 대기 화면만 보낸다.
입장을 허용한 뒤에는 다시 닫지 않으며 강의가 끝나면 방을 삭제한다.

## 교안 본문은 Worker 번들에만 있다

**교안은 이 저장소에 없다.** 형제 비공개 저장소 `eddmpython-course` 가 Cloudflare KV 로
발행하고 강의장 Worker 가 요청마다 읽는다. 빌드는 교안을 읽지 않는다.

- 묶음의 모양은 두 저장소 사이의 계약이다. 바꾸면 `schema` 를 올리고 양쪽을 같은 날 고친다
- **묶음이 깨져도 강의장이 죽지 않는다.** 교안이 없는 것으로 보고 운영 화면은 계속 돈다.
  거기서 던지면 강의 중에 운영자가 방 목록조차 못 본다
- **`npm run check:leak` 이 계속 0건이어야 한다.** 어떤 구현으로 바꾸든 이 조건이 먼저다

## 비공개 시각물은 교안 KV 에 있다

강사 사진과 연락처가 든 장표처럼 공개 데이터셋 Hugging Face `eddmpython/eddmpython-media` 에
올리면 안 되는 시각물은 교안 KV 네임스페이스에 `media/<sha256>.<확장자>` 로 둔다 (2026-09-02
운영자 결정). 교안은 `room://<sha256>.<확장자>` 로 가리키고, 강의장 렌더러가
`/room/<방>/media/<sha256>.<확장자>` 로 바꿔 그린다. Worker 는 그 주소를 **방 세션이 있고 방이
열린 요청에만** 준다. 세션 쿠키가 방 경로에 묶여 있어 그 아래 주소에만 실린다. 이름은 내용
해시라 추측할 수 없고, 어디에서도 목록으로 새지 않는다.

- 올리기, 검증, 삭제는 교안 저장소 `eddmpython-course` 에서 한다.
  `node scripts/roomMedia.mjs put <파일> --alt "<설명>" --source "<원본>"` 이 KV 에 올리고
  되읽어 해시를 대조한 뒤 `curriculum/roomMedia.json` 에 적고 `room://` 주소를 찍는다.
  `verify` 는 카탈로그의 객체가 전부 KV 에 그대로 있는지 보고, `delete` 는 KV 와 카탈로그에서
  같이 뺀다
- 교안 검사는 `room://` 주소가 카탈로그에 없으면, 그리고 카탈로그에 있는데 어떤 글도 안 쓰면
  발행을 막는다. 바이트는 저장소에 없으므로 카탈로그가 "무엇을 올렸나" 의 유일한 기록이다
- 응답은 `cache-control: private, max-age=31536000, immutable` 이다. 내용 해시 주소라 영원히
  같지만 공유 캐시에는 남기지 않는다. `x-robots-tag: noindex` 를 단다
- 방 밖에서 렌더하면(검사, 감사) 그림 대신 `비공개 시각물` 자리가 보이고, 주소 모양이 틀리면
  `비공개 시각물 주소 오류` 로 드러난다. 깨진 그림으로 조용히 나가지 않는다
- 왜 R2 가 아닌가: 이미 묶인 네임스페이스와 발행 인증을 그대로 쓰고 새 바인딩이 없다. 값 하나
  25MiB 까지라 장표와 짧은 영상은 충분하다. 긴 영상이 필요해지면 저장만 R2 로 옮기고
  `room://` 주소 계약과 Worker 경로는 그대로 둔다

주소 모양은 `site/classroom-render.ts` 의 `ROOM_MEDIA` 와 교안 저장소
`scripts/roomMediaCatalog.mjs` 의 `ROOM_MEDIA` 가 같이 든다. 한쪽을 고치면 다른 쪽도 같은
날 고친다.

## 상태 보관

`Classroom` Durable Object 하나가 방 목록과 방마다의 열림 상태를 든다. 수강생이 여럿이어도
같은 인스턴스를 보므로 운영자 클릭이 모두에게 같게 반영된다.

수강생 화면은 3초마다 `/room/<방>/state` 를 읽는다. **들어온 사람만 읽는다.** 쿠키가 없으면
401 이다.

지문에는 **교안의 판 번호도 들어간다.** 안 넣으면 교안을 다시 발행해도 이미 화면을 열고 있는
수강생이 모르고 새로 들어오는 사람만 새 내용을 본다. 교안이 Worker 번들에 있던 때는 재배포가
강제 새로고침 노릇을 했는데 KV 로 옮기면서 그 효과가 사라졌다.

지문은 서명 키로 누른 값이라 **무엇이 열렸는지 읽히지 않는다.** 처음에는 열린 카테고리
슬러그를 그대로 이어 붙였는데 그것은 지문이 아니라 커리큘럼 폴더 이름 목록이었다. 비밀번호
없이 진도까지 실시간으로 새어 나갔다. 이 저장소는 커리큘럼 공개를 금지한다.

## 인증과 비밀값

| 무엇 | 어디에 | 언제 정하나 |
|---|---|---|
| 강의장 비밀번호 | Durable Object. Worker 코드가 정한 PBKDF2 해시 | **운영 화면에서 실행 중에** |
| 세션 세대 | 방마다 하나. 비밀번호를 바꾸면 새로 뽑는다 | 자동 |
| 세션 쿠키 서명 키 | Durable Object 가 처음 필요할 때 만든다 | 자동 |
| 운영자 비밀번호 `ADMIN_PASSWORD` | Worker secret | 배포 때 한 번. `npx wrangler secret put ADMIN_PASSWORD` 로 언제든 바꾼다 |
| 운영 세션 세대 | Durable Object. 비밀번호가 바뀌거나 운영자가 끊으면 새로 뽑는다 | 자동 |

**배포 때 넣는 비밀값은 `ADMIN_PASSWORD` 하나다.** 방과 수강 비밀번호는 배포와 무관하다.
검수 스크립트도 사람과 같은 문으로 들어간다. 그 비밀번호를 `site/.dev.vars` 에 같은 이름으로
두면 `admin:shot`, `classroom:shot`, `classroom:audit` 이 쓴다. 그 파일은 추적하지 않는다.

비밀번호 비교는 상수 시간에 가깝게 한다. 여덟 번 틀리면 그 방을 5분 잠근다. 공개 주소에
짧은 비밀번호가 걸려 있으므로 두드리는 것을 막는다.

## 로컬에서 테스트

**바탕화면 바로가기는 없다.** 저장소에서 직접 부른다. 바탕화면에는 배포된 운영장을 여는
`eddmpython 강의 관리` 하나만 둔다.
`site/scripts/classroom-dev.ps1` 이 교안을 다시 굽고, 운영자 비밀번호가 있는지 보고,
`wrangler dev` 를 올린다. 로컬 운영장은 `http://localhost:8787/admin` 이다.

```powershell
site\scripts\classroom-dev.ps1
```

**교안을 고쳤으면 다시 실행해야 반영된다.** 1번 단계가 그 일을 한다.

로컬 운영자 비밀번호는 `site/.dev.vars` 의 `ADMIN_PASSWORD` 다. 그 줄이 없으면 로컬
`/admin` 에 아무도 못 들어간다. `classroom-dev.ps1` 이 없으면 그 사실을 말하고 멈춘다.

wrangler 상태는 `../eddmpython.out/wrangler-state` 에 둔다. **다만 `--persist-to` 는
스토리지만 옮긴다.** 번들과 임시 파일은 여전히 `site/.wrangler` 에 생기고 wrangler 는 그
경로를 바꾸는 방법을 주지 않는다. 그래서 끝나는 자리에서 지운다.

```powershell
npm run classroom:clean
```

`classroom-dev.ps1` 과 `npm run classroom:dev` 는 끝날 때 이것을 알아서 부른다. Ctrl+C 로 끊으면
못 부를 수 있으므로 그때는 직접 부른다.

## 화면 검수

강의장은 sitemap 에 없고 비밀번호 뒤에 있어서 `verify:visual` 이 못 본다. 따로 찍는다.

```powershell
node scripts/classroom-shot.mjs
```

검수용 강의장을 그 자리에서 만들어 로그인하고 `../eddmpython.out/classroom-shots/` 에
현장 화면 여섯 규격으로 찍는다.

**그림만 보고 넘어가지 않는다.** 확대와 실시간 동기화는 인라인 스크립트라서 CSP 가 막으면
화면은 멀쩡한데 기능만 죽는다. 스크린샷으로는 그것을 못 잡는다. 그래서 스크립트가 실제로
돌았는지와 이미지를 눌렀을 때 확대가 열리는지를 같이 확인하고, 하나라도 실패하면 종료 코드가
1 이 된다.

강의 모드는 기능 확인에 더해 제목, 부제, 시각물이 세로로 이어지는 PPT 구도, 제목 글자
크기, 브랜드 심볼, 숨긴 캡션, 고정 무대 크기, 사진의 가로 채움과
H2 장표 수에 맞는 화면 축소판 수 및 현재 위치를 현장 화면 묶음에서 수치로 검사한다. 발표자 표면(노트
버튼, 발표자 버튼)이 남아 있으면 실패한다.
같은 두 장표를 240회 앞뒤로 전환해 화면이 그려질
때까지의 p95가 90ms 이하, 최댓값이 140ms 이하, 누적 레이아웃 이동이 0.01 이하, 장기 작업이
0건이며 DOM 수가 늘지 않는지 각 현장 화면에서 검사한다. `data-scene-phase="ready"`와
`lectureframe` 이벤트가 장표의 측정 경계다.
제품 조작 검사는 전체화면 해제와 복구, 시작과 끝 화면 축소판 상태, `inert`와 음성 안내, 터치 스와이프,
미디어 실패와 복구, 화면 축소판의 정확한 H2 이동, 제거한 조작 버튼의 부재와 URL 위치 복구를
함께 확인한다.

기본 현장 화면 묶음은 다음 여섯 가지다.

| id | CSS viewport | 확인하는 환경 |
|---|---:|---|
| `desktop` | 1920x900 | 운영자 노트북과 일반 외부 화면 |
| `projector` | 1366x768 | 강의실 프로젝터 |
| `projector-125` | 1093x614 | 1366x768에서 브라우저 125% 확대 |
| `tablet-landscape` | 1180x820 | 터치 태블릿 가로 |
| `tablet-portrait` | 820x1180 | 터치 태블릿 세로 |
| `mobile` | 390x844 | 휴대전화 세로 |

기본 `npm run classroom:shot`은 여섯 화면을 전부 검사한다. 결함을 좁혀 다시 볼 때만 PowerShell에서
`$env:CR_VIEWPORTS='projector-125,tablet-portrait'`처럼 id를 쉼표로 지정한다. 일부 화면만 돌린
결과는 배포 완료 증거가 아니며 마지막 로컬 및 운영 검수는 필터 없이 전체 묶음을 통과해야 한다.
스크린샷은 그 수치 검사를 통과한 뒤 직접 눈으로 확인한다.

화면 행렬과 별도로 교안 전체의 도달 여부를 감사한다.

```powershell
npm run classroom:audit
```

감사기는 비공개 교안 저장소의 모든 카테고리와 번호가 붙은 모든 글을 동적으로 읽는다. 검수용
강의장에서 전체 글을 열고, 원본 마크다운에서 계산한 섹션과 캡션 수,
준비 중 표시, 생 주소, 캐러셀, 실행 칸을 실제 화면과 대조한다. 실행 칸은 버튼을 눌러 교안이 약속한
출력 문구까지 확인한다. 일부 카테고리나 표본 글만 통과한 결과는 전체 교안 완료 증거가 아니다.

강의장 페이지는 nonce 를 붙인 자기 CSP 를 직접 낸다. `worker.ts` 의 `withHeaders` 는 응답이
이미 CSP 를 달고 왔으면 덮어쓰지 않는다. **이 두 가지가 짝이다.** 한쪽만 고치면 강의장이
그림만 남고 죽는다.

## 배포

장면 계약을 올릴 때는 읽는 Worker를 먼저 배포하고 교안 묶음을 나중에 발행한다. 이전 계약도
함께 읽어 배포와 발행 사이에 강의 모드가 사라지지 않게 한다. 강의장 런타임만 바꾼 경우에는
course 전용 Worker만 배포하고 교안 KV를 다시 발행하지 않는다.

```powershell
npm run deploy:classroom
```

Durable Object 마이그레이션이 `wrangler.jsonc` 에 있으므로 첫 배포에서 클래스가 만들어진다.
`ADMIN_PASSWORD` 를 넣기 전에는 운영장에 아무도 못 들어가고 방도 못 만든다. 그래서 배포
자체는 강의방을 열지 않는다.

```powershell
npx wrangler secret put ADMIN_PASSWORD
```

## 롤백

`site/wrangler.jsonc` 의 `durable_objects` 와 `migrations` 를 지우고 `worker.ts` 의
`/admin` 과 `/room` 분기와 `Classroom` export 를 빼면 강의장이 사라진다. 교안 본문은 형제 비공개 저장소
`../eddmpython-course` 에 그대로 있으므로 잃는 것이 없다.
