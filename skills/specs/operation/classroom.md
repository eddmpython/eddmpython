# 강의장

오프라인 강의장에서 **운영자가 그 자리에서 만들고 여는 방**이다. 설계 근거와 아직 안 정한
것은 `../eddmpython-course/memory/architecture/courseRoom.md` 에 있다.

## 브랜드 표면

강의장은 별도 제품 팔레트를 만들지 않는다. 색, 글꼴, 심볼 정본은 `site/src/brand.ts`다.
`site/src/styles.css`는 랜딩에서 그 정본을 소비하는 Tailwind 진입점이고, Worker가 HTML을 직접
만드는 강의장은 `cssVars()`, `TOKENS`, `SYMBOL`을 가져와 같은 값을 쓴다.

로그인, 대기, 과정 목록, 글 화면은 모두 eddmpython 로고 머리띠를 낸다. 브라우저 탭 제목에는
`eddmpython`을 붙이고 파비콘은 `/favicon.svg` 정본을 쓴다. 강의장 전용 hex, 글꼴 스택, 심볼
좌표를 만들지 않는다. `npm run check:brand`가 이 경계를 검사한다.

강의장은 머리띠의 해와 달 아이콘 버튼 하나로 라이트와 다크 테마를 바꾼다. 처음 방문했거나 저장한
값이 없으면 운영체제의 색상 설정을 따르고, 버튼을 누른 뒤에는 고른 값이 같은 브라우저의 로그인,
대기, 과정 목록, 글 화면에 유지된다. 아이콘은 지금 화면이 아니라 누르면 바뀔 테마를 보여 주며,
접근성 이름도 `라이트 테마로 변경`이나 `다크 테마로 변경`으로 맞춘다. 라이트 테마도
`site/src/brand.ts`의 브랜드 색에서 파생하며 별도 팔레트를 만들지 않는다. `npm run cr:shot`은
데스크톱과 모바일에서 라이트와 다크 화면을 각각 찍고 토글과 저장 상태를 확인한다.

강의 모드가 전체 화면을 덮어도 같은 테마 버튼을 상단 강의 셸에 유지한다. 읽기 화면과 강의 셸의
두 버튼은 현재 테마, 다음 테마 이름, 아이콘을 하나의 상태로 함께 갱신한다. 다른 탭에서 같은 강의장
테마를 바꿔도 현재 탭이 즉시 따라가며, 브라우저 테마 색과 네이티브 폼의 `color-scheme`도 같은 값으로
맞춘다. 코드 블록, 실행 칸, 오류, 영상 받침과 확대 배경은 고정 색을 쓰지 않고 의미 토큰을 소비한다.
`npm run check:brand`는 강의장 표면에 고정 hex가 다시 들어오면 실패하고, `npm run cr:shot`은 강의
셸의 라이트와 다크 전환, 두 버튼 동기화, 다른 탭의 저장 이벤트 배선을 함께 확인한다.

본문 섹션 안의 사례 소제목은 위 설명과 충분히 벌리고 바로 아래 이미지, 캐러셀, 영상에는 붙인다.
소제목에 브랜드 배경과 왼쪽선을 적용해 어떤 시각물의 이름인지 한 묶음으로 보이게 한다.
`npm run cr:shot`은 소제목과 다음 시각물의 실제 간격과 경계 스타일도 확인한다.

본문 섹션 제목의 크기, 행간, 굵기, 자간은 공개 블로그와 함께
`site/src/brand.ts`의 `TOKENS.typography.sectionTitle`을 쓴다. 강의장 CSS에서 별도 수치를 만들지
않으며 `npm run check:brand`와 `npm run cr:shot`이 토큰 소비와 실제 렌더 크기를 확인한다.

## 읽기 모드와 강의 모드

강의장 글은 기본으로 위에서 아래로 읽는 교안이다. 글 제목 오른쪽의 **강의 모드** 버튼을 누르면
현재 읽던 H2부터 전체화면 장면으로 바뀐다. 별도 슬라이드 파일은 없고 같은 마크다운과 KV 묶음의
`scenes` 계약을 사용한다.

- H2 하나가 장면 하나다
- H3는 장면 부제다
- 시각물 바로 뒤의 본문 설명은 읽기 모드에 남고 현재 비트의 발표자 노트가 된다
- 이미지, SVG, GIF, 영상, 다이어그램, 코드, 표, 실행 칸, 격리된 외부 HTML 렌더러를 시각물로 쓴다
- 클릭, Space, 오른쪽 화살표는 다음 beat다. 왼쪽 화살표는 이전 beat다
- `N`은 발표자 노트, `M`은 장면 지도, `B`는 관객 화면 가리기, `Esc`는 종료다
- URL의 `#lecture=sN.B`가 현재 장면과 보인 beat 수를 복구한다
- Fullscreen API가 실패해도 고정 overlay에서 같은 강의 화면을 유지한다
- 전체화면과 고정 overlay 모두 상단 막대, 무대, 하단 조작부를 viewport 안에 배치한다
- 상단 막대는 브랜드 심볼과 과정 이름, 장면 진행 수치와 진행선을 한 줄의 강의 셸로 보여 준다
- 시각물이 아직 나오지 않은 장면은 빈 본문 칸을 남기지 않고 장면 번호, 제목, 부제를 무대 중앙에 크게 배치한다
- 시각물이 나온 장면은 제목 위계와 시각물 프레임을 분리하고 이미지 캡션은 시각물 바로 아래에 붙인다
- 시각물 하나만 보이는 beat는 시각물의 원본 폭과 관계없이 현재 레이아웃의 시각물 영역 안에서
  중앙에 배치한다
- `stage`, `code`, 비교 전 `compare`, 마지막 `close`는 데스크톱에서 제목과 시각물을 좌우로
  나눈다. `sequence`와 `demo`는 제목 아래에 넓은 시각물을 둔다
- `compare` 장면은 `compare` 효과가 대상 두 개를 실제로 보여 줄 때만 데스크톱에서 두 칸이 된다
- `compare`의 두 시각물은 같은 높이의 프레임으로 맞추고 긴 코드는 가로 스크롤 대신 프레임 안에서 줄바꿈한다
- 발표자 노트는 데스크톱에서 오른쪽 열로 열어 무대를 덮지 않는다. 모바일에서는 아래 패널로 열고,
  현재 장면과 클릭 위치, 지금 설명할 문단, 다음 클릭의 대상과 동작을 보여 준다. 현재 장면의 마지막
  beat에서는 다음 장면의 번호와 제목을 보여 줘 강사가 설명을 자연스럽게 연결하게 한다
- 관객 화면에 노트를 띄우지 않아야 할 때는 `발표자` 버튼이나 `P`로 분리 창을 연다. 분리 창은
  같은 로그인 세션과 글 주소를 사용하고 현재 장면, 클릭, 실행 효과를 관객 화면과 양방향으로
  동기화한다. 관객 화면의 무대 폭과 좌표는 발표자 창을 열어도 바뀌지 않는다. 발표자 창이 준비
  신호를 보내면 관객 화면이 현재 프레임을 다시 보내므로 늦게 열린 창과 새로고침한 창도 현재
  위치로 복구한다. 발표자 창을 닫으면 관객 화면의 버튼 상태도 다시 열기 상태로 돌아간다
- 장면 지도는 모든 장면 번호와 제목, 현재 장면을 한 화면에 보여 준다. 제목을 고르면 해당 장면의
  첫 프레임으로 즉시 이동하고 관객 창과 발표자 창이 같은 위치를 유지한다. 지도가 열린 동안 뒤의
  강의 셸과 무대는 `inert`로 초점을 받지 않으며 `Esc`는 강의를 닫지 않고 지도부터 닫는다
- 상시 노출된 관객 화면에는 내부 단축키 문구를 두지 않는다. 조작 도움말과 관객 화면 가리기는
  강사가 의도적으로 연 장면 지도에 둬 학습자가 보아야 할 제목과 시각물만 무대에 남긴다
- 발표 시간은 강의 시작부터 계산하고 발표자 노트에서 일시정지, 계속, 초기화할 수 있다. 관객 창과
  발표자 창은 같은 시간 상태를 공유하며 늦게 열린 창과 새로고침한 창도 현재 시간으로 복구한다
- 관객의 시선을 강사에게 돌릴 때 `B`로 관객 화면만 검게 가린다. 발표자 창과 노트는 계속 보이고,
  같은 키나 가려진 화면 클릭으로 즉시 복구한다. 가림 상태도 두 창 사이에서 동기화한다
- 장면 카탈로그는 비공개 교안 저장소에서 `npm run scene:catalog`로 읽는다. 이름이 맞아도
  `compare`에 비교 효과가 없거나 `demo`에 실행 대상과 실행 효과가 없으면 교안 검사가 막는다
- 이전, 다음, 노트, 닫기 조작은 아이콘과 글자를 함께 보여 주고 모바일에서는 아이콘만 남긴다

효과 이름과 작성 판단은 비공개 저장소 `memory/rules/blogWriter.md`가 사람용 정본이고,
허용 형식과 번호 검사는 `scripts/course-scene.mjs`가 기계 정본이다. 이 저장소는
`site/classroom.ts`에서 검사가 끝난 `enter`, `replace`, `focus`, `compare`, `annotate`,
`run`, `simulate`만 실행한다. 교안이 임의 JavaScript나 CSS 선택자를 실행 효과로 보내지 못한다.

장면 계약 2부터 효과는 이름뿐 아니라 대상 수, 선행 가시성, 실행 가능한 시각물과 클릭 뒤 화면
결과를 함께 검사한다. `enter`, `replace`, `focus`, `annotate`, `run`, `simulate`는 대상 하나를
받고 `compare`는 대상 두 개를 받는다. `focus`, `annotate`, `run`, `simulate`의 대상은 앞 beat에서
이미 보여야 한다. `run`은 영상과 실행 칸, `simulate`는 실행 칸과 격리된 HTML 렌더러에만 쓴다.

화면 배선은 다음 소유권을 지킨다.

```text
course-scene 선언
  -> 비공개 발행기: 역할, 레이아웃, beat 검증과 KV 발행
  -> classroom-render.ts: Markdown 시각물과 클릭별 완성 프레임 생성
  -> classroom.ts 브라우저 런타임: 현재 프레임 하나를 DOM 속성으로 투영
  -> classroom.ts CSS: 위치, 강조, 비교, 주석, 실행 상태를 화면에 표시
```

`site/classroom-render.ts`의 `compileSceneTimeline()`이 보이는 시각물, 초점 대상, 비교 슬롯, 주석,
조작 대상과 학습자용 안내를 beat마다 미리 계산한다. 브라우저는 클릭할 때 첫 beat부터 다시 재생하지
않는다. 현재 프레임 하나만 적용하므로 이전 주석이 다음 화면에 남지 않고 beat 수가 늘어도 DOM 쓰기
횟수는 현재 장면의 시각물 수에만 비례한다. 렌더러와 브라우저는 `data-scene-runtime`과
`data-lecture-runtime`이 같을 때만 강의 모드를 연다.

강의 셸은 제품 조작 상태도 함께 책임진다.

- 처음에는 이전 버튼, 마지막에는 다음 버튼을 비활성화하고 접근성 상태도 같은 값으로 맞춘다
- 현재 장면, 클릭, 효과를 `aria-live`로 알리고 보이지 않는 장면은 `inert`로 키보드 초점에서 뺀다
- 장면 지도와 관객 가림 화면이 열리면 뒤의 강의 표면도 `inert`로 빼고, 지도 닫기와 현재 장면
  항목의 접근성 상태를 실제 화면 상태와 맞춘다
- 전체화면이 해제돼도 상단 버튼이나 `F`로 다시 시작할 수 있으며 버튼 이름과 눌림 상태가 실제
  Fullscreen API 상태를 따른다
- 모바일은 `100dvh`, 기기 안전영역, 좌우 스와이프를 함께 지원한다. 스와이프 직후 click이 한 번 더
  진행시키지 않으며 실행 칸, 영상, 링크와 입력 위에서는 장면을 넘기지 않는다
- 이미지, 영상과 격리 렌더러를 350ms 안에 받지 못하면 로딩 상태를 보여 준다. 실패하면 깨진 미디어
  아이콘 대신 설명과 다시 불러오기 버튼을 같은 시각물 자리에 남긴다
- 발표자 분리 창은 `presenter=1`인 같은 글 화면이며 `BroadcastChannel`로 장면과 클릭을 동기화한다.
  새 API나 별도 교안 복사본을 만들지 않고 방 인증과 잠금 경계를 그대로 따른다. 팝업 차단,
  전체화면 실패와 동기화 메시지 오류는 음성 안내에만 남기지 않고 강사가 볼 수 있는 화면 알림으로
  보여 준다
- 세로형 태블릿과 모바일의 발표자 창은 관객 미리보기와 노트를 겹치지 않는 두 행으로 나눈다.
  시각물 최대 높이는 전체 viewport가 아니라 위쪽 미리보기 영역에 맞춰 제목, 라벨과 영상이 겹치지
  않게 한다
- 세로가 650px 이하인 넓은 강의 화면에서는 `sequence`와 `demo`를 단순 축소하지 않는다. 제목은
  왼쪽, 시각물은 오른쪽으로 재배치해 브라우저 125% 확대를 쓴 1366x768 프로젝터에서도 영상과
  실행 화면을 읽을 수 있는 크기로 유지한다

학습자 화면에는 작성용 영어 효과 이름 대신 `살펴보기`, `다음 화면`, `핵심`, `비교`, `판단 기준`,
`실행`, `직접 조작`을 장면 번호 아래에 표시한다. `focus`는 대상과 무대의 밝기를 실제로 갈라서
보여 주고, `compare`는 두 대상을 같은 높이의 프레임으로 놓는다. `annotate`는 예약된 주석 영역에
판단 문장만 나타내며, `run`과 `simulate`는 실제 재생이나 실행과 조작 초점을 함께 표시한다.
효과 안내 폭과 주석 영역 높이는 처음부터 예약해 글자가 바뀌어도 제목과 시각물이 밀리지 않게 한다.
모든 이동은 opacity와 transform만 쓰고 `prefers-reduced-motion`에서는 애니메이션을 끈다.

외부 HTML 렌더러는 `course-embed`의 https 주소만 받는다. `site/classroom-render.ts`가
`sandbox=\"allow-scripts allow-forms\"` iframe으로 만들며 raw HTML은 계속 글자로 escape한다.
로그인, 결제, 개인정보와 장치 권한을 요구하는 외부 화면은 작성 규칙에서 금지한다.

장면 수, 시각물 수, 계약 번호가 본문과 다르면 읽기 모드는 그대로 제공하고 강의 모드 버튼만
만들지 않는다. 깨진 효과 때문에 교안 전체를 못 읽는 상태를 만들지 않는다.

## 운영 화면은 로컬호스트에만 있다

**공개 서버에 운영자 페이지가 없다.** 운영 화면은 운영자 노트북에서 도는 작은 서버가 그리고,
그 서버가 토큰을 얹어 대상 Worker 의 `/cr/api/admin` 하나만 두드린다. 토큰은 브라우저로
내려가지 않고, 서버는 루프백에만 묶여 강의장 와이파이에 노출되지 않는다.

**루프백에 묶는 것만으로는 부족하다.** 운영자가 이 화면을 띄워 둔 채 아무 웹페이지나 열면
그 페이지가 폼 하나로 `127.0.0.1` 에 POST 를 보낼 수 있고, 토큰은 우리가 얹어 준다.
그래서 `/api` 는 네 가지를 다 보고 받는다.

| 막는 것 | 어떻게 |
|---|---|
| 남의 페이지가 보낸 폼 | 이 프로세스가 뽑은 한 회용 열쇠를 헤더로 요구한다 |
| preflight 없는 폼 | `content-type` 이 JSON 이어야 한다. 폼은 JSON 을 못 낸다 |
| 다른 출처 | `Origin` 이 있으면 우리 것이어야 한다 |
| 남의 도메인을 루프백으로 돌리는 것 | `Host` 가 `127.0.0.1` 이나 `localhost` 여야 한다 |

```powershell
site\scripts\classroom-admin.ps1     # 바탕화면 "eddmpython 강의장 운영"
```

화면 위쪽에서 **로컬**과 **운영** 중 어디를 조종하는지 고른다. 운영은 빨간색이라 눈에 띈다.

## 강의장에서 벌어지는 일

1. 운영자가 운영 화면에서 **강의장을 만든다.** 주소 이름, 이름, 비밀번호를 그 자리에서 정한다
2. **만드는 즉시 `/cr/<주소 이름>` 이 살아난다.** 배포하지 않고 secret 도 건드리지 않는다
3. 검수용 방에서 확인했다면 **주소와 이름 적용**으로 제품 이름과 주소로 옮긴다. 비밀번호는
   유지되고 예전 주소는 사라진다
4. 수강생에게 제품 주소와 비밀번호를 알려 준다. `review`, `audit`, `확인용`, `검수용` 이름은
   제품 링크로 전달하지 않는다
5. 수강생이 비밀번호를 치고 들어온다. 열어 둔 동안 계속 들어온다. 지각한 사람도 들어온다
6. **운영자가 클릭한 카테고리만 수강생 화면에 열린다**
7. 진도가 나가면 다음 카테고리를 클릭해 연다
8. 끝나면 방을 닫는다. **닫으면 잠금도 처음으로 되돌아간다**
9. 다시 쓸 일이 없으면 삭제한다. 주소가 사라진다

비밀번호는 언제든 운영 화면에서 바꾼다. **바꾸면 이미 들어와 있던 사람도 전부 나간다.**
비밀번호를 바꾸는 이유는 그것이 샜기 때문인데 안에 있는 사람을 그대로 두면 바꾼 의미가 없다.
방을 지웠다 같은 이름으로 다시 만들어도 앞의 쿠키는 죽는다.

주소를 옮길 때는 방을 새로 만들지 않는다. Durable Object 트랜잭션 안에서 비밀번호 해시와 열린
카테고리를 보존한 채 새 주소로 옮기고 예전 주소를 지운다. 예전 주소에서 받은 세션은 끊는다.

## 닫힌 것은 가리지 않고 안 준다

**이 설계의 요점이다.** 미리 다 내려놓고 화면에서만 가리면 수강생이 개발자 도구로 앞 내용을
먼저 본다. 강의장에는 파이썬을 배우러 온 사람들이 앉아 있으므로 그 일이 실제로 생긴다.

`site/classroom.ts` 는 잠긴 카테고리의 본문을 **만들지도 않는다.**

| 상태 | 본문 주소를 직접 쳤을 때 |
|---|---|
| 만들지 않은 방 | 404. 주소 자체가 없다 |
| 로그인 안 함 | 비밀번호 화면 |
| 다른 방의 쿠키 | 비밀번호 화면 |
| 방 닫힘 | 대기 화면. 본문 없음 |
| 방 열림, 카테고리 잠김 | **404** |
| 방 열림, 카테고리 열림 | 200 |

대기 화면은 404 가 아니라 200 이다. 강의 중에 방을 닫으면 이미 글을 보고 있던 사람의 화면이
죽은 404 가 아니라 대기 화면으로 돌아가고, 다시 열면 알아서 따라온다.

## 교안 본문은 Worker 번들에만 있다

**교안은 이 저장소에 없다.** 형제 비공개 저장소 `eddmpython-course` 가 Cloudflare KV 로
발행하고 강의장 Worker 가 요청마다 읽는다. 빌드는 교안을 읽지 않는다.

- 묶음의 모양은 두 저장소 사이의 계약이다. 바꾸면 `schema` 를 올리고 양쪽을 같은 날 고친다
- **묶음이 깨져도 강의장이 죽지 않는다.** 교안이 없는 것으로 보고 운영 화면은 계속 돈다.
  거기서 던지면 강의 중에 운영자가 방 목록조차 못 본다
- **`npm run check:leak` 이 계속 0건이어야 한다.** 어떤 구현으로 바꾸든 이 조건이 먼저다

## 상태 보관

`Classroom` Durable Object 하나가 방 목록과 방마다의 열림 상태를 든다. 수강생이 여럿이어도
같은 인스턴스를 보므로 운영자 클릭이 모두에게 같게 반영된다.

수강생 화면은 3초마다 `/cr/<방>/state` 를 읽는다. **들어온 사람만 읽는다.** 쿠키가 없으면
401 이다.

지문에는 **교안의 판 번호도 들어간다.** 안 넣으면 교안을 다시 발행해도 이미 화면을 열고 있는
수강생이 모르고 새로 들어오는 사람만 새 내용을 본다. 교안이 Worker 번들에 있던 때는 재배포가
강제 새로고침 노릇을 했는데 KV 로 옮기면서 그 효과가 사라졌다.

지문은 서명 키로 누른 값이라 **무엇이 열렸는지 읽히지 않는다.** 처음에는 열린 카테고리
슬러그를 그대로 이어 붙였는데 그것은 지문이 아니라 커리큘럼 폴더 이름 목록이었다. 비밀번호
없이 진도까지 실시간으로 새어 나갔다. 이 저장소는 커리큘럼 공개를 금지한다.

## 인증과 비밀값

| 무엇 | 어디에 | 언제 정하나 |
|---|---|---|
| 강의장 비밀번호 | Durable Object. Worker 코드가 정한 PBKDF2 해시 | **운영 화면에서 실행 중에** |
| 세션 세대 | 방마다 하나. 비밀번호를 바꾸면 새로 뽑는다 | 자동 |
| 세션 쿠키 서명 키 | Durable Object 가 처음 필요할 때 만든다 | 자동 |
| 운영 토큰 `CR_ADMIN_TOKEN` | Worker secret | 배포 때 한 번 |

**배포 때 넣는 비밀값은 `CR_ADMIN_TOKEN` 하나다.** 방과 비밀번호는 배포와 무관하다.

비밀번호 비교는 상수 시간에 가깝게 한다. 여덟 번 틀리면 그 방을 5분 잠근다. 공개 주소에
짧은 비밀번호가 걸려 있으므로 두드리는 것을 막는다.

## 로컬에서 테스트

바탕화면 바로가기 `eddmpython 강의장 테스트` 가 `site/scripts/classroom-dev.ps1` 을 부른다.
교안을 다시 굽고, 운영 토큰을 맞추고, 운영 화면을 따로 띄우고, `wrangler dev` 를 올린다.

```powershell
site\scripts\classroom-dev.ps1
```

**교안을 고쳤으면 다시 실행해야 반영된다.** 1번 단계가 그 일을 한다.

대상과 토큰은 `site/.classroom-admin.json` 이다. 추적하지 않고 처음 실행할 때 만들어진다.
로컬 토큰은 거기서 뽑아 `site/.dev.vars` 와 자동으로 맞춘다. **운영 토큰은 비어 있다.**

wrangler 상태는 `../eddmpython.out/wrangler-state` 에 둔다. **다만 `--persist-to` 는
스토리지만 옮긴다.** 번들과 임시 파일은 여전히 `site/.wrangler` 에 생기고 wrangler 는 그
경로를 바꾸는 방법을 주지 않는다. 그래서 끝나는 자리에서 지운다.

```powershell
npm run cr:clean
```

`classroom-dev.ps1` 과 `npm run cr:dev` 는 끝날 때 이것을 알아서 부른다. Ctrl+C 로 끊으면
못 부를 수 있으므로 그때는 직접 부른다.

## 화면 검수

강의장은 sitemap 에 없고 비밀번호 뒤에 있어서 `verify:visual` 이 못 본다. 따로 찍는다.

```powershell
node scripts/classroom-shot.mjs
```

검수용 강의장을 그 자리에서 만들어 로그인하고 `../eddmpython.out/classroom-shots/` 에
현장 화면 여섯 규격으로 찍는다.

**그림만 보고 넘어가지 않는다.** 확대와 실시간 동기화는 인라인 스크립트라서 CSP 가 막으면
화면은 멀쩡한데 기능만 죽는다. 스크린샷으로는 그것을 못 잡는다. 그래서 스크립트가 실제로
돌았는지와 이미지를 눌렀을 때 확대가 열리는지를 같이 확인하고, 하나라도 실패하면 종료 코드가
1 이 된다.

강의 모드는 기능 확인에 더해 제목 장면의 중앙 정렬과 글자 크기, 브랜드 심볼, 시각물 테두리와
캡션, 진행률 접근성 값, 레이아웃별 제목과 시각물 위치, 비교 프레임의 높이와 줄바꿈, 비트별
발표자 노트와 다음 클릭 안내, 마지막 beat의 다음 장면 제목, 장면 지도 항목 수와 현재 위치를 현장
화면 묶음에서 수치로 검사한다.
효과 검사에서는 `enter`, `run`, `annotate`, `compare`, `focus`, `simulate`의 실제 DOM 상태와
학습자용 안내를 확인한다. 같은 시각물을 유지하는 비트를 240회 앞뒤로 전환해 두 프레임이 그려질
때까지의 p95가 90ms 이하, 최댓값이 140ms 이하, 누적 레이아웃 이동이 0.01 이하, 장기 작업이
0건이며 DOM 수가 늘지 않는지 각 현장 화면에서 검사한다. `data-scene-phase="ready"`와
`lectureframe` 이벤트가
완성 프레임의 측정 경계다.
제품 조작 검사는 전체화면 해제와 복구, 시작과 끝 버튼 상태, `inert`와 음성 안내, 터치 스와이프,
미디어 실패와 복구, 장면 지도의 키보드와 즉시 이동, 관객 화면 가리기와 복구, 발표 시간의 일시정지와
초기화, 팝업 차단 안내, 실제로 열린 발표자 창과 관객 창의 양방향 프레임, 지도, 가림, 시간 동기화,
발표자 창 새로고침과 종료 복구를 함께 확인한다. 같은 페이지에 발표자 주소만 다시 여는 검사는 실제
두 창 검사를 대신하지 않는다.

기본 현장 화면 묶음은 다음 여섯 가지다.

| id | CSS viewport | 확인하는 환경 |
|---|---:|---|
| `desktop` | 1920x900 | 운영자 노트북과 일반 외부 화면 |
| `projector` | 1366x768 | 강의실 프로젝터 |
| `projector-125` | 1093x614 | 1366x768에서 브라우저 125% 확대 |
| `tablet-landscape` | 1180x820 | 터치 태블릿 가로 |
| `tablet-portrait` | 820x1180 | 터치 태블릿 세로 |
| `mobile` | 390x844 | 휴대전화 세로 |

기본 `npm run cr:shot`은 여섯 화면을 전부 검사한다. 결함을 좁혀 다시 볼 때만 PowerShell에서
`$env:CR_VIEWPORTS='projector-125,tablet-portrait'`처럼 id를 쉼표로 지정한다. 일부 화면만 돌린
결과는 배포 완료 증거가 아니며 마지막 로컬 및 운영 검수는 필터 없이 전체 묶음을 통과해야 한다.
스크린샷은 그 수치 검사를 통과한 뒤 직접 눈으로 확인한다.

화면 행렬과 별도로 교안 전체의 도달 여부를 감사한다.

```powershell
npm run cr:audit
```

감사기는 비공개 교안 저장소의 모든 카테고리와 번호가 붙은 모든 글을 동적으로 읽는다. 현재 기준
2개 카테고리와 9개 글을 검수용 강의장에서 모두 열고, 원본 마크다운에서 계산한 섹션과 캡션 수,
준비 중 표시, 생 주소, 캐러셀, 실행 칸을 실제 화면과 대조한다. 실행 칸은 버튼을 눌러 교안이 약속한
출력 문구까지 확인한다. 일부 카테고리나 표본 글만 통과한 결과는 전체 교안 완료 증거가 아니다.

강의장 페이지는 nonce 를 붙인 자기 CSP 를 직접 낸다. `worker.ts` 의 `withHeaders` 는 응답이
이미 CSP 를 달고 왔으면 덮어쓰지 않는다. **이 두 가지가 짝이다.** 한쪽만 고치면 강의장이
그림만 남고 죽는다.

## 배포

장면 계약을 올릴 때는 읽는 Worker를 먼저 배포하고 교안 묶음을 나중에 발행한다. 현재 Worker는
이전 장면 계약 1과 현재 계약 2를 함께 읽어 배포와 발행 사이에도 강의 모드가 사라지지 않는다.
새 교안 발행기는 계약 2만 만든다.

```powershell
npm run deploy
node scripts/classroom-admin.mjs --link-production
```

두 번째 줄이 운영 토큰을 새로 뽑아 **Worker secret 과 `.classroom-admin.json` 에 같이
넣는다.** 손으로 옮겨 적지 않는다. 어긋나면 그것을 강의장에 가서 401 로 만난다.

Durable Object 마이그레이션이 `wrangler.jsonc` 에 있으므로 첫 배포에서 클래스가 만들어진다.
토큰을 넣기 전에는 운영 화면이 401 을 받고 아무도 방을 못 만든다. 그래서 배포 자체는
강의장을 열지 않는다.

## 롤백

`site/wrangler.jsonc` 의 `durable_objects` 와 `migrations` 를 지우고 `worker.ts` 의
`/cr` 분기와 `Classroom` export 를 빼면 강의장이 사라진다. 교안 본문은 형제 비공개 저장소
`../eddmpython-course` 에 그대로 있으므로 잃는 것이 없다.
