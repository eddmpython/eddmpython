# Agent Template

AI 코딩 에이전트에게 저장소를 맡길 때 쓰는 초기 규칙 템플릿입니다.
파일 하나를 프로젝트 루트에 두면 에이전트가 판단 기준, 작업 규율, 검증 방법, 정보 구조를
같은 방식으로 이해합니다.

eddmpython 이 DartLab, Codaro, xlpod, pyproc 을 만들면서 실제로 사고가 났던 지점만 남긴
규칙입니다. 일반론이 아니라 실패 기록에서 역산한 것입니다.

## 무엇이 들어 있나

| 파일 | 역할 |
|---|---|
| `CLAUDE.md` | 규칙 정본. 판단 기준, 검증, 산출물, 버전 관리, 비밀정보, 정보 구조, 메모리, 테스트, 협업, 출력 |
| `AGENTS.md` | 얇은 진입점. 규칙 본문을 복제하지 않고 `CLAUDE.md` 로 보냄 |

## 쓰는 법

1. 두 파일을 프로젝트 루트에 복사합니다.
2. `{{ }}` 자리표시자를 채웁니다.

   | 자리표시자 | 예시 |
   |---|---|
   | `{{PROJECT}}` | `dartlab` |
   | `{{MAIN_BRANCH}}` | `main` |
   | `{{INSTALL_CMD}}` | `npm install` |
   | `{{DEV_CMD}}` | `npm run dev` |
   | `{{TEST_CMD}}` | `npm test` |
   | `{{BUILD_CMD}}` | `npm run build` |
   | `{{DEPLOY_CMD}}` | `npm run deploy` |
   | `{{BUILD_OUT_DIR}}` | `../project.out/dist` |
   | `{{COMMIT_LANG}}` | `한국어` |
   | `{{CHAT_LANG}}` | `한국어` |
   | `{{SECRET_STORES}}` | `.env`, GitHub Secrets |
   | `{{DOCS_DIR}}` | `docs/` |
   | `{{TRACKER}}` | `plan/` 또는 이슈 트래커 |

3. 11 번 "이 프로젝트 고유 규칙" 을 채웁니다. 여기가 실제로 프로젝트를 구분하는 부분입니다.
4. 쓰지 않는 섹션은 지웁니다. **비어 있는 규칙을 남겨 두지 않습니다.**

## 설계 원칙

- **위반 즉시 사고가 나는 것만 담는다.** 튜토리얼, 배경 설명, 코딩 스타일 취향은 넣지 않습니다.
  규칙이 길어지면 에이전트는 앞부분만 지킵니다.
- **같은 사실을 두 곳에 쓰지 않는다.** 강행규칙 / 지어진 계약 / 앞으로 지을 것을 3층으로 나눕니다.
- **규칙은 실패에서 역산한다.** 사고가 난 적 없는 항목을 예방 차원에서 추가하지 않습니다.
  안 지켜지고 노이즈만 됩니다.
